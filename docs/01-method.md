# Метод

Эксперимент отвечает на один вопрос:

> **Повышает ли подключение Spine к уже выбранному SDD-стеку долю изменений, внесённых
> принятым способом — без просадки содержательного качества архитектурного пакета?**

## 1. Факторная сетка

| Фактор | Уровни |
|---|---|
| Стек (что уже стоит в репозитории) | `plain` (голый агент), `openspec`, `bmad`, `superpowers` |
| Режим Spine | «нет» · `+spine` (MCP-сервер + 66 скиллов) · `+spine-hook` (плюс блокирующий Stop-хук) |

12 ячеек. Имена условий — `<стек>+<режим>`, алиасы `spine` = `plain+spine`,
`spine-hook` = `plain+spine-hook` (совместимость с первой волной).

**Режимы Spine.**

- `spine` — `arch-be connect qwen`: в репозиторий кладутся 66 скиллов и регистрируется
  MCP-сервер; в цикле агента гейт не стоит, он остаётся советующим.
- `spine-hook` — к тому же добавляется Stop-хук в `.qwen/settings.json`, который запускает
  `arch-be gate` по тегу `bench-baseline` и возвращает `exit 2` при находках. Модель получает
  дополнительный ход и обязана находки исправить.

**Почему хук исправлен относительно референса.** Референсный хук из вывода `connect` берёт
базу как `git merge-base main HEAD`. Агент не коммитит работу, поэтому база совпадает с HEAD,
значимость равна нулю и гейт ничего не видит (находка F2). В эксперименте хук берёт базу от
тега `bench-baseline`, поставленного на baseline-коммит, и выполняет `git add -A -N`, чтобы
новые файлы попадали в дифф. Это отклонение объявлено в пререгистрации; тест хука — в
[`03-preflight.md`](03-preflight.md).

## 2. Поле и роль

Один и тот же brownfield-кейс: платёжный шлюз СБП (C2B-приём) и изменение «СБП-подписки».
Задание (`kit/TASK.md`) одинаково для всех ячеек, роль — solution-архитектор банка, хост —
Qwen Code 0.24.6 в живом TUI (tmux), решатель — `deepseek-flash` (DeepSeek-V4.1-Flash).

Контроль смешения: эффект Spine считается **внутри стека**, репозиторий у обеих сторон
сравнения одинаковый, а ячейка `plain` показывает, сколько процессной дисциплины даёт сам
репозиторий (в нём лежит `ARCHITECTURE-SPINE.md`, `CONSTRAINTS.yaml` и конвенция `changes/`).

## 3. Детерминированный слой (без LLM)

Запускается после хода по диффу `bench-baseline..HEAD`, единый для всех ячеек.

| Метрика | Смысл |
|---|---|
| `gate_class` | **PASS_DELTA** — гейт зелёный и есть дельта; **PASS_UNTOUCHED** — зелёный, но принятая архитектура не тронута (изменение живёт вне решения); **PASS_UNEXPLAINED** — зелёный при правке защищённых файлов без дельты (разбирается вручную); **FAIL** |
| `invariants.modified / removed / added` | какие **существующие** AD-001…AD-008 изменены — компенсирует слепую зону `delta_guard` (F4) |
| `contract_breaking` | ломающие изменения контракта (`arch-be contract-diff`); гейт их не включает (F3) |
| `gate_skips` | какие составляющие гейта ушли в SKIP на этом маршруте |
| `hook_blocks` | сколько раз Stop-хук вернул `exit 2` |
| `protected_touched`, `delta_dirs`, `spine_visible` | правки защищённых файлов, активные дельты, видимость решения для Spine |
| `contamination()` | обращения агента к путям вне своей ячейки |

## 4. Смысловой слой (судья)

- Рубрики Spine: `solution_architecture` (15 критериев), `architecture_gates` (A0–A5),
  `adr_quality`, `macedo_dimensions`.
- **Нейтральная рубрика** `neutral_architecture` (9 критериев) — написана не автором Spine:
  ISO/IEC/IEEE 42010 (драйверы, представления, обоснование), arc42, ADR в формате Nygard.
- Судья — другое семейство моделей (`glm-5.3`), чем решатель; `--author-model` равен решателю.
- Досье судьи: бюджет символов, стек-агностичный порядок файлов (`DOSSIER_PRIORITY`),
  правило выбора документа-решения (`DECISION_RULES`). Состав досье (включено, исключено,
  усечено) сохраняется в `score.json` каждого прогона.

## 5. Решающие правила (зафиксированы до прогонов)

- Доли (например, доля PASS_DELTA) — **точный тест Фишера**, для подтверждающих гипотез
  с поправкой Холма.
- Баллы — **точный перестановочный тест**; bootstrap 95 % CI служит описанием, а не решением.
- «Не хуже» = нижняя граница 90 % CI разности > −0.25. «≈ 0» = 90 % CI целиком внутри ±0.25.
  **При n < 4 в группе эти правила не применяются** — тогда итог пишется как «не оценимо».
- Итог рубрики с неоценёнными критериями отбрасывается (F7).
- Таймаут или обрыв агента — прогон с пустым результатом; он не выбрасывается.
- Основной анализ — ITT (все прогоны), вторичный — без загрязнённых.

## 6. Гипотезы

| | Формулировка | Итог |
|---|---|---|
| **H1** (подтверждающая) | для BMAD и superpowers доля PASS_DELTA в `S+spine-hook` выше, чем в `S` | направление подтверждено, значимости при n = 3 нет (p = 0.4 и 1.0) |
| **H2** (подтверждающая) | содержание при хуке не хуже (нижняя граница 90 % CI > −0.25) | **не оценимо**: n = 3 < 4 |
| H3 (исслед.) | хук сильнее совета по PASS_DELTA | 12/12 против 11/12 — советующий режим не хуже |
| H4 (исслед.) | Spine уменьшает долю PASS_UNTOUCHED у OpenSpec | 1/3 → 0/3 (со Spine) |
| H5 (исслед.) | вклад скиллов сверх репозитория (`plain+spine` − `plain`) | 2/3 → 3/3 |
| H6 (исслед.) | взаимодействие: даёт ли Spine стеку больше, чем голому хосту | CI во всех случаях пересекает 0 |
| H7 (исслед.) | `superpowers ≈ plain` | не оценимо при n = 3 |
| Пул (вне пререгистрации) | Spine и хук против отсутствия Spine по PASS_DELTA | **23/24 против 6/12, p = 0.0028** |

Пул — исследовательский: он не был зарегистрирован заранее и приводится рядом с
подтверждающим анализом, а не вместо него.
