# Волна v2.1 — контроль в файловой песочнице

Ответ на главный вопрос, который остался после v2:

> Чистый контроль v2 дал 0/6, но все шесть прошедших гейт контрольных прогонов **сами нашли
> материалы Spine** вне своей ячейки. Значит, «без Spine» означало «не нашли», а не «нет
> доступа». Подтвердится ли ноль при полной изоляции?

**Да, подтвердился: 0/12.** Точный тест Фишера против ячеек со Spine (23/24): **p = 1.0·10⁻⁸**.
Против объединённого чистого контроля (v2 0/6 + v2.1 0/12 = 0/18 против 23/24): **p = 5.4·10⁻¹¹**.

## 1. Что сделано

| Что | Как |
|---|---|
| Изоляция | контейнер `bench-agent:1` (debian + git); агент видит только `ws`, свой `HOME` и образ |
| Почему не bwrap | `kernel.apparmor_restrict_unprivileged_userns = 1`, bwrap не создаёт uid-map; прав на sysctl нет |
| Следы установки | нейтральные коммиты «Принятое решение: импорт» / «Рабочее окружение», единственная метка `accepted` |
| Мета-файлы ячейки | в контейнер не монтируются вообще |
| Счётчик хука | пишется в `/var/log/archgate/hook.log`, а не ищется по тексту журнала (П7) |
| Проба среды | до запуска агента — проверка внутри той же песочницы (П6) |
| Классификатор утечек | категории вместо «любого абсолютного пути» (П5) |

Отклонение от ревью одно и объявлено: **песочница на Docker, а не на bubblewrap** (П2).
Причина техническая, изоляция при этом строже: реальный `$HOME` оператора в контейнер
не попадает вообще.

## 2. Результат

| стек | n | PASS_DELTA | PASS_UNTOUCHED | FAIL | медиана стены, с |
|---|---|---|---|---|---|
| plain | 3 | 0 | 0 | 3 | 385 |
| openspec | 3 | 0 | 2 | 1 | 344 |
| bmad | 3 | 0 | 0 | 3 | 863 |
| superpowers | 3 | 0 | 0 | 3 | 358 |
| **итого** | **12** | **0** | 2 | 10 | **389** |

Ни один контрольный прогон в песочнице не изменил принятую архитектуру через дельту.
Два `PASS_UNTOUCHED` — OpenSpec: гейт зелёный, спайн не тронут, изменение живёт внутри
`openspec/changes/`. Это ровно тот класс, который в v2 был назван «зелёным без дисциплины».

## 3. Проверка утечек

| канал | срабатываний на 12 прогонов |
|---|---|
| материалы Spine (`arch-be`, `spine-bank`, `~/.arch-harness`, `~/.arch-ml`) | **0** |
| файлы харнесса и руководства | **0** |
| мета-файлы ячейки (`panel.txt`, `base.json`, `meta.json`, `prompt.txt`) | **0** |
| домашний каталог оператора | **0** |

Среда агента: `pwd` = `/home/architect/project`, `ls /home` → только `architect`,
`command -v arch-be` → пусто, `git log` → два нейтральных сообщения, `git tag` → `accepted`,
служебных переменных в `env` нет. Полный чек-лист — [`../results/v2.1/preflight.md`](../results/v2.1/preflight.md).

Одна тонкость: первый подсчёт дал `spine_material = 1` в `openspec r3`. Разбор показал фразу
«delta-spec structural headings» — название раздела формата OpenSpec, а не путь к материалам
Spine. Классификатор уточнён: токен `delta-spec` ищется только в форме пути. Это уточнение
к ревью, а не подгонка: срабатывание было ложным по смыслу, и оно названо.

## 4. Что это меняет в выводах

1. **Главный результат усилился, а не ослаб.** Контраст «есть доступ к процессу против нет»
   теперь опирается на чистый контроль: 23/24 против 0/18 (p = 5.4·10⁻¹¹).
2. **Механизм назван точнее.** Дисциплину изменения даёт **знание процесса Spine**, а не
   присутствие стека как такового: в v2 шесть контрольных прогонов прошли гейт ровно потому,
   что нашли `arch-be` и материалы в `$HOME` оператора. В песочнице этот канал закрыт — и
   контроль даёт ноль.
3. **«Зелёный гейт» перестал быть двусмысленным.** В v2.1 два прогона зелёные **без** касания
   спайна (`PASS_UNTOUCHED`): трёхзначный класс гейта работает и на чистом контроле.
4. **Хук по-прежнему не проверялся** в этой волне: ячеек со Spine в v2.1 нет. Его механика
   подтверждена в v2 (12/12 хуковых ячеек, `hook_blocks` ≥ 1).

## 5. Ограничения волны

- **Волна ограничена контролем** (12 прогонов). Ячейки со Spine не перезапускались: их 23/24
  от загрязнения контроля не зависят, но сравнение идёт между средами (хост в v2, контейнер
  в v2.1), и это надо держать в голове.
- **Судья не запускался.** Пререгистрация v2.1 заранее объявляла, что по рубрикам этой волны
  вывод не делается (контролю без Spine не с чем сравниваться по баллам), поэтому судейство
  пропущено ради бюджета времени. Это отклонение, объявленное в пререгистрации.
- **Пилот совмещён с повтором 1** (отклонение 1 в пререгистрации): первые четыре прогона
  проверены классификатором утечек и вошли в анализ.
- **Docker вместо bwrap** (отклонение 2). Если появится возможность включить непривилегированные
  пространства имён, bwrap-вариант стоит прогнать как проверку на устойчивость результата.
- **n = 3 на ячейку.** Как и в v2, значимы только большие эффекты; здесь эффект именно такой.

## 6. Воспроизведение

```bash
# образ песочницы
docker build -t bench-agent:1 harness/sandbox/Dockerfile
# прогон контроля в песочнице (12 ячеек)
BENCH_SANDBOX=docker BENCH_RUNS=runs-v2.1 BENCH_OPAQUE=1 \
  python3 harness/bench/bench.py run --conditions plain,openspec,bmad,superpowers --reps 3
# метрики и класс гейта
python3 harness/recheck_v2.py .          # числа v2 (для сравнения)
```

Скрипты песочницы и исправлений — [`harness/kit/harness_fixes.py`](../harness/kit/harness_fixes.py),
Dockerfile — [`harness/sandbox/Dockerfile`](../harness/sandbox/Dockerfile).
