# Статусная машина согласия и списания по согласию — спецификация переходов

- Status: Draft (для ревью на гейте A1 подписок)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, ADR-002, ADR-005, AD-009

## 1. Две сущности

1. **Согласие (Consent)** — самостоятельный объект, источник допустимости списания. Жизненный цикл описывается ниже.
2. **Списание (Debit)** — платёж с `initiationType=CONSENT`; переиспользует статусную машину платежа (ADR-002) с путём без `QR_ISSUED`.

## 2. Согласие: состояния

| Состояние | Смысл | Виден ТСП |
|---|---|---|
| `PENDING_APPROVAL` | запрос согласия создан, ожидается подтверждение плательщика/банка плательщика | да |
| `ACTIVE` | согласие действует, списания разрешены | да |
| `EXPIRED` | срок действия истёк | да |
| `REVOKED` | отозвано плательщиком (или ТСП) | да |
| `SUSPENDED` | приостановлено (комплаенс/антифрод/технически) | да |

Параметры согласия (иммутабельны после перехода в `ACTIVE`): `maxAmount`, `currency`, `validUntil`, `maxDebitsPerPeriod`/`frequency` (семантика — по НСПК `[ТРЕБУЕТ ПРОВЕРКИ]`), `tspId`.

## 3. Согласие: переходы

| № | From | To | Триггер | Guard (условие) |
|---|---|---|---|---|
| C1 | — | `PENDING_APPROVAL` | `POST /v1/consents` (новый `consentId`) | валидный запрос, ТСП активен |
| C2 | `PENDING_APPROVAL` | `ACTIVE` | событие адаптера `consent.activated` | параметры согласия валидны |
| C3 | `PENDING_APPROVAL` | `REVOKED` | отказ плательщика/НСПК или таймаут подтверждения | — |
| C4 | `ACTIVE` | `REVOKED` | `consent.revoked` (плательщик/НСПК/ТСП) | — |
| C5 | `ACTIVE` | `EXPIRED` | `validUntil` достигнут (таймер/сверка) | — |
| C6 | `ACTIVE` | `SUSPENDED` | комплаенс/антифрод или `transport.unavailable` | — |
| C7 | `SUSPENDED` | `ACTIVE` | снятие приостановки | согласие не истекло и не отозвано |

## 4. Списание (Debit)

Платёж с `initiationType=CONSENT`. Финансовые состояния — те же, что у платежа, но без `QR_ISSUED`:

`CREATED → PAID → CREDITED → COMPLETED`, терминальный `FAILED`; техническое подсостояние `DEBIT_PENDING` (списание отправлено в НСПК, ждём подтверждения).

| № | From | To | Триггер | Guard (условие) | Действие |
|---|---|---|---|---|---|
| D1 | — | `CREATED` | `POST /v1/payments` (`initiationType=CONSENT`, `consentId`) | **согласие в `ACTIVE`**, `amount ≤ maxAmount`, срок/частота соблюдены (AD-009) | запись платежа + outbox «списание в НСПК» |
| D2 | `CREATED` | `PAID` | нотификация НСПК `debit.confirmed` | сумма и получатель совпадают | outbox «зачисление в АБС» |
| D3 | `CREATED` | `FAILED` | отклонение НСПК / исчерпаны ретраи | ошибка не транзиентная | `errorCode`, вебхук `payment.failed` |
| D4 | `PAID` | `CREDITED` | подтверждение АБС (`absDocId`) | идемпотентно по `reference` (AD-005) | сохранить `absDocId` |
| D5 | `CREDITED` | `COMPLETED` | вебхук ТСП доставлен | — | вебхук `payment.completed` |
| D6 | `COMPLETED` | `REFUNDED` | сага возврата завершена | полный возврат, списание было зачислено | вебхук `refund.completed` |

## 5. Запрещённые переходы (инварианты)

- **Списание невозможно при согласии не в `ACTIVE`** (AD-009): guard D1 обязателен, проверяется fitness-тестом.
- Превышение `maxAmount`/`validUntil`/частоты → `FAILED` (или отклонение на входе) **до** обращения к НСПК.
- Повторный запрос списания с тем же `Idempotency-Key`/`reference` → тот же `paymentId`, нового списания нет (AD-003).
- Отзыв согласия (C4) не отменяет уже `PAID`/`CREDITED` списания — они доводятся до конца; отзыв блокирует только новые D1.
- `REVOKED`/`EXPIRED` — терминальные для согласия: повторная активация не допускается; новое согласие — новый `consentId`.
- Зачисление в АБС из `CREATED`/`DEBIT_PENDING` недостижимо (AD-005) — как и в QR-машине.

## 6. Идемпотентность и сверка

- События согласия (`consent.*`) дедуплицируются по `eventId` (ADR-004).
- Сверка: активные согласия и открытые списания — кандидаты ежечасной сверки с НСПК; расхождение «у нас `ACTIVE`, у НСПК `REVOKED`» → стоп-сигнал, эскалация, списание блокируется.
- Согласие в `PENDING_APPROVAL` дольше регламентного срока — сверка закрывает его в `REVOKED` (C3).

## 7. Согласованность с API ТСП

- Состояния согласия наружу: `PENDING_APPROVAL`, `ACTIVE`, `EXPIRED`, `REVOKED`, `SUSPENDED` — без внутренних подсостояний.
- Списание наружу — как платёж: `CREATED`, `PAID`, `CREDITED`, `COMPLETED`, `FAILED`, `REFUNDED`; поле `initiationType=CONSENT` и `consentId` присутствуют. `QR_ISSUED`/`EXPIRED` для списаний не выставляются (нет QR и TTL).
