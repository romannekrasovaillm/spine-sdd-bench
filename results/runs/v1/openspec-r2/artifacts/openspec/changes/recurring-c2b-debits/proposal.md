# Proposal

## Why

ТСП (онлайн-кинотеатры, ЖКХ, связь) требуют рекуррентные C2B-списания по согласию плательщика — «подписки СБП». Сегодня каждый платёж требует выпуска QR и действия клиента, что неприемлемо для регулярных начислений. Это новая финансовая возможность **поверх** принятого решения «Платёжный шлюз СБП (C2B-приём)», а не отдельная инициатива.

**Значимость и маршрут.** Оценка значимости ~8/15: высокое финансовое последствие ошибки (двойное списание), ПДн согласия (152-ФЗ), новая доменная сущность со своей статусной машиной, регуляторные требования к отзыву (161-ФЗ / правила НСПК). Маршрут — **Major**: глубокая проработка обязательна (новый ADR, delta-spec, изменения контракта, NFR), но платформа и транспорт уже в проектировании, поэтому повторного Solutioning уровня Critical не требуется. Обоснование глубины и детальный разбор — в `design.md`.

## What Changes

- Новая доменная сущность **Согласие плательщика** (`consent`/mandate) с собственным жизненным циклом и статусной машиной — второй источник истины в шлюзе наряду с платежом.
- **Рекуррентное списание** как платёж, инициируемый по активному согласию (без QR), повторно использующий существующую статусную машину платежа (`CREATED→…→COMPLETED`).
- Новые методы API ТСП: создание/просмотр/отзыв согласия, инициирование и просмотр списаний — **аддитивно**, в пределах `/v1`.
- Новые типы вебхуков `consent.*` и `debit.*` — аддитивно; существующие `payment.*` сохраняются без изменений.
- Расширение схем `PaymentRequest`/`Payment` опциональными полями (`paymentType`, `consentId`, `mandateRef`) без изменения обязательных полей.
- Расширение требований к вендору адаптера ОПКЦ (рекуррентные операции НСПК) и к сверке/аудиту/AML.
- Предлагаемый новый инвариант **AD-009**: согласие — отдельный источник истины; списание инициируется только по активному согласию в пределах лимитов.

Никаких **BREAKING** изменений существующего контракта нет.

## Capabilities

### New Capabilities
- `recurring-debits`: жизненный цикл согласия плательщика (создание, лимиты, отзыв/приостановка/истечение) и исполнение рекуррентных списаний с идемпотентностью по периоду.

## Impact

- **Инварианты spine**: AD-002 и AD-003 расширяются (второй автомат, новые ключи идемпотентности); AD-005 уточняется (зачисление только из подтверждённого статуса; согласие само по себе не является основанием для зачисления); предлагается AD-009. AD-001/AD-004/AD-006/AD-008 не меняются по сути. Ни один инвариант не нарушается.
- **API ТСП**: новые эндпоинты, события и опциональные поля — обратно совместимо, `/v1` сохраняется.
- **Адаптер ОПКЦ**: новые операции внутреннего контракта (`registerConsent`, `initiateRecurringDebit`) + событие; расширение RFP вендора.
- **Данные**: новая таблица согласий и планировщик списаний в платёжном контуре; требования RPO=0 распространяются на согласия.
- **Сверка / аудит / AML**: согласия и списания включаются в сверку, неизменяемый аудит-лог и AML-контроль.
