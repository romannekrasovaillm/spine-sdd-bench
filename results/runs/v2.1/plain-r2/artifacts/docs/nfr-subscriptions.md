# NFR — Подписки СБП (рекуррентные C2B-списания)

- Status: Draft (для ревью на гейте A1 изменения; целевые значения baseline)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, AD-003, AD-005, AD-009, AD-010

Дополняет `docs/nfr.md` (принятые NFR шлюза действуют без изменений). Ниже — **только новые** измеримые требования. Значения — baseline; финальные согласуются с бизнесом, АБС и НСПК (регламенты оператора могут быть строже) [ТРЕБУЕТ ПРОВЕРКИ].

## 1. Планировщик рекуррентных списаний (новый критичный компонент)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Точность инициирования планового списания | ≥ 99,9 % попыток инициируются в окне `plannedAt + 0…60 с` | Метрика лага планировщика |
| Пропущенные occurrence без исхода | 0 (каждая плановая попытка имеет ровно один исход: `INITIATED`/`SKIPPED`) | Сверка occurrence, тест на рестарт |
| Идемпотентность при рестарте/реплее планировщика | 0 вторых `Payment` по одной `occurrence` | Chaos-тест «убить планировщик перед инициированием → рестарт» |
| Доступность планировщика | ≥ 99,95 % (мес.) | SLO-отчёт |
| Горизонт планирования | не менее 30 суток вперёд рассчитанных occurrence | Проверка расписания |

## 2. Жизненный цикл согласия

| Метрика | Цель | Метод проверки |
|---|---|---|
| Активация подписки после подтверждения согласия ОПКЦ | p95 < 5 с | Метрика процесса |
| Сверка согласий с ОПКЦ | ежечасная; расхождений по активным согласиям — 0 | Reconciliation-отчёт |
| Fail-safe при расхождении | 100 % случаев «локально `ACTIVE`, в ОПКЦ `REVOKED`» приводят к стоп списаний | Тест: подмена данных сверки |
| Прекращение будущих списаний после отзыва | новых occurrence не инициируется: 0 списаний после подтверждения отзыва (кроме уже инициированных — см. §6) | Тест на отзыв согласия |

## 3. Списание и зачисление

| Метрика | Цель | Метод проверки |
|---|---|---|
| Инициирование → `PAID` | p95 < 10 с (без учёта времени банка плательщика) [ТРЕБУЕТ ПРОВЕРКИ] | Нагрузочный/интеграционный тест |
| `PAID` → зачисление в АБС | p95 < 60 с (наследует NFR зачисления) | Метрика процесса |
| Двойное списание по одной occurrence | 0 | Тест на повторную доставку/реплей |
| Двойное зачисление при повторах | 0 (наследует NFR шлюза) | Тест идемпотентности |

## 4. Лимиты и корректность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Списания сверх лимитов согласия | 0 (проверка на H2/H3) | Негативный тест `AMOUNT_EXCEEDS_CONSENT_LIMIT` |
| Списания при неактивных согласии/подписке | 0 (AD-009) | Fitness-тест запрещённых переходов |
| Плановые списания, обслуженные поверх уже завершённого согласия | 0 | Негативный тест |

## 5. Масштаб и производительность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Число активных подписок | baseline 100 000 (расширяемо) | Нагрузочный тест |
| Плановых списаний в сутки | baseline 300 000, пик в «часы списания» — по расчёту | Нагрузочный тест |
| Дополнительная нагрузка на шлюз | не выводит шлюз за принятые NFR (200 TPS sustained / 500 TPS пик) | Нагрузочный тест с профилем подписок |
| Деградация API ТСП при пике списаний | latency NFR v0.1 (`docs/nfr.md` §2) соблюдаются | Нагрузочный тест |

## 6. Гонка «отзыв ↔ инициированное списание»

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доля «списаний после отзыва, но в состоянии `INITIATED`/`PAID`» | измеряется и видима в отчёте; политика обработки определена (бизнес-решение) | Отчёт по гонкам, тест-кейс отзыва в момент списания |
| Автоматическая обработка таких случаев по политике | 100 % по runbook | KPI дежурной смены |

## 7. Безопасность, ПДн, аудит

| Метрика | Цель | Метод проверки |
|---|---|---|
| ПДн плательщика по согласию | минимизированы, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Доказательство согласия (воля плательщика) | хранится неизменяемо, доступно для аудита/спора | Аудит, ретеншен-политика |
| Переходы согласия/подписки/списания в аудит-логе | 100 %, лог неизменяем | Аудит, SIEM |
| Доступ операторов к управлению подписками/согласиями | 4-eyes для ручных операций | RBAC-проверка |

## 8. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace id на плановое списание | 100 % (от occurrence до вебхука) | APM |
| Алерт «occurrence без исхода» | ≤ 5 мин от обнаружения | Мониторинг |
| Алерт «расхождение согласий с ОПКЦ» | немедленно при обнаружении | Мониторинг |
| Отчёт незавершённых подписок/списаний | доступен всегда, актуален | Проверка |
| Лаг очереди нотификаций подписок | ≤ 60 с в норме (наследует NFR) | Мониторинг |

## Зависимости (внешние входы для NFR)

- Регламент НСПК по автоплатёжу: тайминги уведомления о списании, окна отзыва, лимиты [ТРЕБУЕТ ПРОВЕРКИ — из документации НСПК].
- Поддержка операций автоплатежа вендором транспорта (расширение RFP) — влияет на инициирование и сверку.
- SLA АБС — наследуется без изменений.
- Бизнес-политики: глубина ретраев отказанного списания, поведение при пропущенном окне, политика гонки отзыва (влияют на достижимые метрики §3/§6).
