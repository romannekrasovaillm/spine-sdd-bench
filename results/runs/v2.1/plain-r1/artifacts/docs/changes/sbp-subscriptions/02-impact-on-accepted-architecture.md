# 02. Влияние на принятую архитектуру

- Status: Draft (для рассмотрения на архитектурном решении)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, `ARCHITECTURE-SPINE.md` (AD-001…AD-008)

Оценка — по каждому принятому инварианту spine. Формулировка «инвариант не меняется» означает, что Rule остаётся дословно в силе; «расширяется» — что область применения растёт, но Rule не ослабляется.

## 1. Влияние на инварианты spine

| Инвариант | Влияние | Что именно |
|---|---|---|
| **AD-001** Изоляция платёжного контура | **Не меняется** | Мандаты, планировщик циклов и вся финансовая логика подписок размещаются в платёжном контуре; АБС и ОПКЦ — по-прежнему только через адаптеры шлюза |
| **AD-002** Единый источник истины — статусная машина | **Расширяется** | Каждый цикл — переходы «статус + outbox + аудит» в одной транзакции, как и сейчас. Добавляется техническое подсостояние `DEBIT_PENDING` (аналог `ABS_PENDING`/`NOTIFY_PENDING`, ADR-002 п.1). Финансовый enum не меняется |
| **AD-003** Идемпотентность финансовых операций | **Расширяется** | Новые ключи: регистрация мандата — по `Idempotency-Key`; цикл списания — по `(subscriptionId, cycleNumber)`; списание в ОПКЦ — по `reference` (= `paymentId`). Повторная доставка события мандата — по `eventId`. Rule (повтор не меняет завершённое состояние) — в силе |
| **AD-004** Единственный адаптер ОПКЦ | **Расширяется** | Протокол мандатов знает только адаптер ОПКЦ; добавляются операции/события контракта адаптера. Второй точки знания протокола не появляется |
| **AD-005** Зачисление только из подтверждённого статуса | **Не меняется, усиливается** | Зачисление цикла возможно только из подтверждённого НСПК статуса; из `DEBIT_PENDING`/`CREATED` — недостижимо. Требуется новый fitness-тест на недостижимость зачисления из цикла-в-обработке |
| **AD-006** Trust-зоны и сегментация | **Расширяется** | Новые точки входа: API подписок — в контуре ТСП-API (mTLS/WAF/rate limit); планировщик — внутренний; ключи/СКЗИ — без изменений (в адаптере) |
| **AD-007** Соответствие НПС, КИИ и ПДн | **Усиливается** | Добавляются согласие плательщика (неизменяемый аудит) и ПДн плательщика (минимизация, шифрование в покое, маскирование, журналирование доступа). Списание без действующего согласия запрещено |
| **AD-008** Стратегия реализации — гибрид **[ADOPTED]** | **Связывает (не меняется)** | Блок остаётся дословно. Следствие для изменения: транспорт мандатов — **вендорский**; расширение контракта адаптера входит в договор с вендором, реализация транспорта не начинается до получения документации НСПК. Менять AD-008 — только решением человека |

## 3. Что принципиально не меняется

- **Финансовый enum статусов платежа** и каноническая статусная модель CREATED→QR_ISSUED→PAID→CREDITED→COMPLETED (+ FAILED/EXPIRED/REFUNDED). Цикл подписки использует её как есть; новизна — только в техническом подсостоянии.
- **Модель зачисления в АБС**: документ с внешним ключом `paymentId`, идемпотентность на стороне шлюза, возвраты как сага (ADR-005).
- **Outbox, at-least-once, дедупликация по `eventId`, DLQ и сверка** (ADR-001, ADR-004).
- **Граница ядро↔транспорт и СКЗИ/HSM** (ADR-003, ADR-007, AD-008 [ADOPTED]).
- **Trust-зоны и модель ПДн** (ADR-006) — расширяются данными согласия, но не пересматриваются.

## 4. Новые инварианты (предлагаются, Proposed)

Добавляются в spine (см. §2); действуют после ратификации ADR-008.

- **AD-009. Подписка — отдельный агрегат над неизменным ядром платежа.**
  Binds: мандат (согласие), планировщик циклов, статусная машина, outbox, аудит.
  Prevents: смешивание жизненного цикла согласия с платежом; создание второго пути зачисления в обход AD-005; дубль/потеря цикла.
  Rule: каждый цикл — отдельный платёж, подчиняющийся AD-002/AD-003/AD-005; зачисление цикла — только из подтверждённого статуса; создание цикла и запись outbox — в одной транзакции.

- **AD-010. Согласие плательщика — неизменяемый аудируемый артефакт.**
  Binds: хранилище мандатов, аудит-лог, интеграция с ОПКЦ.
  Prevents: списание без действующего согласия; подлог/потерю согласия; нарушение 152-ФЗ.
  Rule: согласие хранится как неизменяемая запись с журналом; каждое списание ссылается на действующий мандат; отзыв согласия немедленно блокирует новые циклы, включая ещё не отправленные в ОПКЦ.

## 5. Риски изменения (архитектурные)

| Риск | Влияние | Митигация в пакете |
|---|---|---|
| Двойное списание при ретрае/перезапуске планировщика | Финансовый инцидент | Идемпотентность цикла `(subscriptionId, cycleNumber)`; идемпотентный вызов ОПКЦ по `reference`; fitness-тест |
| Списание без действующего согласия (гонка отзыв↔цикл) | Регуляторный/финансовый инцидент | Transaction-guard: проверка мандата и создание цикла в одной транзакции; приоритет отзыва |
| Протокол мандатов НСПК отличается от ожидаемого | Переработка адаптера | Локализация в вендорском адаптере (AD-008); `[ТРЕБУЕТ ПРОВЕРКИ]` до документации; POC-сценарии |
| Вендор не поддерживает мандаты в текущем контракте | Сроки | Расширение договора/RFP — решение человека; kill-criteria POC |
| Рост ПДн/регуляторной поверхности | Аудит/штрафы | Минимизация, шифрование, маскирование, неизменяемый аудит (ADR-006, AD-007, AD-010) |
| Согласие собрано, но функциональность сворачивают | Правовое обязательство | Трёхуровневая обратимость ADR-008: honor existing until expiry, stop-new |
