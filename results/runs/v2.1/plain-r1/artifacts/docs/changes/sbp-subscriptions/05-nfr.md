# 05. Измеримые NFR нового функционала (подписки СБП)

- Status: Draft (baseline; финализируются с НСПК и бизнесом)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, `docs/nfr.md` §7 (каноническое размещение), `docs/changes/sbp-subscriptions/06-acceptance-criteria-and-rollback.md`

Значения — измеримые критерии приёмки на гейтах A4/A5. Не заменяют базовые NFR (`docs/nfr.md` §1–6) и не ослабляют их: циклы подписок не должны ухудшать базовые SLO разовых платежей. Регламенты НСПК могут быть строже — помечено `[ТРЕБУЕТ ПРОВЕРКИ]`.

## 1. Функциональная надёжность (главное)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Двойные списания по одному циклу | **0** | Тест на повторный запуск цикла / повторное событие (N1, N2) |
| Списания без действующего согласия | **0** | Guard-тест: отозванный/истёкший мандат; гонка «отзыв ↔ цикл» (N5, N6) |
| Потеря цикла при недоступности ОПКЦ/АБС | **0** | Chaos-тест; сверка; отчёт незавершённых операций (N7, N9) |
| Идемпотентность `debitMandate` по `paymentId` | 100 % повторов → одна проводка | Тест повторного вызова (N1, N3) |
| Полнота аудита циклов и операций с согласием | **100 %**, лог неизменяем | Аудит/SIEM |
| Ссылка каждого списания на действующий мандат | 100 % | Проверка данных + аудит |

## 2. Производительность и лаг планировщика

| Метрика | Цель | Метод проверки |
|---|---|---|
| Регистрация мандата (`POST /v1/subscriptions`) | p95 < 500 мс, p99 < 1 с (без времени ОПКЦ) | Нагрузочный тест, APM |
| Активация мандата после подтверждения ОПКЦ | p95 < 60 с | Метрика процесса |
| Лаг планировщика циклов (план → создание цикла) | p95 < 60 с, p99 < 5 мин | Метрика планировщика |
| Зачисление цикла в АБС от подтверждения ОПКЦ | p95 < 60 с (SLA с АБС, как база) | Метрика процесса |
| Throughput подписок | не снижает базовые 200 TPS sustained / 500 TPS пик | Нагрузочный тест (совместно с разовыми платежами) |
| Масштабируемость планировщика | ×2 по числу мандатов без изменения архитектуры | Load-test |

## 3. Доступность и восстановление

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доступность функционала подписок | ≥ 99,95 % (мес.) | SLO-отчёт |
| RPO по мандатам и циклам | 0 | Тест отключения ноды |
| RTO | ≤ 1 ч | Chaos-тест, DR-учения |
| Доля успешных циклов с первой попытки | ≥ 97 % (исключая подтверждённые отказы плательщика) | Метрика; отказ плательщика не считается сбоем |

## 4. Отзыв согласия и сверка

| Метрика | Цель | Метод проверки |
|---|---|---|
| Остановка новых циклов после отзыва/отмены | ≤ 60 с (включая циклы, ещё не отправленные в ОПКЦ) | Тест N5/N6 |
| Отражение отмены/отзыва в ОПКЦ | p95 ≤ 5 с | Метрика интеграции |
| Сверка мандатов с ОПКЦ | ежечасная; расхождений по завершённым операциям — 0 | Reconciliation-отчёт |
| Разбор неуспешных циклов (DLQ) | 100 % по runbook за ≤ 4 ч | KPI дежурной смены (как база §4) |
| Алерт на DLQ циклов | за ≤ 5 мин | Мониторинг |

## 5. Безопасность, ПДн, наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| ПДн плательщика | минимизация, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Каналы к ОПКЦ для мандатов | 100 % на сертифицированных СКЗИ/ГОСТ, mTLS | ИБ-аудит |
| Trace id на цикл/мандат | 100 % | APM |
| Доступ операторов к ручным операциям с мандатами | 4-eyes | RBAC-проверка |

## 6. Зависимости (внешние входы для NFR)

- Точная механика и тайминги мандатов/списаний НСПК `[ТРЕБУЕТ ПРОВЕРКИ — документация НСПК]`.
- SLA АБС на списание/зачисление по циклам (согласуется с владельцем АБС).
- Правовая модель согласия и сроки его действия/отзыва `[ТРЕБУЕТ ПРОВЕРКИ — юристы/ИБ]`.
- Политика ретраев цикла (число попыток, окно) — регламент НСПК + бизнес (см. `07-human-decisions.md`).
