# Архитектурный контекст — дельта CHG-001 (подписки СБП)

Собран: 2026-09-29. Статус: **delta, применяется после ратификации ADR-008** (гейт A3′).

Источники: `docs/changes/CHG-001-sbp-subscriptions.md`, `docs/adr/ADR-008-sbp-podpiski-mandaty-rekurrentnye-spisaniya.md`, `docs/spec/mandate-state-machine.md`, `docs/contracts/tsp-api.md` §7, `docs/nfr.md` §7, `ARCHITECTURE-SPINE.md` (AD-009/AD-010).

## Цель и границы

Добавить к принятому C2B-шлюзу **рекуррентные списания по согласию плательщика** (подписки СБП): плательщик один раз подтверждает мандат, далее ТСП инициирует списания без участия клиента; плательщик может отозвать согласие. Границы: ядро (мандат, статусная машина дебета, контракты, сверка) — в scope; реальный протокол НСПК по подпискам — внешний вход `[ТРЕБУЕТ ПРОВЕРКИ]`, реализуется только за внутренним контрактом адаптера; планировщик списаний в шлюзе — вне baseline (решение человека, CHG-001 H1).

## Ключевая модель

- **Мандат** — отдельный ресурс, единственный источник авторизации списаний; состояния `CREATED, CONSENT_PENDING, ACTIVE, SUSPENDED, REVOKED, EXPIRED, REJECTED`; `ACTIVE` — только по подтверждению ОПКЦ; отзыв необратим; лимиты (сумма, период, число, срок) фиксируются при согласии.
- **Дебет** — это платёж: `CREATED → PAID → CREDITED → COMPLETED` / `FAILED`, **без `QR_ISSUED`**; тот же outbox, тот же гейт зачисления `PAID`, та же сага возврата.
- **Идемпотентность дебета** — `Idempotency-Key` + `(mandateId, billingRef)`; повтор с другой суммой → `409 DEBIT_CONFLICT`.
- **Гейт мандата** — проверка `ACTIVE` + лимитов **до** вызова ОПКЦ; отзыв блокирует новые дебеты немедленно.
- **Совместимость** — API ТСП v0.2 строго аддитивно; `Payment.status` не меняется; `MandateStatus` — отдельное перечисление.

## Связывающие инварианты (spine, применимые к этой дельте)

- **AD-009** — мандат-согласие как источник авторизации; гейт `ACTIVE` + лимиты; немедленная блокировка при отзыве; `mandateId`+версия в аудите.
- **AD-010** — единый денежный путь: дебет — это платёж в общей статусной машине/outbox; отдельного канала зачисления подписок нет.
- **AD-003** — идемпотентность (для дебета ключ `(mandateId, billingRef)`).
- **AD-005** — зачисление только из `PAID` (распространяется на дебеты).
- **AD-002** — переходы «статус + outbox + аудит» атомарны.
- **AD-008** — ядро контрактно-независимо от транспорта; протокол НСПК знает только адаптер.

## Стыки (контракты)

- **ТСП → шлюз:** `POST /v1/mandates`, `GET /v1/mandates/{id}`, `POST /v1/mandates/{id}/revoke`, `POST /v1/mandates/{id}/debits`; поля `mandateId`/`billingRef`; ошибки `MANDATE_*`, `DEBIT_CONFLICT`; события `mandate.*`.
- **Ядро → адаптер ОПКЦ:** создание/статус/отзыв мандата, создание/статус дебета (расширение контракта `opkc-adapter.md`); нормализованные события; идемпотентность по `reference`.
- **Ядро → АБС:** без изменений — зачисление по `paymentId`, списание по `refundId`.
- **Сверка:** мандаты — с ОПКЦ (ежечасно); дебеты — в общей сверке с АБС.

## Что запрещено

Расширять `Payment.status`; создавать денежный путь в обход статусной машины/outbox; считать мандат `ACTIVE` без подтверждения ОПКЦ; выполнять дебет при не-`ACTIVE` мандате или вне лимитов; начинать транспортную реализацию до ратификации ADR-008 и получения документации НСПК.
