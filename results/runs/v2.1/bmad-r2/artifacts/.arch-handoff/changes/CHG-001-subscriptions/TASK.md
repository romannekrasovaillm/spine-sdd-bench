# Задача для кодового харнесса — дельта CHG-001 (подписки СБП)

- Stage: **delta, применяется только после ратификации ADR-008** (гейт A3′, CHG-001 §7). До ратификации транспортная часть запрещена (AD-008).
- База: walking skeleton принятого решения (`docs/solutioning.md`, ADR-001..007). Настоящая задача — расширение, а не переписывание.

## Что реализовать (поверх walking skeleton)

1. **Мандат (согласие плательщика)** — ресурс со статусной машиной `CREATED → CONSENT_PENDING → ACTIVE → (SUSPENDED ⇄ ACTIVE) → REVOKED | EXPIRED`, терминальный `REJECTED`; лимиты (сумма, за период, число списаний, срок); `ACTIVE` устанавливается только по подтверждению мок-ОПКЦ; отзыв необратим. Спецификация — `docs/spec/mandate-state-machine.md`.
2. **Рекуррентное списание (дебет)** — платёж в существующей статусной машине (`CREATED → PAID → CREDITED → COMPLETED`, отказ `FAILED`; **без `QR_ISSUED`**), в том же транзакционном outbox; зачисление только из `PAID`; возврат — существующая сага.
3. **API ТСП v0.2** (обратно совместимо): `POST /v1/mandates`, `GET /v1/mandates/{mandateId}`, `POST /v1/mandates/{mandateId}/revoke`, `POST /v1/mandates/{mandateId}/debits`; необязательные поля `mandateId`/`billingRef`. `Payment.status` не расширять. Контракт — `openapi/tsp-api.yaml` v0.2.0, `docs/contracts/tsp-api.md` §7.
4. **Идемпотентность дебета** — по `Idempotency-Key` **и** паре `(mandateId, billingRef)`; повтор не создаёт второе списание/проводку; тот же `billingRef` с другой суммой → `409 DEBIT_CONFLICT`.
5. **События мандата** — `mandate.activated/suspended/revoked/expired/rejected`; результат дебета — существующие `payment.*` с `mandateId`/`billingRef`.
6. **Мок-адаптер ОПКЦ** расширить операциями/событиями подписок (создание/статус/отзыв мандата, дебет) — протокол НСПК не реализуется (внешний вход `[ТРЕБУЕТ ПРОВЕРКИ]`).
7. **Сверка мандатов** с мок-ОПКЦ (ежечасная логика) + дебеты в общей сверке с АБС-моком.
8. **Аудит** — каждый дебет хранит `mandateId` и версию согласия.

## Spine-инварианты (обязательны, дословные Rule)

- **AD-009**: «Любое рекуррентное списание инициируется только при мандате в состоянии `ACTIVE`, подтверждённом ОПКЦ, и только в пределах лимитов (сумма, период, число списаний, срок) на момент инициации. Отзыв, приостановка или истечение мандата немедленно блокируют новые списания; ядро не выставляет мандат `ACTIVE` по собственной инициативе. Каждый дебет хранит `mandateId` и версию согласия в аудит-логе.»
- **AD-010**: «Рекуррентное списание моделируется как платёж в той же статусной машине и том же транзакционном outbox; зачисление — только из `PAID` (AD-005), возврат — та же сага. Отдельного хранилища денежных операций подписок не создаётся: мандат даёт право инициировать платёж, но не меняет путь денег.»
- **AD-003 (уточнён)**: «Для рекуррентного списания ключ идемпотентности — пара `(mandateId, billingRef)` в дополнение к `Idempotency-Key`…»
- Сохраняются без изменений: AD-001, AD-002, AD-004, AD-005, AD-006, AD-007, AD-008.

**Запрещено менять:** значения `Payment.status`; правило зачисления только из `PAID`; границу «ядро ↔ транспорт» (AD-008); денежный путь и сагу возврата; trust-зоны/криптографию; семантику существующих ошибок/событий. Конфликт с spine обязан останавливать работу и эскалироваться.

## Критерии приёмки

- AC-CHG1-01…11 из `docs/changes/CHG-001-sbp-subscriptions.md` §6 — проверяемы на моках.
- Негативные сценарии обязательны: повтор дебета, дебет при не-`ACTIVE` мандате, превышение лимитов, отзыв во время in-flight, `billingRef` с другой суммой, дубль события ОПКЦ.
- NFR — `docs/nfr.md` §7 (лаги, отсутствие двойных списаний, лаг отзыва).
- Совместимость: клиент v0.1 работает без изменений; diff схем аддитивен.

## Контракт результата

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа):

```json
{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}
```

- `status`: `complete` — выполнено полностью; `partial` — частично; `blocked` — заблокировано (например, не ратифицирован ADR-008 или нет документации НСПК для транспортной части).
- `assumptions`: допущения; `open_questions`: вопросы к архитектору; `conflicts_with_prior_decisions`: расхождения с ADR/spine — обязаны останавливать работу.

Архитектурный контекст — `ARCHITECTURE.md`; ограничения — `CONSTRAINTS.yaml`.
