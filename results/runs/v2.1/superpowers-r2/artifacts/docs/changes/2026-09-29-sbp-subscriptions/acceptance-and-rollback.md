# Критерии приёмки и план отката — СБП-подписки

- Status: Draft (вход на гейты A3/A4; критерии проверяемы на моках и в бою)
- Date: 2026-09-29
- Owner: solution-architect (платёжный контур) + SRE + владелец продукта
- Related: ADR-008, ADR-009, `docs/spec/subscription-state-machine.md`, `docs/nfr.md` §7

## 1. Позитивные критерии приёмки

| ID | Критерий | Метод проверки |
|---|---|---|
| AC-S1 | ТСП создаёт мандат; плательщик соглашается; мандат становится `ACTIVE`; ТСП получает вебхук `mandate.activated` | Сквозной тест (walking skeleton на моках) |
| AC-S2 | По активному мандату списание проходит `CREATED/SENT → PAID → CREDITED → COMPLETED`, деньги зачислены на счёт ТСП один раз, ТСП получает `charge.completed` | Сквозной тест + сверка АБС |
| AC-S3 | Повторная инициация списания с тем же `Idempotency-Key` возвращает тот же `chargeId` без второго зачисления | Тест идемпотентности |
| AC-S4 | Повторная нотификация `charge.paid` с тем же `eventId` не меняет состояние и не создаёт вторую проводку | Тест дедупликации |
| AC-S5 | Полный/частичный возврат по зачисленному списанию работает по существующей саге возвратов | Тест возврата |
| AC-S6 | Метрики латентности/пропускной способности подписок уложены в NFR §7 | Нагрузочный тест |
| AC-S7 | Каждый мандат и каждый финансовый переход списания присутствует в неизменяемом аудит-логе; факт согласия сохранён | ИБ-аудит + запрос к аудит-логу |
| AC-S8 | Сверка синхронизирует статусы мандатов со сверкой НСПК без расхождений | Reconciliation-отчёт |

## 2. Негативные критерии приёмки (обязательны)

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| N1 | Списание при мандате в статусе `REVOKED`/`EXPIRED`/`REJECTED`/`SUSPENDED` | Отказ `422 MANDATE_NOT_ACTIVE`, **нулевое движение средств**, инцидент не создаётся |
| N2 | Списание сверх лимита на одно списание | Отказ `422 LIMIT_EXCEEDED`, деньги не движутся |
| N3 | Сумма списаний за период превышает `maxAmountPerPeriod` | Отказ `422 LIMIT_EXCEEDED` (пред-проверка шлюза), отсутствие списания |
| N4 | Дублирующая доставка `charge.paid` (новый `eventId` по уже завершённому переходу) | Состояние не меняется, алерт (признак расхождения); второй проводки нет |
| N5 | Отзыв мандата плательщиком во время уже инициированного списания (гонка) | Ровно один исход по правилу НСПК: либо списание отклонено, либо доведено до `COMPLETED`; **двойного зачисления нет**; отзыв отражён в аудите |
| N6 | Недоступность ОПКЦ/НСПК при инициации списания или приёме нотификации | Операция не теряется: ретраи/circuit breaker/DLQ, сверка дозакрывает; двойных списаний нет |
| N7 | Недоступность АБС после подтверждения `PAID` | Списание остаётся `PAID`, видно в отчёте незавершённых, зачисление гарантируется сверкой; дубля нет |
| N8 | Повторный отзыв мандата / повторный запрос статуса | Идемпотентно: состояние не меняется, ошибки нет |
| N9 | Попытка списания без действующего согласия (мандат отсутствует) | Отказ `404/422`, деньги не движутся, событие в аудите |

## 3. Сигналы-триггеры отката

Откат изменения инициируется дежурной сменой/архитектором при любом из сигналов:

- зафиксировано двойное зачисление или двойное списание по одному `chargeId` (финансовый инцидент);
- доля успешных списаний ниже порога бизнеса при активных мандатах (устойчивое падение);
- расхождение статусов мандатов с НСПК не устраняется сверкой за ≤ 4 ч;
- массовые отказы/жалобы плательщиков, связанные с автосписаниями;
- деградация основного C2B-приёма из-за нагрузки подписок (регресс существующего SLO).

## 4. План отката

**До боевой эксплуатации (текущая фаза):** откат = не включать. Изменение аддитивно, данные существующих платежей не мигрируются; удаление/перекрытие фиче-флага достаточно.

**После включения (боевой режим):**

1. **Stop-new (немедленно, ≤ 5 мин):** фиче-флаг отключает приём новых мандатов и инициацию новых списаний. Обработка уже открытых операций, зачисление, возвраты и нотификации **продолжаются** (не останавливаются).
2. **Drain (в пределах SLA):** незавершённые списания доводятся до терминального состояния либо компенсируются по runbook; сверка обязательна.
3. **Защита данных:** БД шлюза остаётся источником истины по зачислению; обратной миграции нет — мандаты/списания сохраняются для отчётности и аудита.
4. **Статусы мандатов:** действующие согласия закрываются/приостанавливаются по политике (через НСПК, если требуется), чтобы исключить списания «в пустоту».
5. **Откат релиза:** rolling-back без downtime (совместимо с NFR §1 исходного решения); контракты аддитивны, старые потребители не затронуты.
6. **Аварийная ветка:** DLQ → дежурная смена по runbook; сверка компенсирует потерянные нотификации; RTO ≤ 1 ч.

**Критерий успешного отката:** новые мандаты/списания не создаются; все уже созданные доведены до терминального состояния (или явно видны в отчёте незавершённых); сверка НСПК и АБС без расхождений; двойных проводок — 0; основной C2B-приём работает в штатном SLO.

## 5. Владельцы решения

- **Инициировать откат:** дежурная смена SRE (по сигналу) либо solution-архитектор (по архитектурному риску).
- **Подтвердить и согласовать:** solution-архитектор + владелец продукта; при регуляторном риске — ИБ/комплаенс.
- **Исполнить:** SRE/эксплуатация (фиче-флаг, drain, runbook), команда сопровождения АБС/НСПК при необходимости.
- **Решение «не включать» на этапе проектирования:** человеческий архитектор на гейте A3.
