# ADR-009. Транспорт подписок: расширение единственного адаптера ОПКЦ и scope RFP

- Date: 2026-09-29
- Status: Proposed (зависит от подтверждения протокола подписок НСПК; вступает после ADR-008 / A3′)
- Owner: solution-architect (платёжный контур) + проектный офис/закупки + ИБ
- Related: ADR-003, ADR-007, ADR-008, AD-004, AD-008

## Context

Для подписок (ADR-008) нужен обмен с ОПКЦ СБП: регистрация согласия, его активация/отзыв/истечение и списание по согласию. Протокол подписок НСПК — внешний вход `[ТРЕБУЕТ ПРОВЕРКИ]`; неизвестно, доступен ли он вендору транспортного адаптера и на каких условиях. Инварианты AD-004 (единственный адаптер ОПКЦ) и AD-008 (ядро контрактно-независимо от транспорта) должны сохраниться.

## Decision

1. **Протокол подписок знает только адаптер ОПКЦ** (AD-004 не нарушается); ядро не разбирает протокольные детали (AD-008).
2. **Внутренний контракт адаптера расширяется** (`docs/contracts/opkc-adapter.md` v0.2): методы `registerConsent`, `getConsentStatus`, `revokeConsent`, `createPaymentByConsent`; события `consent.activated`, `consent.rejected`, `consent.revoked`, `consent.expired` (для списаний переиспользуется существующее `payment.paid`).
3. **Идемпотентность мутирующих вызовов по `reference`** — как для разовых операций: повтор `registerConsent` / `createPaymentByConsent` не создаёт дубль в ОПКЦ. Обязательное требование к вендору.
4. **RFP и контракт вендора расширяются** (`docs/rfp/vendor-rfp.md` §12): поддержка протокола подписок, тестовый контур со сценариями активации/отзыва/лимитов/повторов, SLA на события согласий; критерий допуска проверяется на POC.
5. **Если вендор не поддерживает подписки** — варианты для A3′: (а) смена/дополнение вендора; (б) доработка транспорта с пересмотром ADR-007; (в) временный fallback — gateway-scheduler без автосписания (альтернатива в ADR-008). Решение фиксируется отдельным ADR.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Расширить существующий адаптер и вендора (выбран при поддержке протокола)** | Единый контур; наследуются СКЗИ/сертификация, мониторинг, эксплуатация; сохраняется AD-004 | Риск: вендор не умеет подписки; расширение стоимости и сроков |
| Отдельный адаптер/вендор только для подписок | Независимость по срокам | Дублирование транспорта и СКЗИ-контура; нарушает AD-004 (единственный адаптер); сложнее аудит и сверка |
| Говорить с НСПК напрямую из ядра | Нет прослойки | Отклонено: ADR-003/AD-004 — расползание протокола, несертифицированная криптография |

## Consequences

### Positive

- Сохраняется единая точка знания протокола НСПК и заменяемость транспорта.
- Подписки наследуют сертифицированный транспорт, СКЗИ/HSM, мониторинг и сверку.

### Negative

- Расширение scope и стоимости вендорского контракта; сроки зависят от внешнего поставщика.
- Возможная задержка до подтверждения поддержки протокола — потенциально блокирующий внешний вход для подписок.

## Reversibility

**reversible** — расширение аддитивно к контракту, транспорт заменяем; при отказе вендора возможен пересмотр ADR-007 (гибрид) с сохранением границы контракта.
