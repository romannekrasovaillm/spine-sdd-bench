# Proposal

## Why

ТСП (онлайн-кинотеатры, ЖКХ, связь) просят **рекуррентные C2B-списания по согласию плательщика** (подписки СБП). Сейчас принятое решение «Платёжный шлюз СБП (C2B-приём)» поддерживает только оплату по QR/ссылке, где каждое списание требует сканирования QR и действия клиента, — модель подписки на нём не строится. Бизнес теряет сегмент регулярных платежей; изменение добавляет способ инициирования платежа **без QR и без участия клиента на каждое списание**, не ломая существующий приём C2B и его инварианты.

## What Changes

- **Новый ресурс «согласие плательщика» (mandate)**: регистрация согласия (оформляется плательщиком в банке плательщика через ОПКЦ), параметры (лимит на списание, суммарный лимит, срок действия, периодичность, реквизиты получателя), статусная модель, изменение и полный/частичный отзыв, идемпотентность.
- **Новое инициируемое списание (debit) по действующему согласию**: платеж инициирует ТСП, а не плательщик; без динамического QR. Сохраняются AD-005 (зачисление только из подтверждённого ОПКЦ статуса), AD-002 (атомарные переходы «статус + outbox + аудит»), AD-003 (идемпотентность повторных доставок).
- **Расширение статусной модели**: отдельный автомат согласия и новый поток инициируемого платежа; канонические состояния платежа CREATED→QR_ISSUED→PAID→CREDITED→COMPLETED **не меняются** для существующего способа, новый поток добавляет свои состояния/подсостояния (детали — `design.md`).
- **Расширение API ТСП**: новые ресурсы `/v1/mandates`, `/v1/debits` — **аддитивно**, существующие методы и поля не изменяются (без **BREAKING**).
- **Расширение внутреннего контракта адаптера ОПКЦ** операциями согласий и инициируемых списаний; транспортный протокол НСПК по автоплатежам — внешний вход `[ТРЕБУЕТ ПРОВЕРКИ]`.
- **Новые NFR и fitness-тесты**: лимиты списаний, задержки, идемпотентность, запрет списания по отозванному/исчерпанному согласию (детали — `design.md`, дельта к `docs/nfr.md`).
- **Ратификация инвариантов**: новый AD для рекуррентного списания и дельта к AD-002/AD-003/AD-005 (spine обновляется **после** архитектурного решения, не в этом пакете).

## Capabilities

### New Capabilities

- `subscriptions/mandates`: жизненный цикл согласия плательщика — регистрация, параметры (лимиты/срок/периодичность), изменение, отзыв, статусная модель, идемпотентность, аудит и уведомления ТСП о событиях согласия.
- `subscriptions/debits`: инициируемое C2B-списание по действующему согласию — создание, статусная модель, зачисление по подтверждённому ОПКЦ статусу, возвраты, обработка отказов/отзыва, сверка.
- `tsp-api`: расширение мерчант-API СБП-шлюза новыми ресурсами подписок; аддитивная обратно совместимая эволюция `openapi/tsp-api.yaml` и `docs/contracts/tsp-api.md`.

### Modified Capabilities

Пусто: `openspec/specs/` не содержит спецификаций (принятые требования зафиксированы в `docs/` вне OpenSpec). Дельты к `docs/contracts/opkc-adapter.md`, `docs/spec/state-machine.md`, `docs/nfr.md` и `ARCHITECTURE-SPINE.md` оформляются **после ратификации** этого изменения и в данный пакет как правки принятых файлов не входят.

## Impact

- **Контракты (аддитивно, без поломки потребителей):** `openapi/tsp-api.yaml` — новые пути/схемы `/v1/mandates`, `/v1/debits`; `docs/contracts/tsp-api.md` — новые разделы; `docs/contracts/opkc-adapter.md` — новые операции/события (согласия, инициируемые списания).
- **Архитектура:** `ARCHITECTURE-SPINE.md` — новый AD (рекуррентное списание) + дельта AD-002/AD-003/AD-005; `docs/adr/` — новый ADR (по итогам ратификации); AD-008 (гибрид, транспортный адаптер) **не затрагивается**.
- **Компоненты шлюза:** статусная машина (новый автомат согласия + поток debit), API ТСП, адаптер ОПКЦ, нотификатор ТСП, сверка, БД (таблицы mandates/debits + outbox/аудит), антифрод/AML (лимиты).
- **Внешние входы:** протокол НСПК по согласиям/автоплатежам и его регламенты (таймауты, лимиты, сроки нотификаций) `[ТРЕБУЕТ ПРОВЕРКИ]` — по договору/Порталу поддержки НСПК; подтверждение возможности продукта в Правилах ОПКЦ СБП.
- **Регуляторика и соответствие:** 161-ФЗ (переводы), 152-ФЗ (согласие — правовое основание и ПДн), 115-ФЗ (лимиты/мониторинг), 187-ФЗ/КИИ (новый поток в том же защищённом контуре).
- **Эксплуатация:** новые runbook-и (массовый отзыв согласий, исчерпание лимитов, DLQ списаний), расширение мониторинга и отчётности ЦБ/НСПК.
