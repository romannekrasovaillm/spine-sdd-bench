# Статусная машина мандата подписки — спецификация переходов

- Status: Draft (для ревью на архитектурном гейте; связанное изменение — `openspec/changes/sbp-recurring-payments`)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, ADR-009, AD-002, AD-003, AD-009 (new), AD-010 (new)

Единый источник истины коммерческого состояния мандата — БД шлюза (ADR-008). Факт согласия и отзыва плательщика авторитетно определяется ОПКЦ и зеркалится в шлюз событиями и сверкой. Каждый переход — **атомарная транзакция** «смена состояния + запись в outbox + аудит-лог» (AD-002). Повторные события ОПКЦ идемпотентны по `eventId` (AD-003).

## 1. Состояния мандата

| Состояние | Смысл | Терминальное |
|---|---|---|
| `PENDING_CONSENT` | Мандат зарегистрирован ТСП, ожидается подтверждение согласия плательщиком | нет |
| `ACTIVE` | Согласие подтверждено; списания в пределах лимитов разрешены | нет |
| `SUSPENDED` | Временная приостановка (по требованию ТСП или ОПКЦ); новые списания запрещены | нет |
| `REVOKED` | Согласие отозвано плательщиком; новые списания запрещены навсегда | да |
| `EXPIRED` | Согласие не подтверждено в TTL либо срок мандата истёк | да |

## 2. Таблица переходов

| № | From | To | Триггер | Guard (условие) | Действие при переходе |
|---|---|---|---|---|---|
| M1 | — | `PENDING_CONSENT` | регистрация мандата ТСП (`POST`, `Idempotency-Key`) | ТСП активен; лимиты валидны | запись мандата + outbox-событие «регистрация в ОПКЦ»; ссылка/QR согласия |
| M2 | `PENDING_CONSENT` | `ACTIVE` | подтверждённое событие ОПКЦ об активации | подтверждение плательщика получено | фиксация лимитов; outbox-нотификация ТСП `subscription.activated` |
| M3 | `PENDING_CONSENT` | `EXPIRED` | TTL подтверждения истёк | подтверждение не получено | outbox-нотификация ТСП; списаний не было |
| M4 | `PENDING_CONSENT` | `REVOKED` | событие ОПКЦ об отказе/отзыве | — | outbox-нотификация ТСП; терминально |
| M5 | `ACTIVE` | `SUSPENDED` | приостановка (ТСП или ОПКЦ) | — | запрет новых списаний; outbox-нотификация |
| M6 | `SUSPENDED` | `ACTIVE` | возобновление (ОПКЦ) | согласие по-прежнему действует | разрешение списаний; outbox-нотификация |
| M7 | `ACTIVE`/`SUSPENDED` | `REVOKED` | подтверждённое событие об отзыве согласия | — | **немедленный запрет новых списаний**; outbox-нотификация; терминально |
| M8 | `ACTIVE`/`SUSPENDED` | `EXPIRED` | истечение срока мандата | — | запрет новых списаний; outbox-нотификация |
| M9 | `ACTIVE` | `REVOKED` | сверка: у ОПКЦ отозвано, у шлюза `ACTIVE` | расхождение подтверждено сверкой | блокировка списаний + алерт; терминально |

Разрешение списаний возможно **только** в состоянии `ACTIVE`.

## 3. Запрещённые переходы (инварианты)

- **Новое списание невозможно из любого состояния, кроме `ACTIVE`** (AD-009). Из `PENDING_CONSENT`/`SUSPENDED`/`REVOKED`/`EXPIRED` — недостижимо; проверяется fitness-тестом.
- `REVOKED` и `EXPIRED` — терминальные: из них переходов нет. Реактивация отозванного мандата невозможна — только новый мандат.
- **Отзыв согласия приоритетен**: событие отзыва обрабатывается вне очереди относительно рутинных операций и необратимо.
- Лимиты мандата иммутабельны после `ACTIVE` (M2); изменение — только новый мандат.
- Согласие плательщика не может быть подтверждено шлюзом или ТСП — только событием ОПКЦ.

## 4. Обработка повторных триггеров (идемпотентность)

| Триггер | Ключ идемпотентности | Поведение при повторе |
|---|---|---|
| Регистрация мандата ТСП | `Idempotency-Key` | возврат того же `mandateId`, состояние не меняется |
| Событие ОПКЦ (активация/отзыв/приостановка) | `eventId` | обработанный `eventId` игнорируется; состояние не меняется |
| Инициирование списания | детерминированный `chargeId` + `Idempotency-Key` | возврат существующего `chargeId`, второе списание не создаётся |
| Подтверждение АБС по списанию | `chargeId`/`paymentId` | без второй проводки |

## 5. Переходы списания и связь с зачислением

Жизненный цикл рекуррентного списания: `CREATED → AWAITING_CONFIRMATION → PAID → CREDITED → COMPLETED`, терминальные `FAILED`/`EXPIRED`/`REFUNDED` (ветка `AWAITING_CONFIRMATION` используется только для сумм выше порога подтверждения).

- **Зачисление в АБС невозможно, кроме как из `PAID`** (AD-005, AD-010). Из `CREATED`/`AWAITING_CONFIRMATION` — недостижимо; проверяется fitness-тестом.
- `EXPIRED` списания означает «плательщик не подтвердил в TTL»: средства не списаны, зарезервированный лимит освобождён.
- Возврат (`REFUNDED`) — только из `COMPLETED`, через существующую сагу (ADR-005).

## 6. Сверка и расхождения

- Мандаты (`ACTIVE`, `SUSPENDED`) — кандидаты для периодической сверки с ОПКЦ; целевой регламент — ежечасный.
- Расхождение «у ОПКЦ отозвано, у шлюза `ACTIVE`» → M9: блокировка списаний + алерт; разрешение в пользу ОПКЦ.
- Расхождение по лимитам/срокам → приведение к данным ОПКЦ, инцидент в отчёт незавершённых операций.
- Списания без итогового статуса → дозапрос у ОПКЦ; при подтверждении — обработка как нотификация (ADR-004).

## 7. Политика списаний «в полёте» при отзыве (D7)

При переходе M7/M9 для уже инициированных списаний по мандату:

- `PAID` (подтверждённые) — доводятся до зачисления: обязательство исполнено, откат создал бы «зависшие деньги» и диспуты;
- `CREATED`/`AWAITING_CONFIRMATION` (не подтверждённые) — отменяются без списания средств, зарезервированный лимит освобождается.

Политика подлежит юридическому подтверждению (см. `design.md` — Open Questions).
