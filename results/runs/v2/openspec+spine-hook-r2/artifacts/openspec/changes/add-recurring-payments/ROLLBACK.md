# План отката — add-recurring-payments

## Владелец решения об откате

- **Технический откат** (флаг off, откат релиза): дежурный руководитель эксплуатации платёжного контура.
- **Продуктовый откат** (вывод функции у ТСП, отзыв согласий): solution-architect платёжного контура + владелец продукта ТСП.
- **Регуляторный/ИБ-триггер** (несанкционированные списания, инцидент ИБ): ИБ — право инициировать немедленный stop-new.

## Сигналы-триггеры отката

1. Любое списание без действующего согласия (нарушение AD-009) — немедленный stop-new.
2. Двойное списание по одной подписке за период (нарушение AD-010) — stop-new + разбор.
3. Отзыв согласия не блокирует списания сверх NFR (≤ 5 с) в серии наблюдений.
4. Рост отказов/инцидентов на QR-потоке после релиза (регрессия).
5. Инцидент ИБ/антифрода, связанный с рекуррентным потоком.

## Шаги отката

### До боевой эксплуатации (обратимо, дешёвый откат)

1. Не включать фиче-флаг — функционал недоступен, QR-поток не затронут.
2. Согласия не выдаются; данные тестового контура изолированы.

### После включения (по ТСП)

1. **Stop-new**: фиче-флаг off для затронутых ТСП → новые эндпоинты возвращают `404/403`; новые списания невозможны; уже открытые операции дообрабатываются.
2. **Откат релиза**: rolling-откат до предыдущей версии; БД не мигрируется обратно (аддитивные таблицы/поля остаются).
3. **Отзыв согласий**: по runbook отозвать выданные согласия (`POST /v1/consents/{id}/revoke` или через НСПК) — ≤ 4 ч (NFR).
4. **Открытые операции**: `DEBIT_PENDING`/`PAID` без зачисления — в отчёт незавершённых операций; закрытие через сверку с НСПК/АБС.
5. **Уведомление**: ТСП получают `consent.revoked`/уведомление об отключении функции.

## Что НЕ откатывается

- Завершённые (`COMPLETED`) списания и зачисления — необратимы; корректируются только возвратами (сага ADR-005).
- Данные согласий/подписок сохраняются (нужны для аудита и сверки).

## Критерий успешного отката

См. `ACCEPTANCE.md` — «Критерий успешного отката»: новые списания невозможны, согласия в не-`ACTIVE`, QR-поток зелёный, открытые операции закрыты/в сверке.

## Репетиция

Репетиция отката проводится на handoff-пакете: `arch-be control gate A4 <packet> --rehearse` → `.arch-handoff/REHEARSAL.json`. Сигналом считается успешная репетиция «stop-new + отзыв согласий» на тестовом контуре.
