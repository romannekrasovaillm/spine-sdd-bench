# ADR-011. Расширение статусной машины платежа для рекуррентных списаний (origin=MANDATE)

- Date: 2026-09-28
- Status: Proposed
- Owner: solution-architect (платёжный контур)
- Модель-автор: qwen
- Related: ADR-002, ADR-005, ADR-008, ADR-009, AD-002, AD-005, AD-009, AD-011

## Context

Принятая статусная машина платежа (`docs/spec/state-machine.md`) входит в `PAID` только из `QR_ISSUED` (переход T4), а `QR_ISSUED` получается регистрацией QR (T2). Рекуррентное списание (ADR-008) не имеет QR: дебет инициируется по согласию, и ОПКЦ либо подтверждает исполнение, либо отклоняет. Если переиспользовать платёж как источник финансовой истины списания (ADR-008), нужен переход в `PAID` без QR-пути — иначе «списание→платёж→зачисление» невыразимо (переход `CREATED→PAID` в принятой машине отсутствует, а `QR_ISSUED`/`EXPIRED` для списания недостижимы).

## Decision

Платёж получает признак происхождения **`origin`** (`QR` | `MANDATE`):
- `origin=QR` — принятая машина без изменений: `CREATED → QR_ISSUED → PAID → CREDITED → COMPLETED` (+ `EXPIRED`).
- `origin=MANDATE` — переход `CREATED → PAID` выполняется по подтверждению ОПКЦ о списании (нотификация/сверка), **без** `QR_ISSUED`; далее `PAID → CREDITED → COMPLETED` как в принятой машине. Состояния `QR_ISSUED`/`EXPIRED` для `origin=MANDATE` недостижимы; отказ исполнения приводит к `FAILED`.

Зачисление по-прежнему возможно только из `PAID` (AD-005). Переход для `origin=MANDATE` идемпотентен по `eventId`/`paymentId` (AD-003/ADR-002).

## Alternatives Considered

| Вариант | Плюсы | Минусы | Почему отвергнут |
|---|---|---|---|
| A. Искусственно проводить списание через `QR_ISSUED` (создавать фиктивный QR) | нет изменения машины | ложная семантика (QR нет), лишние артефакты ОПКЦ, риск «платежей из воздуха» | искажает модель и аудит |
| B. Отдельная статусная машина списания | независимость | второй источник истины для денег, дублирование AD-002/AD-005 | противоречит ADR-008/AD-002 |
| C. Разрешить `CREATED→PAID` для всех платежей | проще | ослабляет QR-путь, ломает запрещённый переход/инварианты | размывает AD-005 и принятую машину |
| **D. `origin`-обусловленный переход `CREATED→PAID` только для `origin=MANDATE` (выбрано)** | точное расширение без изменения QR-пути; единый источник истины | новая ось (`origin`) в модели платежа | — |

## Consequences

### Positive

- QR-путь не меняется; существующие потребители и инварианты (AD-005) сохраняются.
- Единая финансовая модель: зачисление списания идёт через тот же `PAID→CREDITED→COMPLETED`.
- `QR_ISSUED`/`EXPIRED` явно недостижимы для списаний — аудит не допускает «фантомных» QR.

### Negative

- В модели платежа появляется ось `origin`, влияющая на допустимые переходы и тесты — растёт число тест-кейсов.
- Требуется обновить спецификацию статусной машины и fitness-проверки (запрет `QR_ISSUED` для `origin=MANDATE`).

## Reversibility

**reversible.** Расширение аддитивно и ограничено признаком `origin`; откат — перестать создавать `origin=MANDATE` платежи, QR-путь не затронут.

Условие пересмотра (expiry): получение протокола НСПК по списаниям; если ОПКЦ требует иных состояний (например, отдельного подтверждения), переходы `origin=MANDATE` уточняются.
