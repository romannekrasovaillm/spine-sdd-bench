# Дельта: recurring-c2b

- Route: Critical — полное Solutioning (пакет `docs/change/recurring-c2b-change-package.md`, ADR-008); Significance Score 5/15 (api_contract_change, data_contract_change, consistency_model_change, significant_nfr, financial_impact)
- Created: 2026-09-28

## Проблема

ТСП (онлайн-кинотеатры, ЖКХ, связь) просят рекуррентные C2B-списания по согласию плательщика (подписки СБП); сейчас каждый платёж требует QR и действия клиента. Нужен новый доменный объект — мандат плательщика (согласие) — и списание без QR, инициируемое ТСП, без ослабления принятых инвариантов (зачисление только из `PAID`, атомарность, идемпотентность, аудит).

## ADDED

- When ТСП регистрирует мандат (`POST /v1/mandates`), the шлюз shall создать мандат в состоянии `PENDING_CONSENT` и зарегистрировать его в ОПКЦ.
- When плательщик подтверждает согласие (событие ОПКЦ), the шлюз shall перевести мандат в `ACTIVE` и зафиксировать доказательство согласия в неизменяемом аудите.
- When ТСП инициирует списание (`POST /v1/mandates/{mandateId}/payments`), the шлюз shall выполнить guard-проверки (мандат `ACTIVE`, `amount ≤ maxAmountPerDebit`, сумма и число списаний за период в пределах лимитов, `now ≤ validUntil`, валюта, активность ТСП) до вызова ОПКЦ.
- If guard-проверка не пройдена, the шлюз shall отклонить запрос (`422`) без вызова ОПКЦ и без финансового действия.
- When дебет подтверждён банком плательщика/НСПК, the шлюз shall перевести платёж в `PAID` и разрешить зачисление в АБС только из `PAID` (AD-005, AD-010).
- When приходит повторный запрос/событие (тот же `Idempotency-Key`/`paymentId`/`eventId`), the шлюз shall не создавать второе списание, не расходовать лимит повторно и не зачислять дважды (AD-003).
- When мандат отозван или приостановлен (ТСП/плательщиком/банком), the шлюз shall немедленно запретить новые списания; отзыв плательщика через НСПК приоритетен.
- When состояние мандата меняется, the шлюз shall менять статус, писать outbox-событие и аудит в одной локальной транзакции (AD-002, AD-007).
- When дебет/мандат меняет состояние, the шлюз shall доставить вебхук ТСП (`payment.completed`/`payment.failed`/`mandate.*`) with at-least-once и дедупликацией по `eventId`.

## План отката

Фиче-флаг `recurring_c2b` (глобально/по ТСП): выключение останавливает приём новых мандатов и новых списаний, не затрагивая QR-поток и уже открытые операции (обработка, отзыв, вебхуки, сверка продолжаются); при необходимости — массовый отзыв мандатов по runbook. Данные обратной миграции не требуют (мандат — новый объект). Сигналы: списание без действующего согласия, дубль, расхождение статусов мандатов с НСПК, провал испытаний НСПК. Владелец решения — архитектор + дежурная смена (SRE) + ИБ. RTO ≤ 1 ч. Подробно — пакет изменения §6.

## Критерии приёмки

- [ ] Счастливый путь: мандат → согласие (`ACTIVE`) → дебет → `PAID` → `CREDITED` → `COMPLETED` → вебхук.
- [ ] Списание при мандате не в `ACTIVE` → `422`, вызова ОПКЦ и финансового действия нет.
- [ ] Списание сверх лимитов (`maxAmountPerDebit`/`maxTotalAmount`/`maxDebitsPerPeriod`) → `422`, лимит не израсходован.
- [ ] Повтор `POST …/payments` с тем же `Idempotency-Key` → тот же `paymentId`, второго списания и расхода лимита нет.
- [ ] Повтор события (`eventId`) → нет второго зачисления.
- [ ] Гонка «отзыв ∥ списание» → после `REVOKED` нового списания нет; состояние согласовано.
- [ ] Зачисление по мандатному платежу из `CREATED` недостижимо (fitness).
- [ ] Регресс QR-потока и contract-compat test v0.1→v0.2 без breaking changes.
