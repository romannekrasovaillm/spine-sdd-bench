# Оценка значимости и маршрута

## Architecture Significance Score: 11/15 → маршрут **Critical**

Проверено инструментом Spine: `significance_score` (триггеры объявлены) → `{"route":"Critical","score":11}`.

| Триггер | Факт | Обоснование |
|---|---|---|
| `security_boundary_change` | **да (критический)** | Списание без действия плательщика: согласие становится авторизационным артефактом вместо per-transaction подтверждения; новая модель доверия и ответственности |
| `financial_impact` | да | Рекуррентные списания — финансовые операции; ошибка = двойное списание/потеря средств |
| `cross_domain_integration` | да | Новый стык с рекуррентным сервисом СБП; взаимодействие ТСП ↔ шлюз ↔ НСПК ↔ АБС ↔ плательщик |
| `api_contract_change` | да | Новые методы API ТСП и внутреннего контракта адаптера ОПКЦ |
| `data_contract_change` | да | Новый контракт данных согласия/подписки/попытки списания |
| `new_component` | да | Планировщик списаний и реестр согласий/подписок |
| `new_datastore` | да | Хранилище согласий/подписок/попыток (источник истины) |
| `consistency_model_change` | да | Плановые (асинхронные) списания + длительный жизненный цикл согласия |
| `significant_nfr` | да | Новые измеримые NFR: своевременность, отзыв, отсутствие двойных списаний, масштаб |
| `domain_ownership_change` | да | Появляется домен «согласия/подписки» со своим жизненным циклом и владельцем |
| `criticality_or_exception` | да (критический) | Система — платёжный контур в объекте КИИ; распространяется на критичный функционал |

Не сработали: `new_vendor` (вендор транспорта уже выбран по ADR-007, расширяется объём, не поставщик), `irreversible_migration` (изменение обратимо/аддитивно), `trust_zone_change` (зоны доверия не меняются), `rto_rpo_targets` (новых целей сверх существующих нет — наследуются).

## Почему Critical, а не Fast/Standard

Достаточно **одного** критического триггера (`security_boundary_change`, `irreversible_migration`, `criticality_or_exception`) для маршрута Critical; здесь критических два. Рекуррентные списания меняют границу безопасности и затрагивают финансовый контур КИИ — Fast/Standard недопустимы (антипаттерн `significance-routing`: «Fast Path на платежах/КИИ»).

## Что означает маршрут Critical

- **Полное Solutioning** (spine + ADR + NFR), а не только дельта-спека.
- **Обязательная человеческая точка A3** — решение по `DECISION.md`; агент поле `decided_by` не заполняет.
- **Walking skeleton до массовой реализации** — сквозной сценарий подписки на моках (`WALKING-SKELETON.md`).
- **Evidence-гейты** — бандл из 13 артефактов; `arch-be gate --route critical`; рубрики/состязательное ревью.
- **Состязательное ревью** (`docs/REVIEW.md`) и репетиция отката на A4.

## Ключевые риски

| Риск | Влияние | Митигация |
|---|---|---|
| Двойное списание за период (ошибка планировщика/ретрая) | Финансовый инцидент, регуляторный риск | Ключ `(subscriptionId, billingPeriod)` (AD-010), идемпотентность на адаптере и АБС, тесты повторов |
| Списание после отзыва согласия | Нарушение прав плательщика, репутация | Транзакционный запрет + событие + аудит (AD-009), сверка/опрос статуса, тест отзыва |
| Неполнота протокола НСПК по подпискам (внешний вход) | Переработка контракта/сроков | Контрактная изоляция адаптера (AD-008), `[ТРЕБУЕТ ПРОВЕРКИ]`, обновление ADR по факту |
| Вендор не поддерживает подписки | Срыв сроков | Расширение RFP (G3, P9–P11), POC, заменимость адаптера |
| Новая граница безопасности не согласована ИБ/юристами | Блокировка релиза | Раннее согласование (A3), ПДн-минимизация, аудит |
| Пиковые массовые списания деградируют разовый приём | SLO-инцидент | Управление темпом и приоритеты, нагрузочные тесты (NFR §7) |
| Рост ПДн (данные согласия) | 152-ФЗ | Минимизация, шифрование, сроки хранения, правовое основание |

## Обратимость

Изменение **reversible**: аддитивно, включается фиче-флагом, one-off C2B не затрагивается. Триггеры пересмотра и expiry — в ADR-008/009/010.
