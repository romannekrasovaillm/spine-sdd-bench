# План отката — Подписки СБП

Откат согласован с обратимостью решений (ADR-008/009/010: **reversible**, аддитивное изменение) и с планом отката принятого решения (`docs/solutioning.md` §8). Репетиция отката (`rollback_rehearsal`) проводится на A4 и обязана быть PASS на том же baseline.

## Принцип

Изменение **аддитивно и выключаемо фиче-флагом**. Откат не требует обратной миграции данных: согласия/подписки остаются как аудиторский след (152-ФЗ/сроки хранения), а не «удаляются». Разовый C2B-приём и уже подтверждённые операции не затрагиваются ни на одном шаге отката.

## Уровни отката

| Уровень | Действие | Что останавливает | Что продолжает работать |
|---|---|---|---|
| **R0. До включения** | Не включать фиче-флаг подписок | Всё новое | Весь разовый приём |
| **R1. Stop-new** | Фиче-флаг `subscriptions.stop_new = on`: запрет новых подписок и новых плановых списаний | Создание подписок, планирование новых списаний | Существующие подписки видны; подтверждённые списания завершаются; разовый приём |
| **R2. Отзыв-режим** | `subscriptions.revocation_only = on`: новые списания запрещены, обработка отзывов и завершение начатых — продолжаются | Любые новые списания | Отзывы, сверка, возвраты, разовый приём |
| **R3. Откат релиза** | Rolling-откат приложения на предыдущую версию (схема данных совместима — аддитивные таблицы) | Новый код подписок | Старый код разового приёма; данные согласий сохраняются |
| **R4. Аварийный** | DLQ → дежурная смена по runbook; сверка восстанавливает расхождения | Инцидент | RTO ≤ 1 ч |

## Триггеры (сигналы) отката

- Любой инцидент **двойного списания** за один период, не устранимый идемпотентностью.
- Любое **списание после отзыва** согласия (AC-9/AC-17 нарушен).
- Рост DLQ/расхождений сверки рекуррентных операций выше порога (NFR §7).
- Деградация разового приёма ниже SLO из-за нагрузки планировщика.
- Недоступность/некорректность вендорского транспорта по подпискам без обходного пути.
- Требование регулятора/ИБ приостановить рекуррентные списания.

## Владелец решения об откате

- **Технический откат (R1–R3)** — дежурный SRE/платёжный мониторинг по runbook (немедленно), с уведомлением владельца продукта и архитектора.
- **Продуктовый/полный откат (R0/R4, отключение функциональности)** — владелец продукта «Эквайринг» + архитектор; при регуляторном требовании — ИБ/комплаенс.

## Шаги отката (R1, типовой)

1. Установить `subscriptions.stop_new = on` (без перезапуска, hot-flag).
2. Убедиться: новые подписки/плановые списания не создаются (метрика = 0).
3. Дать завершиться начатым операциям; проследить отчёт незавершённых.
4. Провести сверку план ↔ НСПК ↔ АБС; расхождения — по runbook.
5. При необходимости — R3 (rolling-откат релиза), схема данных совместима.
6. Постмортем; обновить ADR/дельту по причине отката.

## Критерий успешного отката

Новые списания за период **не создаются**, подтверждённые операции целостны (сверка — 0 расхождений), разовый приём работает в штатном режиме, данные согласий сохранены и аудируемы. Проверяется в репетиции отката на A4.

## Что откат НЕ делает

- Не удаляет данные согласий (аудиторский след/152-ФЗ).
- Не откатывает уже подтверждённые списания автоматически (только возврат — сага ADR-005).
- Не меняет принятые ADR-001…007 и существующие контракты разового приёма.
