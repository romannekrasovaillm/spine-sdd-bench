# Handoff-пакет «Подписки СБП» (sbp-recurring-c2b)

Статус: **provisional (до A3)**. Пакет сгенерирован командой

```bash
arch-be handoff --repo . --route critical \
  --spec ARCHITECTURE-SPINE.md --spec docs/solutioning-subscriptions.md \
  qwen-code
```

в изолированной копии репозитория, чтобы не затирать принятый baseline-пакет `.arch-handoff/` (задача walking skeleton). Содержимое:

- `TASK.md` — задача исполнителю + headless-контракт результата + план отката.
- `ARCHITECTURE.md` — epic-context (≈1824 токена; инварианты AD-001…AD-011 дословно + решение).
- `SPEC.md` — компиляция spine/solutioning; **требует авторской правки**.
- `ROLLBACK.yaml` — git-якорь (репетируемо) + операционный откат фичи (вручную).
- `MANIFEST.json` — мета (маршрут Critical, timeout 7200 с, baseline `a5df5aa`).
- `adr/` — копии ADR-001…ADR-011 (ADR-008…011 — Proposed). Новые ADR-008…011 добавлены в пакет вручную: генератор скопировал только принятый набор ADR-001…007 из baseline-пакета.

## Важно перед передачей

1. **A3.** Инварианты AD-009…011 и ADR-008…011 в статусе `Proposed` — до ратификации A3 пакет **не выдавать** в реализацию: handoff обязан нести Accepted-инварианты (иначе исполнитель действует по нератифицированным решениям).
2. **Перегенерировать после A3** (baseline и статусы ADR обновятся). При повторной генерации пользовательский `CONSTRAINTS.yaml` не затирается (флаг `--refresh-constraints` нужен только для явной перезаписи).
3. **Epic-context ≈1824 токена > бюджета 800–1500** (рубрика `handoff_quality`): при перегенерации сократить `--spec` (детали и так доступны в репозитории).
4. **Открытые вопросы состязательного ревью** (`docs/REVIEW.md` в каталоге изменения) — часть из них (источник `payerRef`, семантика отзыва для дебета «в полёте») должны быть закрыты до старта реализации.
