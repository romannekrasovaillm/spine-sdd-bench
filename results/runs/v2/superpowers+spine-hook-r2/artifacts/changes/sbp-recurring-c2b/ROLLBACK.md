# План отката — sbp-recurring-c2b

## До боевой эксплуатации

Откат = не включать функционал; все работы обратимы (ADR-008…011 на старте reversible/costly). Технический откат — `git reset --hard a5df5aa` (работа исполнителя приходит одним коммитом поверх).

## После боевого включения (операционный откат)

1. **Запрет регистрации новых согласий** (фиче-флаг stop-new).
2. **Сохранение отзыва и действующих обязательств:** запросы на отзыв согласий и исполнение уже действующих обязательств НЕ отключаются (потребительское право и финансовые обязательства сохраняются).
3. **Синхронная сверка согласий с НСПК** — до любого решения о заморозке исполнения.
4. **Заморозка плановых списаний по каждому согласию** — только после сверки; каждое согласие либо исполняется по runbook, либо приостановлено с уведомлением ТСП.
5. Уведомление ТСП и дежурной смены; обновление отчёта незавершённых операций.

## Сигналы отката (триггеры)

- >0 списаний после подтверждённого отзыва;
- >0 дублей списаний за период (`consentId+periodNumber`);
- расхождения согласий при сверке с НСПК;
- недоступность контура согласий;
- каскадные ошибки протокола НСПК.

## Владельцы и данные

- **Владелец решения об откате:** solution-архитектор совместно с бизнесом (остановка биллинга затрагивает выручку ТСП и обязательства) — закрепляется на A3.
- **Исполнитель** откат не выполняет и не маскирует проблему обходным редизайном.
- **Данные:** согласия не мигрируются обратно; шлюз остаётся источником истины по согласиям до полной сверки с НСПК.

## Репетиция

Репетиция отката — гейт A4 (`.arch-handoff/REHEARSAL.json`), **после** A3 и появления кода. Для handoff-пакета см. `handoff/ROLLBACK.yaml` (git-якорь репетируем; операционные шаги — вручную).
