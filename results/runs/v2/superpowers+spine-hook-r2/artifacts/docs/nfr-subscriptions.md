# NFR — подписки СБП (рекуррентные C2B-списания по согласию плательщика)

- Status: Draft (для ревью на гейте A1; дополняет `docs/nfr.md`, не заменяет его)
- Owner: solution-architect (платёжный контур) + владелец АБС
- Связано: ADR-008, ADR-009, ADR-010, ADR-011, AD-009, AD-010, AD-011

Целевые значения — **измеримые критерии приёмки** на гейтах A4/A5. Baseline; финальные согласуются с бизнесом, НСПК и владельцем АБС (регламенты оператора могут быть строже). Нормируются приросты к базовым NFR (`docs/nfr.md`), а не их замена.

## 1. Доступность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доступность контура согласий и планировщика (месяц) | ≥ 99,95 % | Uptime-мониторинг, синтетика на путь согласия |
| Доступность эндпоинтов согласий API ТСП | ≥ 99,95 % (≤ 22 мин/мес) | SLO-отчёт |
| Недоступность базового приёма платежей из-за подписок | 0 (подписки не деградируют разовый приём) | Chaos/нагрузочный тест, bulkhead-проверка |

## 2. Производительность и расписание

| Метрика | Цель | Метод проверки |
|---|---|---|
| Latency `POST /v1/consents` (приём заявки) | p95 < 500 мс, p99 < 1 с (без учёта НСПК) | Нагрузочный тест, APM |
| Latency `GET /v1/consents/{id}` | p95 < 300 мс | Нагрузочный тест |
| Подтверждение согласия от НСПК | p95 < 5 с (регламент уточняется `[ТРЕБУЕТ ПРОВЕРКИ]`) | Метрика процесса |
| Точность расписания: доля дебетов, инициированных в допуске окна | ≥ 99,9 % | Метрика планировщика (наблюдаемое время инициации против плана) |
| Дебет→CREDITED (как базовое зачисление) | p95 < 60 с (SLA с АБС) | Метрика процесса |
| Пропускная способность контура согласий | ≥ 20 TPS sustained (регистрация/статус/отзыв) | Нагрузочный тест |
| Пик на границе периода (1-е число, зарплатные дни) | ≥ 300 TPS в течение 2 ч без деградации базового приёма; распределение джиттером | Нагрузочный тест «границы периода» |
| Масштабируемость планировщика | ×2 по числу активных согласий без изменения архитектуры | Load-test на удвоенном реестре |

## 3. Надёжность, согласованность и восстановление

| Метрика | Цель | Метод проверки |
|---|---|---|
| RPO реестра согласий (включая отзывы) | 0 (ни один отзыв/изменение не теряется) | Тест отключения ноды + сверка |
| RTO контура согласий | ≤ 1 час | Chaos-тест, DR-учения |
| Списаний после подтверждённого отзыва | 0 | Тест `consent_before_auto_action` + сверка с НСПК |
| Двойных списаний за период (`consentId + periodNumber`) | 0 | Тест `debit_period_idempotency` + сверка |
| Сверка согласий с НСПК | ежечасная; расхождений по активным согласиям — 0 | Reconciliation-отчёт |
| Отработка расхождений согласий | 100 % по runbook за ≤ 4 часа | KPI дежурной смены |

## 4. Безопасность, аудит и соответствие

| Метрика | Цель | Метод проверки |
|---|---|---|
| Изменения согласия и попытки дебета в аудит-логе | 100 %, лог неизменяем | Аудит, SIEM |
| ПДн плательщика в согласии | минимизированы, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Ручные операции с согласиями | 4-eyes (два согласования) | RBAC-проверка |
| Передача в AML/антифрод по порогам подписок | 100 % | Тест-кейсы |
| Хранение доказательств согласия/отзыва | по требованию ЦБ/НСПК `[ТРЕБУЕТ ПРОВЕРКИ]` | ИБ/комплаенс-ревью |

## 5. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace id на операции согласия и дебета | 100 % | APM |
| Алерт на расхождение согласий с НСПК | за ≤ 5 мин | Мониторинг |
| Алерт на пропущенный период / `UNKNOWN` дебета | за ≤ 5 мин | Мониторинг |
| Отчёт активных согласий и незавершённых дебетов | доступен всегда, актуален | Проверка |

## Зависимости (внешние входы для NFR)

- Регламенты НСПК по подпискам: тайминги подтверждения/отзыва, уведомления плательщика `[ТРЕБУЕТ ПРОВЕРКИ]`.
- SLA АБС на массовые списания на границе периода (согласуется с владельцем АБС).
- Требования ЦБ/152-ФЗ к хранению доказательств согласия (уточнить у ИБ) `[ТРЕБУЕТ ПРОВЕРКИ]`.
