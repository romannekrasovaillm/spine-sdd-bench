# Tasks

> Реализация — после A3 (человеческое решение по ADR-008/ADR-009) и получения документации НСПК по подпискам. Приоритет — доказать архитектуру сквозным сценарием на моках, а не полнотой продукта.

## 1. Согласие: агрегат, реестр, API

- [ ] 1.1 Реализовать агрегат «согласие» (`PENDING/ACTIVE/SUSPENDED/REVOKED/EXPIRED/REJECTED`) с таблицей `consents` и уникальными ключами; проверить юнит-тестами допустимые и запрещённые переходы
- [ ] 1.2 Реализовать переходы согласия как атомарную транзакцию «статус + outbox + аудит» (AD-002); проверить тестом, что при откате транзакции нет ни смены статуса, ни события outbox
- [ ] 1.3 Реализовать `POST /v1/subscriptions` с обязательным `Idempotency-Key`; проверить тестом: повтор с тем же ключом и телом → тот же `subscriptionId`, без дубля
- [ ] 1.4 Реализовать `GET /v1/subscriptions/{subscriptionId}` и `POST /v1/subscriptions/{subscriptionId}/cancel`; проверить контрактным тестом ответов (статусы, поля)
- [ ] 1.5 Валидировать параметры согласия (лимит > 0, период, срок действия) и проверять аддитивность — проверить негативными юнит-тестами (`INVALID_REQUEST`)
