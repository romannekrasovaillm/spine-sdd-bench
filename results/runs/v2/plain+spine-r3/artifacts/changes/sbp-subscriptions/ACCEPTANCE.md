# Критерии приёмки и план отката: СБП-подписки

Дельта к плану гейтов A4/A5 (`docs/solutioning.md` §7–8). Критерии — в нотации EARS, каждый проверяем тестом/командой. Негативные сценарии обязательны: дубль, гонка, отказ соседа, рестарт.

## 1. Критерии приёмки (EARS)

### Мандат (согласие)

- When ТСП регистрирует согласие с валидным `Idempotency-Key`, the шлюз shall создать мандат `PENDING_OPKC` и зарегистрировать его в ОПКЦ только через адаптер ОПКЦ (проверка: нет исходящих вызовов к ОПКЦ вне адаптера).
- When приходит повторный запрос регистрации с тем же `Idempotency-Key`, the шлюз shall вернуть тот же `mandateId` без второго мандата в ОПКЦ.
- When ОПКЦ подтверждает регистрацию, the шлюз shall перевести мандат в `ACTIVE` атомарно (статус + outbox + аудит) — проверка: тест на разрыв транзакции не оставляет «полу-статуса».
- If ОПКЦ отклоняет регистрацию, then the шлюз shall перевести мандат в `REJECTED` с `reasonCode` и не допускать списаний.

### Рекуррентное списание

- When ТСП инициирует списание по `ACTIVE`-мандату в пределах границ, the шлюз shall принять поручение (p95 < 500 мс) и провести платёж по существующей машине `CREATED → PAID → CREDITED → COMPLETED`.
- While мандат `ACTIVE` и лимит слота доступен, the шлюз shall допускать ровно одно списание на слот `mandateId + periodKey`.
- When приходит повторная инициация того же слота, the шлюз shall вернуть существующий `debitId` и не создать второе списание.
- When приходит повторная нотификация `debit.paid` с уже обработанным `eventId`, the шлюз shall проигнорировать её (состояние не меняется).
- If сумма списания превышает потолок мандата, then the шлюз shall отклонить списание (`MANDATE_LIMIT_EXCEEDED`), не менять финансовое состояние и поднять алерт.
- If мандат отозван или истёк, then the шлюз shall отклонить списание (`MANDATE_NOT_ACTIVE`) и не обращаться к АБС.
- Where рекуррентный поток, the шлюз shall не создавать QR и не использовать состояние `QR_ISSUED`.

### Отзыв согласия

- When получен отзыв (от ОПКЦ/банка плательщика или от ТСП), the шлюз shall перевести мандат в `REVOKED` и прекратить новые списания ≤ 5 мин (NFR-SUB-9).
- When списание было в полёте в момент отзыва и подтвердилось после, the шлюз shall инициировать возврат (NFR-SUB-10) — критерий успеха: платёж в `REFUNDED`, деньги возвращены плательщику.
- When сверка обнаруживает расхождение статуса мандата с ОПКЦ, the шлюз shall заблокировать списания по спорному мандату до разрешения.

### Прослеживаемость и уведомление

- Where рекуррентный поток, the шлюз shall хранить цепочку «списание → мандат → платёж → проводка АБС → событие НСПК» (проверка: аудит-запрос восстанавливает цепочку по `debitId`).
- When списание исполнено, the шлюз shall зафиксировать уведомление плательщика (100 %, NFR-SUB-12).

## 2. Негативные сценарии (обязательные тесты)

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| N1 | Дубль: повторная инициация того же слота | одно списание, тот же `debitId` |
| N2 | Дубль: повторная доставка `debit.paid` (тот же `eventId`) | состояние не меняется, дубля проводки нет |
| N3 | Гонка: отзыв мандата во время in-flight списания | новые списания стоп; подтверждённое после отзыва — возврат |
| N4 | Границы: списание сверх потолка за списание и сверх числа за период | отказ + алерт, состояние не меняется |
| N5 | Отказ соседа: АБС недоступна после `PAID` | платёж остаётся `PAID`, виден в сверке, двойной проводки нет |
| N6 | Отказ соседа: ОПКЦ недоступен на инициации | поручение ретраится/в DLQ, дедупликация по ключу слота, потерянных слотов нет |
| N7 | Рестарт шлюза в середине слота | после подъёма слот доводится, второго списания нет |
| N8 | Поздняя нотификация по закрытому слоту | состояние не меняется, инцидент в сверке |
| N9 | Некорректный/чужой `mandateId` (мандат другого ТСП) | отказ (`MANDATE_NOT_ACTIVE`/`INVALID_REQUEST`) |

## 3. План отката

### До боевого включения

- Откат = **не включать**: фиче-флаг `subscriptions_enabled` (глобально и per-ТСП) выключен по умолчанию. Все артефакты дельты обратимы; боевых данных нет.

### После включения

- **Мягкий откат (штатный).** `stop-new` для выбранных ТСП/мандатов: запрет новых списаний и регистраций мандатов **без** остановки обработки уже открытых слотов и без отзыва действующих согласий. Деньги уже списанные не мигрируют обратно — только штатный возврат.
- **Откат релиза.** Rolling-откат версии; данные мандатов/слотов остаются в БД шлюза (шлюз — источник истины по своим операциям) до полной сверки. Обратной миграции данных нет.
- **Аварийный сценарий.** DLQ по слотам → дежурная смена по runbook; сверка компенсирует потерянные нотификации; RTO ≤ 1 ч (NFR-SUB-19).

### Сигналы-триггеры отката (автоматические пороги)

| Сигнал | Порог | Действие |
|---|---|---|
| Двойное списание по слоту | > 0 | **Немедленный `stop-new`** + инцидент высшей категории |
| Списание сверх границ мандата | > 0 | `stop-new` по затронутому ТСП + разбор |
| Доля отказов списаний | > 5 % за 15 мин | `stop-new` + инцидент |
| Лаг распространения отзыва | > 5 мин (p99) | Алерт + `stop-new` при повторении |
| Расхождение сверки мандатов | > 0 по завершённым операциям | Разбор до снятия `stop-new` |

### Владелец решения

- **`stop-new` штатно** — дежурная смена платёжного мониторинга по runbook (предустановленное право, без ожидания комитета).
- **Полное выключение фичи / откат релиза** — владелец платёжного контура (человек-архитектор) совместно с SRE-руководителем; фиксация в аудит-логе.
- **Отзыв действующих мандатов** (крайняя мера) — только владелец продукта подписок + комплаенс.

### Критерий успешного отката

Фича выключена; новых списаний нет; все открытые слоты доведены или явно закрыты с записью в сверке; расхождений с ОПКЦ и АБС — 0; инцидент закрыт с RCA.

## 4. Контракт результата для исполнителя (headless)

Прогон реализации подписок обязан завершаться JSON (после него — ни символа):

```json
{"status": "complete|partial|blocked",
 "assumptions": [],
 "open_questions": [],
 "conflicts_with_prior_decisions": []}
```

- `conflicts_with_prior_decisions` — расхождение с AD-001…AD-012 или ADR-001…ADR-010; обязано **останавливать** работу и эскалироваться архитектору, а не решаться молча.
- `status: blocked` — перечислить недостающие входы (например, протокол НСПК по рекуррентным списаниям).
