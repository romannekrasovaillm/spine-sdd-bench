# NFR: рекуррентные C2B-списания по согласию плательщика (подписки СБП)

Дельта к `docs/nfr.md`. Каждая цель — метрика + число + метод проверки + следствие нарушения. Значения — baseline; финальные согласуются с бизнесом, НСПК и ИБ; регламенты оператора могут быть строже (`[ТРЕБУЕТ ПРОВЕРКИ]`).

## 1. Инициация и жизненный цикл

| ID | Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|---|
| NFR-SUB-1 | Latency регистрации мандата (API ТСП → принятие в шлюз, без времени ОПКЦ) | p95 < 1 с, p99 < 2 с | Нагрузочный тест, APM | Медленный онбординг подписки, раздражение ТСП |
| NFR-SUB-2 | Latency инициации списания (API ТСП → принятие поручения) | p95 < 500 мс, p99 < 1 с | Нагрузочный тест, APM | Массовые таймауты ТСП в окно списаний |
| NFR-SUB-3 | Подтверждение списания ОПКЦ → зачисление в АБС | p95 < 60 с | Метрика процесса, сверка | Задержка денег ТСП, эскалации |
| NFR-SUB-4 | Полный цикл слота (инициация → вебхук ТСП) | p95 < 90 с | Сквозная метрика | ТСП не видит результат, повторные инициации |

## 2. Корректность и идемпотентность

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-5 | Двойные списания по одному слоту (`mandateId + periodKey`) | 0 | Тест повторной инициации и повторной доставки `debit.paid` |
| NFR-SUB-6 | Списания сверх границ мандата | 0 | Тест на потолок суммы и число списаний за период |
| NFR-SUB-7 | Списания по отозванному/истёкшему мандату | 0 | Тест «отзыв → инициация», тест TTL мандата |
| NFR-SUB-8 | Потеря связи «списание ↔ мандат ↔ платёж» | 0 | Аудит-проверка целостности ссылок, сверка |

## 3. Отзыв согласия

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-9 | Распространение отзыва от НСПК/банка плательщика до блокировки новых списаний | ≤ 5 мин (p99) | Chaos-тест «отзыв под нагрузкой», метрика лага |
| NFR-SUB-10 | Списание, подтверждённое после фиксации отзыва → возврат | 100 % за ≤ 4 ч | Тест гонки «отзыв vs in-flight списание» |
| NFR-SUB-11 | Расхождение статуса мандата с ОПКЦ | 0 по завершённым сверкам | Reconciliation-отчёт |

## 4. Уведомление плательщика

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-12 | Доля исполненных списаний с уведомлением плательщика | 100 % | Аудит журнала уведомлений |
| NFR-SUB-13 | Лаг уведомления плательщика от подтверждения списания | p95 < 5 мин | Метрика лага |

## 5. Нагрузка (профиль подписок)

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-14 | Sustained throughput поручений | ≥ 200 TPS | Нагрузочный тест |
| NFR-SUB-15 | Пик массовых окон (1-е число, зарплатные дни) | burst 1000 TPS на 1 мин, 500 TPS sustained | Нагрузочный тест на профиле «первое число» |
| NFR-SUB-16 | Масштабируемость контура мандатов/слотов | ×2 без перепроектирования | Load-test на 400 TPS |

## 6. Доступность, восстановление, сверка

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-17 | Доступность API мандатов и поручений (месяц) | ≥ 99,95 % | SLO-мониторинг |
| NFR-SUB-18 | RPO по мандатам и слотам | 0 | Тест отключения ноды, сверка |
| NFR-SUB-19 | RTO восстановления инициации | ≤ 1 ч | Chaos-тест, DR-учения |
| NFR-SUB-20 | Сверка мандатов с ОПКЦ | ежечасная; расхождений — 0 | Reconciliation-отчёт |
| NFR-SUB-21 | «Ожидаемый слот не инициирован» (ТСП не вызвал) | алерт ≤ 15 мин | Мониторинг ожидаемых слотов |

## 7. Наблюдаемость

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-22 | Trace id на рекуррентную операцию | 100 % | APM |
| NFR-SUB-23 | Алерт на аномалию отказов списаний | всплеск отказов → алерт ≤ 5 мин | Мониторинг |
| NFR-SUB-24 | Отчёт незавершённых слотов и мандатов | всегда доступен и актуален | Проверка отчёта |

## 8. Безопасность и ПДн (дельта)

| ID | Метрика | Цель | Метод проверки |
|---|---|---|---|
| NFR-SUB-25 | Хранение идентификаторов плательщика | шифрование в покое, маскирование в логах | ИБ-ревью, сканы |
| NFR-SUB-26 | Правовое основание повторного списания | 100 % списаний имеют действующий мандат | Аудит, fitness-правило |
| NFR-SUB-27 | Доступ к ручным операциям по мандатам | 4-eyes | RBAC-проверка |

## Зависимости (внешние входы)

- Регламент НСПК по рекуррентным списаниям: допустимые лимиты, TTL согласия, формат уведомления плательщика, тайминги — `[ТРЕБУЕТ ПРОВЕРКИ]` из документации НСПК.
- Требования ЦБ/161-ФЗ к уведомлению и согласию — уточнить у ИБ/комплаенса.
- Возможности вендорского транспорта по мандатам и списаниям — из RFP (`docs/rfp/vendor-rfp.md`).
