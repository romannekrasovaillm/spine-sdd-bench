# Статусная машина мандата и семантика слота списания — спецификация

- Status: Draft (дельта к `docs/spec/state-machine.md`; для A1)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, ADR-009, ADR-010, AD-009, AD-010, AD-011, AD-012

Дополняет автомат платежа (`docs/spec/state-machine.md`), не переписывая его. Единый источник истины мандата — БД шлюза (проекция; авторитетный статус согласия — ОПКЦ, ADR-008). Каждый переход мандата — **атомарная транзакция** «статус + outbox + аудит» (дисциплина AD-002).

## 1. Состояния мандата

| Состояние | Смысл | Терминальное |
|---|---|---|
| `DRAFT` | Согласие создано в шлюзе, регистрация в ОПКЦ не начата | нет |
| `PENDING_OPKC` | Регистрация отправлена, ждём подтверждения ОПКЦ | нет |
| `ACTIVE` | Согласие действует; списания разрешены в пределах границ | нет |
| `SUSPENDED` | Временно приостановлено (технический стоп, спор по сверке) | нет |
| `REVOKED` | Отозвано плательщиком/ТСП/ОПКЦ | да |
| `EXPIRED` | Истёк срок действия согласия | да |
| `REJECTED` | ОПКЦ отклонил регистрацию | да |

```
DRAFT ──► PENDING_OPKC ──► ACTIVE ──► REVOKED
                │            │  └──► EXPIRED
                │            └─────► SUSPENDED ──► ACTIVE / REVOKED
                └──► REJECTED
```

## 2. Таблица переходов мандата

| № | From | To | Триггер | Guard | Действие |
|---|---|---|---|---|---|
| M1 | — | `DRAFT` | `POST /v1/mandates` (Idempotency-Key) | ТСП активен, плательщик указан | запись мандата, outbox «регистрация в ОПКЦ» |
| M2 | `DRAFT` | `PENDING_OPKC` | отправка `registerMandate` в адаптер ОПКЦ | — | outbox-событие к адаптеру |
| M3 | `PENDING_OPKC` | `ACTIVE` | событие ОПКЦ `mandate.activated` / подтверждение сверкой | мандат подтверждён | outbox, аудит; списания разрешены |
| M4 | `PENDING_OPKC` | `REJECTED` | событие `mandate.rejected` | reasonCode получен | outbox, уведомление ТСП |
| M5 | `ACTIVE` | `REVOKED` | отзыв (ОПКЦ/банк плательщика или ТСП) | — | стоп новых списаний, обработка in-flight (ADR-010), outbox |
| M6 | `ACTIVE` | `EXPIRED` | таймер срока действия | срок истёк | стоп новых списаний, outbox |
| M7 | `ACTIVE` | `SUSPENDED` | расхождение сверки с ОПКЦ | спор не разрешён | стоп новых списаний по мандату, алерт |
| M8 | `SUSPENDED` | `ACTIVE` | сверка подтвердила действующий статус | расхождение снято | возобновление списаний |
| M9 | `SUSPENDED` | `REVOKED` | сверка подтвердила отзыв | — | как M5 |
| M10 | `ACTIVE` | (без смены) | повторный `mandate.activated` | — | игнор (идемпотентность по `eventId`) |

## 3. Слот списания (ключевое для идемпотентности)

**Слот** — это разрешённое мандатом единичное списание на расчётный период. Идентификатор слота — `periodKey` (например, `2026-10`), формируемый ТСП по согласованному правилу формата.

- Ключ идемпотентности списания = **`mandateId + periodKey`** (AD-011).
- Повторная инициация/ретрай того же слота возвращает существующий `debitId` и **не создаёт второе списание**.
- Один и тот же `periodKey` в рамках одного мандата соответствует ровно одному списанию (успешному или закрытому как неуспешное).
- Формат `periodKey` валидируется; несовпадение с согласованным правилом → `INVALID_REQUEST`.

## 4. Связь с автоматом платежа

Рекуррентное списание материализуется в **существующий** автомат платежа; отдельного автомата денег не вводится.

| Шаг рекуррентного потока | Состояние платежа |
|---|---|
| Поручение принято, отправлено в ОПКЦ | `CREATED` |
| ОПКЦ подтвердил списание | `PAID` (через `debit.paid`/сверку) |
| АБС подтвердила зачисление | `CREDITED` |
| Вебхук ТСП поставлен/доставлен | `COMPLETED` |

Состояние `QR_ISSUED` в рекуррентном потоке **не используется**. Ветка отказа (`FAILED`) и сага возврата (`REFUNDED`) — переиспользуются без изменений.

## 5. Инварианты мандата и списания

- **Действующий мандат — предусловие списания** (AD-009): списание возможно только при `mandateId` в статусе `ACTIVE`. Из `REVOKED`/`EXPIRED`/`REJECTED`/`SUSPENDED` — недостижимо.
- **Границы мандата** (AD-010): сумма каждого списания ≤ потолка; число/сумма за период ≤ лимита. Выход за границы → отказ (`MANDATE_LIMIT_EXCEEDED`) + алерт; финансовое состояние не меняется.
- **Идемпотентность слота** (AD-011): `mandateId + periodKey` не допускает второго списания.
- **Отзыв останавливает будущие списания** (AD-012): после `REVOKED` новые списания невозможны; подтверждённое после отзыва — возвращается (ADR-010).
- Мандат не удаляется: смена статуса без физического удаления (аудит, AD-007).

## 6. Обработка повторных триггеров

| Триггер | Ключ | Поведение при повторе |
|---|---|---|
| `POST /v1/mandates` | `Idempotency-Key` | возврат того же `mandateId` |
| `POST /v1/mandates/{id}/debits` | `mandateId + periodKey` | возврат того же `debitId`, второго списания нет |
| Событие ОПКЦ `mandate.activated` / `debit.paid` | `eventId` | повтор игнорируется, состояние не меняется |
| Отзыв | `mandateId` | повтор отзыва идемпотентен |

## 7. Сверка

- Мандаты в `ACTIVE`/`SUSPENDED` — кандидаты ежечасной сверки с ОПКЦ (NFR-SUB-20).
- «У ОПКЦ отозван — у нас активен» → `SUSPENDED` + эскалация (M7); новые списания блокируются до разрешения.
- «У ОПКЦ активен — у нас `REVOKED`» → эскалация, авто-возобновление не выполняется без решения.
