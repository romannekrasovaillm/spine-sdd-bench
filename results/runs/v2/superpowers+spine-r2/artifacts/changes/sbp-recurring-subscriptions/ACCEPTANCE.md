# Критерии приёмки — Подписки СБП (рекуррентные C2B-списания)

Критерии в нотации EARS; каждый проверяем тестом/командой на стенде (walking skeleton: ТСП → шлюз → мок ОПКЦ → мок АБС → нотификация). Гейт A4: позитивные + негативные сценарии + репетиция отката.

## 1. Функциональные критерии (EARS)

- **AC-1** When ТСП запрашивает рекуррентное списание по согласию в статусе `ACTIVE` и в пределах лимитов, the СБП-шлюз shall создать платёж типа `recurring` и инициировать списание через адаптер ОПКЦ.
- **AC-2** If согласие находится в статусе `REVOKED`, `EXPIRED` или `SUSPENDED`, then the СБП-шлюз shall отклонить списание кодом `CONSENT_REVOKED` / `CONSENT_EXPIRED` / `CONSENT_SUSPENDED`, не создавая проводку.
- **AC-3** If сумма или число списаний за период превышают лимиты согласия, then the СБП-шлюз shall отклонить списание кодом `CONSENT_LIMIT_EXCEEDED`.
- **AC-4** When приходит повторный запрос с той же парой `(consentId, billingPeriod)`, the СБП-шлюз shall вернуть существующий `paymentId` без второго списания.
- **AC-5** When ОПКЦ подтверждает списание (`PAID`), the СБП-шлюз shall зачислить средства на счёт ТСП только из состояния `PAID` (AD-005).
- **AC-6** When плательщик отзывает согласие, the СБП-шлюз shall в течение p99 ≤ 60 с перевести согласие в `REVOKED` и отклонять новые списания (fail-closed).
- **AC-7** While согласие в статусе `ACTIVE`, the СБП-шлюз shall применять лимиты согласия к каждому списанию.
- **AC-8** Where рекуррентное списание зачислено, the СБП-шлюз shall поддерживать возврат через существующую сагу (ADR-005).
- **AC-9** When канал к ОПКЦ недоступен, the СБП-шлюз shall не создавать проводку, вернуть транзиентную ошибку и не менять статус согласия.
- **AC-10** When запрос списания приходит по согласию, локальная проекция которого старше 300 с, the СБП-шлюз shall выполнить синхронную сверку согласия перед созданием списания.
- **AC-11** When согласие переходит в `ACTIVE` (подтверждение плательщика), the СБП-шлюз shall доставить ТСП вебхук `consent.activated` идемпотентно по `eventId`.

## 2. Негативные сценарии (обязательны)

- **N-1 Дубль периода**: два запроса за один `billingPeriod` → ровно один платёж и одна проводка (тест идемпотентности цикла).
- **N-2 Гонка**: два параллельных списания за один период → один платёж (уникальный индекс `(consentId, billingPeriod)`).
- **N-3 Отзыв во время in-flight**: отзыв приходит, когда списание уже в НСПК → in-flight доводится/компенсируется по утверждённой политике; новые списания отклоняются; аудит полный.
- **N-4 Отказ НСПК по списанию**: платёж → `FAILED`, вебхук `debit.failed`, повтор — только в следующем периоде по решению ТСП.
- **N-5 Недоступность АБС после `PAID`**: платёж остаётся `PAID`, виден в сверке, зачисление не теряется (AD-005/ADR-005).
- **N-6 Транспорт `DOWN`**: `503 TRANSPORT_UNAVAILABLE`, событие `transport.unavailable`, «осиротевших» платежей нет; регистрация возобновляется после восстановления.
- **N-7 Расхождение сверки**: «у НСПК списано, у нас нет» → дозапрос и обработка как нотификация; «у нас есть, у НСПК нет» → стоп-сигнал и эскалация.
- **N-8 Лимит по числу списаний**: превышение `maxDebitsPerPeriod` → отказ `CONSENT_LIMIT_EXCEEDED`, состояние согласия не меняется.
- **N-9 Просроченная проекция**: проекция старше порога → синхронная сверка; при недоступности сверки — отказ (не списывать «вслепую»).

## 3. Инварианты (проверяются fitness на гейте A4)

- Зачисление только из `PAID` (AD-005) — недостижимость зачисления из `CREATED`/`QR_ISSUED` для рекуррентного платежа.
- Атомарность «статус + outbox + аудит» — на каждый переход согласия (AD-002).
- Идемпотентность цикла `(consentId, billingPeriod)` (AD-003/AD-010) — **0** дублей.
- Отзыв fail-closed (AD-010) — **0** списаний после применённого отзыва.

## 5. Критерий отката (успех отката)

Откат считается успешным, если: при выключенном фиче-флаге рекуррентных списаний **ни один** новый рекуррентный запрос не создаёт проводку; ранее начатые операции доводятся или компенсируются; разовые платежи не затронуты; сверка согласий и списаний чиста (расхождений 0); данные согласий сохранены для аудита.
