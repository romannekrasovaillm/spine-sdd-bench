# План отката — Подписки СБП (рекуррентные C2B-списания)

Согласован с оценками обратимости ADR: ADR-008 — `costly` (после появления боевых согласий), ADR-009 и ADR-010 — `reversible`. До боевой эксплуатации откат тривиален (выключение фиче-флага).

## 1. Владелец решения об откате

- Основной: solution-архитектор платёжного контура **+ владелец продукта «Подписки СБП»** (совместно).
- Аварийный (в дежурстве): дежурная смена платёжного мониторинга — немедленное отключение новых списаний (шаг 1), с последующим уведомлением владельцев.

## 2. Сигналы-триггеры (что считается сигналом отката)

- Подтверждено хотя бы одно **двойное списание** на пару `(consentId, billingPeriod)`.
- Систематическое (не разовое) **неприменение отзыва** дольше SLA (p99 > 60 с) или хотя бы одно списание после применённого отзыва.
- Рост **несанкционированных списаний/жалоб плательщиков** выше установленного порога (порог задаёт бизнес/юр).
- Рост расхождений сверки согласий/списаний, не устранимый runbook.
- Инцидент ИБ с ПДн согласий.
- Регуляторное предписание приостановить рекуррентные списания.

## 3. Пошаговый откат

1. **Stop-new-debits** — выключить фиче-флаг `sbp_recurring_debits`. Новые рекуррентные списания отклоняются; разовые платежи и обработка уже начатых операций продолжаются (rolling, без downtime).
2. **Stop-new-consents** — выключить фиче-флаг `sbp_consents`. Регистрация новых согласий запрещена; существующие не трогаются до решения.
3. **Обработка in-flight** — довести или компенсировать начатые списания (по политике ADR-010); DLQ → runbook дежурной смены.
4. **Заморозка/отзыв действующих согласий** — по согласованию с юр/бизнес: массовый отзыв согласий по регламенту НСПК, уведомление ТСП и плательщиков.
5. **Сверка** — полная сверка согласий и рекуррентных списаний с НСПК/АБС; отчёт незавершённых операций; устранение расхождений.
6. **Данные** — обратная миграция НЕ выполняется; данные согласий сохраняются для регуляторного аудита и разбора. Шлюз остаётся источником истины до полной сверки с АБС.

## 4. Восстановление (roll-forward)

Возврат функциональности — только после устранения причины и повторного прохождения затронутых критериев приёмки (AC-4, AC-6, AC-9) и сверки; включение фиче-флага поэтапно по ТСП.

## 5. Репетиция отката (критерий A4)

На стенде, на том же baseline, что пакет: имитировать сигнал → выполнить шаги 1–3 → подтвердить: **0** новых проводок по рекуррентным списаниям; in-flight завершены/компенсированы; разовые платежи не затронуты; сверка чиста. Результат — PASS для `rollback_rehearsal` в Evidence Bundle.

## 6. Обратимость по ADR

| ADR | Обратимость | Комментарий |
|---|---|---|
| ADR-008 (модель согласия) | costly | Дёшево до боевых согласий (флаг); после — управляемое сворачивание с затронутыми правами плательщиков |
| ADR-009 (ТСП-драйвер) | reversible | Контракт согласия стабилен; переход к планировщику позже не откат, а добавление компонента |
| ADR-010 (идемпотентность/отзыв) | reversible | Механика ключей заменяема; право отзыва откату не подлежит |
