# NFR-DELTA — Подписки СБП (рекуррентные C2B-списания)

Дополняет `docs/nfr.md`. Каждая цель измерима и имеет метод проверки; значения — baseline, финализируются с бизнесом и по регламентам НСПК (`[ТРЕБУЕТ ПРОВЕРКИ]`). Унаследованные цели (доступность 99,95 %, RPO=0, RTO ≤ 1 ч, зачисление p95 < 60 с) не дублируются и продолжают действовать.

## 1. Согласия

| Метрика | Цель | Метод проверки |
|---|---|---|
| Приём запроса на согласие (`POST /v1/consents`, без НСПК) | p95 < 500 мс, p99 < 1 с | Нагрузочный тест, APM |
| Активация согласия (от события `consent.granted` до `ACTIVE`) | p95 < 5 с | Метрика процесса |
| Свежесть локальной проекции согласия перед списанием | ≤ 300 с; иначе синхронная сверка | Метрика; тест порога |
| Латентность сверки согласия с ОПКЦ | p95 < 3 с | APM |

## 2. Рекуррентные списания

| Метрика | Цель | Метод проверки |
|---|---|---|
| Приём запроса на списание (`POST /v1/payments`, `type=recurring`) | p95 < 500 мс, p99 < 1 с | Нагрузочный тест |
| Списание → зачисление (сквозной путь) | p95 < 60 с (наследуется) | Метрика процесса |
| Повторные списания на пару `(consentId, billingPeriod)` | **0** | Тест идемпотентности цикла |
| Отклонения по лимитам/согласию | измеряются; алерт на аномальный рост | Мониторинг, отчёт |

## 3. Залповый биллинг (дни массовых списаний)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Sustained (рекуррентный путь) | ≥ 300 TPS | Нагрузочный тест |
| Пик «залпа» (начало месяца) | 1000 TPS на 5 мин без потери принятых операций | Нагрузочный тест; backpressure |
| Поведение при превышении | контролируемые отказы `429`/`503` + `Retry-After`, без частичных проводок | Chaos/нагрузочный тест |
| Влияние на разовые платежи | изоляция: деградация рекуррентного пути не ухудшает разовый p95 сверх нормы | Нагрузочный тест |

## 4. Отзыв согласия (регуляторно значимо)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Распространение отзыва (от события `consent.revoked` до блокировки новых списаний) | p95 ≤ 30 с, p99 ≤ 60 с | Метрика; тест |
| Списаний после применённого отзыва | **0** | Тест fail-closed |
| Потеря события отзыва | 0 (компенсируется сверкой опросом) | Сверка с НСПК |
| RPO согласий и ключей идемпотентности | 0 | Тест отключения ноды; сверка |

## 5. Сверка

| Метрика | Цель | Метод проверки |
|---|---|---|
| Сверка согласий с НСПК | ежечасная; расхождений по действующим согласиям — 0 | Reconciliation-отчёт |
| Сверка рекуррентных списаний | в общей ежечасной/суточной сверке; расхождений — 0 | Reconciliation-отчёт |
| Отработка расхождений | 100 % по runbook за ≤ 4 ч | KPI дежурной смены |

## 6. Безопасность и ПДн

| Метрика | Цель | Метод проверки |
|---|---|---|
| ПДн в согласии | минимизация (токенизированный идентификатор плательщика, без избыточных реквизитов) | ИБ-ревью, тесты |
| Шифрование в покое / маскирование в логах | 100 % | ИБ-аудит |
| Аудит изменения статуса согласия | 100 % переходов, лог неизменяем | Аудит, SIEM |
| Каналы НСПК | 100 % на сертифицированных СКЗИ (без изменений, ADR-003/AD-006) | Конфигурация |

## 7. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace на операцию согласия и списания | 100 % | APM |
| Алерты | лаг применения отзыва, глубина DLQ, дубли-попытки, отказы по лимитам | Мониторинг, пороги |
| Отчёт по действующим/отозванным согласиям | доступен всегда, актуален | Проверка |
