# NFR подписок СБП (предложение к `docs/nfr.md`)

- Status: Proposed (вливается в `docs/nfr.md` при архивации change `sbp-subscriptions`)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, ADR-009, AD-009…AD-011, `docs/nfr.md` (базовые NFR)

Правило: NFR без числа — пожелание. Каждая цель — метрика + значение + метод проверки + следствие нарушения. Значения помечены `[ТРЕБУЕТ ПРОВЕРКИ]` там, где их диктует регламент НСПК/бизнес; базовая доступность и RTO/RPO **не меняются** (`docs/nfr.md` §1, §3).

## 1. Функциональная надёжность рекуррентности

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Двойные списания за период `(subscriptionId, billingPeriod)` | **0** | property-тест на фейке «два тика/ретрай с одним ключом → одно списание»; продовая сверка | Двойное списание средств плательщика — финансовый и регуляторный инцидент |
| Списания после зафиксированного отзыва мандата | **0** | тест «плановое время позже отзыва» + продовая сверка | Списание без действующего согласия — нарушение прав плательщика |
| Пропущенные периоды без следа | **0** (каждый период либо списан, либо терминально закрыт с событием) | отчёт по периодам подписок | Тихая потеря выручки ТСП |
| Зачисление списания вне подтверждённого `PAID` | **0** (инвариант AD-005) | тест недостижимости + ревью переходов | «Платёж из воздуха» |
| Дубли зачисления при повторе подтверждения АБС | **0** | тест повторного подтверждения | Двойная проводка |

## 2. Пунктуальность расписания

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Отклонение фактической инициации списания от планового времени | p95 ≤ 60 с, p99 ≤ 300 с | метрика `scheduler_drift_seconds` (p95/p99), нагрузочный тест | Непредсказуемые даты списаний, претензии плательщиков |
| Доля списаний, инициированных в окне пунктуальности | ≥ 99,9 % | SLO-отчёт по `scheduler_drift_seconds` | Нарушение ожиданий ТСП и плательщика |
| Дрейф расписания после рестарта/дренажа узла | 0 потерянных планов; догон в пределах окна | chaos-тест «рестарт планировщика» | Пропуск периода или двойное списание |

## 3. Обработка отзыва

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Лаг от фиксации отзыва до гарантированной блокировки списаний | ≤ 60 с `[ТРЕБУЕТ ПРОВЕРКИ — регламент НСПК]` | метрика `mandate_revoke_block_lag_seconds`, тест | Списание по отозванному согласию |
| Полнота обработки событий отзыва | 100 % (компенсация сверкой) | сверка согласий, тест «потерянное событие отзыва → сверка блокирует» | Согласие «зависает» активным |
| Расхождения состояния мандата с СБП | 0 по завершённым согласиям | ежечасная сверка согласий | Списание по несуществующему согласию или отказ по действующему |

## 4. Отказы списания и ретраи

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Число попыток списания за период | ≤ N `[ТРЕБУЕТ ПРОВЕРКИ — регламент НСПК]`, задержка с экспонентой и джиттером | конфигурация + тест политики | Шторм на ОПКЦ/АБС, исчерпание лимитов плательщика |
| Доля успешных списаний после ретрая | ≥ X % `[ТРЕБУЕТ ПРОВЕРКИ — бизнес]` | отчёт по периодам | Недополученная выручка ТСП |
| Терминальный отказ периода доставляется ТСП | 100 % за ≤ 5 мин после исчерпания попыток | метрика доставки событий | ТСП не знает об отказе |

## 5. Производительность и нагрузка

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Throughput инициации списаний (ядро) | sustained 200 TPS, пик 500 TPS, burst 1000 TPS на 1 мин (как базовые NFR) | нагрузочный тест на моках ОПКЦ/АБС | Деградация в окнах биллинга |
| Пунктуальность в окне пиковых списаний (начало месяца) | ≥ 99,9 % при burst-профиле | нагрузочный тест «1-е число» | Массовые сдвиги списаний |
| Latency инициации списания (ядро → адаптер), без времени НСПК | p95 < 1 с, p99 < 2 с | APM + нагрузочный тест | Сдвиг окон, рост backlog |
| Деградация базового C2B (разовые платежи) из-за подписок | ≤ 10 % к базовым p95, доступность не ниже 99,95 % | регресс-нагрузочный тест, SLO-отчёт | Ухудшение основного продукта |

## 6. Уведомления плательщика

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Полнота уведомлений о списании | 100 % списаний | метрика + сверка «списания vs уведомления» | Регуляторное нарушение, претензии плательщиков |
| Срок доставки уведомления | в срок регламента НСПК `[ТРЕБУЕТ ПРОВЕРКИ]` | метрика `payer_notify_lag_seconds` + алерт | Регуляторный инцидент |
| Алерт при задержке уведомлений | ≤ 5 мин | мониторинг | Позднее обнаружение инцидента |

## 7. Данные, безопасность, наблюдаемость

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| ПДн плательщика | минимизация, шифрование в покое, маскирование в логах | ИБ-ревью, тесты | Нарушение 152-ФЗ |
| Аудит событий мандата и списания | 100 % событий, лог неизменяем | аудит + SIEM | Неаудируемое списание |
| Сквозной `traceId` на списание и на уведомление | 100 % | APM | Нерасследуемые инциденты |
| Алерт на «отказ периода» и на расхождение согласий | за ≤ 5 мин | мониторинг | Позднее обнаружение |

## Зависимости (внешние входы)

- Регламент НСПК по подпискам: операции, правила ретраев, сроки отзыва и уведомлений `[ТРЕБУЕТ ПРОВЕРКИ — документация Портала поддержки НСПК]`.
- Бизнес-цели по доле успешных списаний и по числу попыток — согласуются с владельцем продукта.
- Канал и объём уведомлений плательщика (наш банк vs банк плательщика) — согласуется с ИБ/комплаенсом.
