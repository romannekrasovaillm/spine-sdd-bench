## Проблема

ТСП (онлайн-кинотеатры, ЖКХ, связь) не могут принимать оплату по подписке: принятое решение C2B требует QR и действия клиента в каждом платеже. Изменение добавляет **подписки СБП** — рекуррентные C2B-списания по согласию плательщика (мандату), зарегистрированному в СБП. Меняется модель авторизации списания (деньги списываются без участия плательщика в момент операции), поэтому изменение идёт маршрутом Critical и требует человеческого решения A3.

## План отката

- **До боевых мандатов** (мандаты не зарегистрированы в СБП, списаний не было): откат = выключить функционал подписок фиче-флагом — планировщик списаний off, новые пути API отвечают «недоступно»; данные мандатов в проде отсутствуют; миграции не откатываются (аддитивные таблицы).
- **После включения**: `stop-new` — планировщик off и запрет регистрации новых мандатов/подписок, при этом открытые операции доводятся до конца; по каждому действующему мандату инициируется отзыв в СБП; ежечасная сверка подтверждает отсутствие «зависших» списаний; возвраты по завершённым — обычным контуром. Средства обратно не мигрируют: шлюз остаётся источником истины до сверки с АБС и СБП.
- **Сигналы-триггеры отката**: (1) ≥ 1 двойное списание за период; (2) ≥ 1 списание с плановым временем позже времени отзыва; (3) расхождение согласий с СБП > 0 в течение часа; (4) задержка уведомления плательщика сверх регламента; (5) деградация базового C2B сверх бюджета (NFR §5).
- **Владелец решения об откате**: дежурный платёжной смены (инициирует) + архитектор изменения (подтверждает) + бизнес-владелец продукта (согласует). Исполняется по runbook.
- **Обратимость**: согласована с ADR-008 (costly после боевых мандатов; до них — тривиально обратимо).
