# Оценка значимости и маршрут изменения

- Status: Proposed
- Owner: solution-architect
- Инструмент: `arch-be control score` (15 триггеров) + `arch-be gate --route auto` (механический floor из git-диффа)

## Заявленная оценка (архитектор)

| Триггер | Сработал | Почему |
|---|---|---|
| `api_contract_change` | да | Новые пути `/v1/consents*`, `/v1/payments/{paymentId}/charges/{chargeId}`, новые схемы и опциональные поля (`openapi/tsp-api.yaml`, `docs/contracts/tsp-api.md`). |
| `data_contract_change` | да | Новая сущность «Согласие» (мандат) с лимитами, сроком, доказательством согласия; новые данные плательщика → расширение периметра ПДн. |
| `consistency_model_change` | да | Вторая статусная машина (согласие) + правило согласованности «согласие ↔ списание»; гонка «отзыв ↔ списание в полёте». |
| `financial_impact` | да | Рекуррентное списание — движение денег **без действия плательщика в момент списания**; ошибка = несанкционированное списание. |
| `significant_nfr` | да | Новые измеримые цели (активация, отзыв, дедуп, выравнивание окна биллинга) — `docs/nfr.md` §7. |
| `security_boundary_change` | нет (сознательно) | Границы доверия и канал к НСПК не меняются (AD-004/AD-006); меняется *модель авторизации* списания (делегирование через согласие), но не security boundary. Отмечено как консервативное решение: не завышать счёт. |
| `new_component` | нет | Согласие — модуль ядра шлюза, не новый деплоймент/канал; отдельный сервис отвергнут (ADR-010, вариант B). |

**Score: 5 → маршрут Critical.** Подтверждено инструментом:

```
arch-be control score --trigger api_contract_change=true --trigger data_contract_change=true \
  --trigger consistency_model_change=true --trigger financial_impact=true --trigger significant_nfr=true
→ Score: 5 (...) → маршрут Critical
```

Critical, потому что: финансовое влияние + модель консистентности (две машины + гонка) + данные плательщика (152-ФЗ) + новый публичный контракт. Процесс: полный Solutioning (spine + ADR + NFR), обязательная человеческая точка A3 (ADR-011), walking skeleton до массовой генерации, evidence-гейты A4.

## Механический floor (anti-bypass, ADR-034)

Гейт `--route auto` вычисляет триггеры из git-диффа (`detect_diff_triggers`) и **только добавляет** к заявленным. Для этого изменения дифф даёт `api_contract_change` (правки `openapi/tsp-api.yaml` и `docs/contracts/**`) — то есть механический floor = 1 (Fast). Это **ниже** истинной значимости: детекторы из диффа не видят `financial_impact`, `consistency_model_change`, `data_contract_change`, `significant_nfr` — они выводимы только из смысла.

**Следствие для процесса:** нельзя полагаться на `--route auto` как на источник маршрута; при подготовке к A3 выносить вердикт по явному `--route critical`. Автоматический floor здесь — нижняя граница, а не оценка.

## Blast radius

| Затронуто | Характер |
|---|---|
| Ядро шлюза | Новый агрегат «Согласие» + ветка списания; существующая статусная машина переиспользуется |
| Контракт API ТСП | Аддитивно (`/v1`), ломающих изменений нет |
| Адаптер ОПКЦ (внутренний контракт) | Новые операции: создание/статус/отзыв мандата, инициация списания, события согласия |
| АБС | Без изменений (списание — обычный платёж, зачисление по `paymentId`) |
| Нотификации ТСП | Новые события `consent.*` |
| Эксплуатация | Сверка согласий, мониторинг `IN_FLIGHT`, DLQ |
| Регуляторика/ИБ | ПДн плательщика, доказательство согласия, аудит |

## Почему не Fast/Standard

- Fast исключён: платежи/КИИ/финансовое влияние — прямой антипаттерн «Fast Path на платежах».
- Standard исключён: 5 триггеров и модель консистентности с необратимыми юридическими последствиями; нужна человеческая точка A3 (правило отзыва).
