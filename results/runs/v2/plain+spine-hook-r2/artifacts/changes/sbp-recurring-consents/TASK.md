# Задача для кодового харнесса — рекуррентные C2B-списания (walking skeleton)

Реализовать рекуррентные C2B-списания («подписки СБП») поверх принятого решения «Платёжный шлюз СБП (C2B-приём)» по `changes/sbp-recurring-consents/` (DELTA.md, SOLUTION.md, ACCEPTANCE.md) и ADR-008..011.

## Что построить

1. **Менеджер согласий**: агрегат `Consent` и статусная машина `PENDING_PAYER → ACTIVE → REVOKED | EXPIRED` (+ `SUSPENDED`, `REJECTED`) по `docs/spec/consent-state-machine.md`; лимиты (`amountType`, `maxAmountPerCharge`, `periodicity`, `validUntil`); доказательство согласия и `revokedAt` в неизменяемом аудите.
2. **Инициатор списаний**: `POST /v1/consents/{consentId}/charges`; guard «согласие `ACTIVE` + сумма ≤ лимита» **до** вызова адаптера; уникальность по паре `(consentId, billingId)`; создание обычного платежа (`initiation=CONSENT`) в существующей статусной машине.
3. **Расширение мок-адаптера ОПКЦ**: `registerConsent`, `getConsentStatus`, `revokeConsent`, `createCharge`, `getChargeStatus`; события `consent.activated`, `consent.revoked`, `consent.rejected`, `payment.paid`. Реального протокола НСПК НЕ реализовывать (внешний вход `[ТРЕБУЕТ ПРОВЕРКИ]`).
4. **Отзыв**: `POST /v1/consents/{consentId}/revoke` (идемпотентно) и обработка нотификации ОПКЦ об отзыве (дедуп по `eventId`).
5. **Правило «отзыв ↔ списание в полёте»** (ADR-011, предлагаемое): запрет новых списаний после `revokedAt`; списание `IN_FLIGHT` доводится только если подтверждено `PAID`, иначе отменяется.
6. **Нотификации ТСП**: события `consent.*` (существующий контур вебхуков); списание — существующими `payment.*` с `consentId` в теле.
7. **Сверка**: согласия с ОПКЦ; поиск дублей списаний по `(consentId, billingId)`.

## Что НЕ менять (инварианты — дословно из spine)

- **AD-005** (Rule): «Вызов АБС на зачисление возможен только из состояния `PAID` (подтверждённый НСПК статус). Fitness: проверка недостижимости зачисления из `CREATED`/`QR_ISSUED`.»
- **AD-002** (Rule): «Изменение финансового статуса платежа и запись исходящего события (outbox) выполняются в одной локальной транзакции.»
- **AD-003** (Rule): «Повторная доставка любого сообщения не изменяет уже завершённое состояние.»
- **AD-004** (Rule): «Протокол НСПК знает только адаптер ОПКЦ; внутренний контракт шлюза — единственный интерфейс для остальных компонентов.»
- **AD-009** (Rule): «Рекуррентное списание создаётся только при согласии в статусе `ACTIVE` с совпадающими ТСП/счётом и в пределах `maxAmountPerCharge` и срока действия. Уникальность списания — пара `(consentId, billingId)` поверх обязательного `Idempotency-Key`. После `revokedAt` новые списания запрещены; списание в полёте обрабатывается по ADR-011.»

Запрещено: менять существующие эндпоинты/поля/события v0.1; переносить логику протокола НСПК из адаптера; зачислять из состояния, отличного от `PAID`.

## Критерии приёмки

`changes/sbp-recurring-consents/ACCEPTANCE.md` (AC-1..4, AC-N1..10, AC-C1..3, AC-P1..4) — обязательны негативные сценарии (дедуп, отказ без согласия, отзыв, недоступность ОПКЦ/АБС). Прогон на моках.

## Ограничения и дисциплина

- Код не писать до человеческого решения A3 по ADR-011: ветка «списание в полёте» реализуется по итогу A3; остальной контур можно строить.
- Исполняемая проверка инварианта AD-009: применить `arch-be rules template apply consent-before-auto-action --ad AD-009` (и `idempotency-key` для дедупа).
- Перед завершением: `arch-be gate` (fitness + spine + delta), `control check`, `openapi_lint`/`contract_diff` для контракта.

## План отката

`changes/sbp-recurring-consents/ROLLBACK.md`: фича-флаг `recurring_consents_enabled`, дренирование очереди, компенсации, без обратной миграции.

## Контракт результата

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа):

```json
{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}
```

- `status`: `blocked` ожидаем до A3/протокола НСПК — это корректный исход для части работ.
- `conflicts_with_prior_decisions`: любое расхождение с ADR/spine — сигнал эскалации архитектору, не молчаливое отклонение.
