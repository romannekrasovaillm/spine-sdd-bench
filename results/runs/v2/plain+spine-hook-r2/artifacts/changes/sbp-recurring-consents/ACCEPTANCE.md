# Критерии приёмки — рекуррентные C2B-списания

- Status: Proposed
- Owner: solution-architect + QA
- Связано: `DELTA.md`, `SOLUTION.md`, ADR-008..011; нотация EARS

Каждый критерий проверяем тестом/командой; негативные сценарии обязательны. Проверка — на walking skeleton (моки ОПКЦ/АБС) до массовой генерации.

## Функциональные (позитивные)

| ID | Критерий (EARS) | Проверка | Трассировка |
|---|---|---|---|
| AC-1 | When ТСП создаёт согласие, the шлюз shall зарегистрировать мандат и вернуть `PENDING_PAYER` | Интеграционный тест, p95 ≤ 500 мс | REQ-REC-1, ADR-008 |
| AC-2 | When ОПКЦ уведомляет об активации, the шлюз shall перевести согласие в `ACTIVE` и уведомить ТСП | Тест + вебхук `consent.activated` | REQ-REC-2 |
| AC-3 | While согласие `ACTIVE`, when приходит charge-запрос, the шлюз shall создать списание и довести до `COMPLETED` | Сквозной тест на моках | REQ-REC-3 |
| AC-4 | When ТСП отзывает согласие, the шлюз shall вернуть `REVOKED` идемпотентно | Тест повторного вызова | ADR-011 |

## Негативные сценарии (обязательны)

| ID | Критерий (EARS) | Проверка | Трассировка |
|---|---|---|---|
| AC-N1 | When согласие не в `ACTIVE`, the шлюз shall отклонить списание `409 CONSENT_NOT_ACTIVE` **без вызова ОПКЦ** | Тест: счётчик вызовов адаптера = 0 | REQ-REC-4, AD-009 |
| AC-N2 | When сумма > `maxAmountPerCharge`, the шлюз shall отклонить `422 CHARGE_EXCEEDS_CONSENT_LIMIT` до вызова ОПКЦ | Тест | REQ-REC-6 |
| AC-N3 | When повторный charge-запрос с той же парой `(consentId, billingId)` и другим `Idempotency-Key`, the шлюз shall создать ровно одно списание | Тест дедупликации (property) | REQ-REC-5, ADR-009 |
| AC-N4 | When та же пара `(consentId, billingId)` приходит с другой суммой, the шлюз shall вернуть `409 CHARGE_CONFLICT` | Тест | ADR-009 |
| AC-N5 | When нотификация `consent.activated` доставлена повторно, the шлюз shall не изменить состояние (дедуп по `eventId`) | Тест повторной доставки | AD-003 |
| AC-N6 | When применяется отзыв, the шлюз shall не создать ни одного списания с временем инициации позже `revokedAt` | Тест + анализ журнала | REQ-REC-7, ADR-011 |
| AC-N7 | When списание `IN_FLIGHT` не подтверждено `PAID` к моменту отзыва, the шлюз shall отменить его (`FAILED`); подтверждённое — довести до зачисления | Тест двух ветвей | REQ-REC-8, ADR-011 |
| AC-N8 | While платёж/списание не в `PAID`, the шлюз shall сделать зачисление в АБС недостижимым | Fitness-тест AD-005 | REQ-REC-9, AD-005 |
| AC-N9 | When АБС недоступна, the шлюз shall сохранить `PAID`, не потерять операцию и гарантировать зачисление сверкой | Chaos-тест + сверка | AD-005, ADR-004 |
| AC-N10 | When ОПКЦ недоступен, the шлюз shall не терять charge-запрос (очередь/ретраи) и не создавать дубль | Chaos-тест | ADR-009 |

## NFR-приёмка

| ID | Критерий | Проверка |
|---|---|---|
| AC-P1 | Активация согласия p95 < 30 с; при потерянной нотификации — ≤ 1 ч сверкой | Метрика + сверка |
| AC-P2 | Применение отзыва p95 < 30 с | Метрика |
| AC-P3 | Двойное списание по паре = 0; списание без согласия = 0 | Тесты + сверка |
| AC-P4 | Окно биллинга: burst +300 TPS выровнен очередью, лаг p95 < 5 мин, мгновенная нагрузка ≤ 1000 TPS | Нагрузочный тест |
