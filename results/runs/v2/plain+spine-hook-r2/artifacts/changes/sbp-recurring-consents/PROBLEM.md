# Проблема и гипотеза результата — рекуррентные C2B-списания (подписки СБП)

- Status: Proposed
- Owner: владелец продукта C2B + solution-architect
- Связано: `DELTA.md`, `RISK.md`, ADR-008..011

## Проблема

Принятое решение «Платёжный шлюз СБП (C2B-приём)» поддерживает одноразовые платежи: ТСП регистрирует QR/ссылку, плательщик сканирует и платит. Для подписочных моделей (онлайн-кинотеатры, ЖКХ, связь) это не работает: каждый период клиент должен снова совершить действие. Бизнес теряет выручку на отвале плательщиков и не может конкурировать с карточными рекуррентными списаниями; ТСП уходят в другие банки-эквайеры.

Одновременно рекуррентное списание — это финансовое действие **без участия клиента в момент списания**. Без явного, доказуемого и отзываемого согласия банк не может ни законно списывать, ни остановить списание, ни доказать регулятору основание операции. Цена бездействия: потеря подписочного сегмента C2B и/или неконтролируемые списания при «полуручной» реализации (риск 161-ФЗ/НПС, диспуты, отзыв).

## Гипотеза результата (измеримая)

Если добавить согласие плательщика и списание по нему **аддитивно** к принятому решению, то:

- ТСП подписочного сегмента (кинотеатры, ЖКХ, связь) смогут принимать рекуррентные платежи через СБП;
- одноразовые платежи и их потребители не меняют интеграцию (0 ломающих изменений контракта);
- двойных списаний по одному расчётному периоду — 0; списаний без действующего согласия — 0; списаний после отзыва — 0;
- доля успешных продлений подписки ≥ 95 % (метрика продукта, baseline согласовать с бизнесом).

## Метрики успеха (проверяемые на A4/A5)

| Метрика | Цель |
|---|---|
| Двойное списание по `(consentId, billingId)` | 0 |
| Списание без `ACTIVE`-согласия | 0 |
| Списание, инициированное позже `revokedAt` | 0 |
| Ломающие изменения контракта v0.1→v0.2 | 0 |
| Активация согласия (нотификация ОПКЦ → `ACTIVE`) | p95 < 30 с |
| Применение отзыва | p95 < 30 с |

## Цена бездействия

- Подписочный сегмент C2B недоступен банку; ТСП интегрируются у конкурентов.
- При «быстром» обходном решении (ТСП сам хранит мандат, шлюз не знает о согласии) — недоказуемое основание списания, неуправляемые списания, регуляторный и репутационный риск.

## Границы изменения (scope)

**В scope:** согласие плательщика (создание, активация, отзыв), списание по согласию, лимиты, дедупликация, отзыв vs списание в полёте, аддитивное расширение API ТСП, NFR, критерии приёмки, план отката.

**Вне scope (Deferred в spine):** управление подписками из клиентского ЛК банка; изменение параметров действующего согласия; C2C и выплаты; диспуты.

## Стейкхолдеры

| Роль | Интерес |
|---|---|
| Владелец продукта C2B | Выручка подписочного сегмента, SLA для ТСП |
| ТСП (кинотеатры, ЖКХ, связь) | Рекуррентный приём, простота интеграции |
| Плательщик | Прозрачность списаний, простота отзыва |
| Юристы/комплаенс | Законность списаний, доказательство согласия (161-ФЗ/НПС, 152-ФЗ) |
| ИБ/КИИ | Периметр ПДн, аудит, сегментация |
| Владелец API ТСП | Совместимость, дисциплина контракта |
| Дежурная смена/SRE | Сверка, DLQ, `IN_FLIGHT`, план отката |
