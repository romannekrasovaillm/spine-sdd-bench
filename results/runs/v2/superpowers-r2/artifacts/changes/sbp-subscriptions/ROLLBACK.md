# План отката: sbp-subscriptions

Откат аддитивного изменения поверх принятого решения. Обратимость обоснована в ADR-008 (reversible): новых trust-зон и каналов нет, миграции БД — аддитивные (новые сущности), деструктивной миграции нет.

## Сигналы отката

- доля успешных списаний по активным мандатам ниже порога (`docs/nfr.md` §7);
- зафиксировано списание без действующего согласия;
- рост жалоб/споров плательщиков по списаниям;
- расхождение состояния мандатов с сервисом СБП (шлюз считает `ACTIVE`, СБП — `REVOKED`);
- инцидент вендора транспорта, влияющий на операции подписок.

## Пошаговый откат

1. **Мгновенный стоп:** включить `subscriptions.charges=off` — новые списания не создаются; мандаты и история остаются читаемыми.
2. **Списания в полёте:** доводятся до терминального состояния штатно либо компенсируются возвратом (сага ADR-005).
3. **Остановка создания мандатов:** `subscriptions.create=off` — новые подписки не заводятся.
4. **Возврат к базовой способности:** ТСП продолжают работать по разовым QR/ссылкам — базовая функциональность не изменялась.
5. **Данные:** записи о согласиях, доказательствах и операциях **не удаляются** (регуляторное хранение и аудит); откат кода не означает удаление данных.
6. **Сверка:** финальная сверка мандатов и незавершённых списаний; отчёт для регуляторного/внутреннего аудита.

## Владелец решения

Владелец продукта «СБП-приём» совместно с ИБ (при риске для ПДн). Решение об отказе фиксируется в аудит-логе с обоснованием.

## Критерий успешного отката

После включения флага новых списаний нет; незавершённых списаний нет; сверка чистая; разовые платежи работают штатно; записи согласий читаемы и не утрачены. Репетиция — на гейте A4 (`arch control gate A4 . --rehearse`).
