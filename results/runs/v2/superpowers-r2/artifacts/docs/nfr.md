# NFR — Платёжный шлюз СБП (C2B-приём)

Целевые значения — **измеримые критерии приёмки** на гейтах A4/A5. Значения помечены как baseline; финальные согласуются с бизнесом и НСПК (регламенты оператора могут быть строже). Раздел 7 — измеримые цели подписок (рекуррентных списаний), добавленные изменением `changes/sbp-subscriptions/`.

## Проблема

NFR нужны, чтобы архитектурные обещания проверялись, а не декларировались: каждый пункт ниже имеет числовую цель и метод проверки. Пробел в измеряемости (нет числа или способа проверки) — дефект пакета; для подписок добавляется риск незаконного или двойного списания, который измеряется отдельными негативными критериями.

## 1. Доступность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доступность шлюза (месяц) | ≥ 99,95 % (плановая); целевая 99,99 % в часы пик | Uptime-мониторинг, синтетика на критичный путь |
| Недоступность регистрации QR (месяц) | ≤ 22 мин суммарно (для 99,95 %) | SLO-отчёт |
| Плановая недоступность | 0 при деплоях (rolling, без downtime) | CI/CD pipeline |

## 2. Производительность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Latency API ТСП «регистрация QR» | p95 < 500 мс, p99 < 1 с (без учёта времени НСПК) | Нагрузочный тест, APM |
| Latency «запрос статуса» | p95 < 300 мс | Нагрузочный тест |
| Доставка нотификации ТСП от события НСПК | p95 < 5 с | Метрика лага очереди |
| Зачисление в АБС от подтверждения НСПК | p95 < 60 с (SLA с АБС) | Метрика процесса |
| Throughput sustained | 200 TPS | Нагрузочный тест |
| Throughput пик (burst) | 500 TPS, допустимый burst 1000 TPS на 1 мин | Нагрузочный тест |
| Масштабируемость | ×2 без изменения архитектуры (горизонтальное масштабирование) | Load-test на 400 TPS |

## 3. Надёжность и восстановление

| Метрика | Цель | Метод проверки |
|---|---|---|
| RPO | 0 (нет потери зарегистрированных операций, статусов, событий outbox) | Тест отключения ноды, сверка |
| RTO (восстановление обработки) | ≤ 1 час | Chaos-тест, DR-учения |
| Потеря нотификации НСПК | 0 (компенсируется сверкой и опросом статусов) | Сверка с НСПК |
| Двойное зачисление при повторах | 0 (идемпотентность) | Тест на повторную доставку |

## 4. Сверка и расхождения

| Метрика | Цель | Метод проверки |
|---|---|---|
| Сверка с НСПК | ежечасная; расхождений по завершённым операциям — 0 | Reconciliation-отчёт |
| Сверка с АБС | суточная; расхождений — 0 | Reconciliation-отчёт |
| Отработка расхождений | 100 % по runbook за ≤ 4 часа | KPI дежурной смены |

## 5. Безопасность и соответствие

| Метрика | Цель | Метод проверки |
|---|---|---|
| Каналы к ОПКЦ | 100 % на сертифицированных СКЗИ (ГОСТ, mTLS) | ИБ-аудит, конфигурация |
| Финансовые переходы в аудит-логе | 100 %, лог неизменяем | Аудит, SIEM |
| ПДн | хранение минимизировано, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Доступ операторов к ручным операциям | 4-eyes (два согласования) | RBAC-проверка |
| Интеграция с AML/антифрод | передача операций по порогам — 100 % | Тест-кейсы |

## 6. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace id на операцию | 100 % операций | APM |
| Алерт на DLQ | DLQ > 0 → алерт за ≤ 5 мин | Мониторинг |
| Лаг очереди нотификаций | ≤ 60 с в норме | Мониторинг |
| Отчёт незавершённых операций | доступен всегда, актуален | Проверка |

## 7. Рекуррентные списания (подписки СБП)

Значения — baseline для пилота; финальные согласуются с бизнесом, НСПК и ИБ. Негативные цели (равенство нулю) — обязательные критерии приёмки, а не «желаемые».

| Метрика | Цель | Метод проверки |
|---|---|---|
| Списание без действующего мандата | **0** (ни одного списания и ни одного обращения в ОПКЦ при отсутствии/отзыве/истечении мандата) | Негативный тест + fitness-правило `consent-before-auto-action`; тест-шпион на адаптер |
| Двойное списание при повторе | **0** (повтор с тем же `Idempotency-Key` и повтор за закрытый период не создают второе списание) | Негативный тест идемпотентности; fitness-правило `idempotency-key` |
| Повторная отправка при неопределённом исходе | **0** (таймаут → `OPKC_UNKNOWN`, отправка ровно одна, далее только опрос статуса) | Тест-сценарий таймаута; fitness-правило `unknown-outcome-no-resend` |
| Доля успешных списаний по активным мандатам | ≥ 98 % (без учёта отказов плательщика/банка плательщика) | Метрика процесса, суточный отчёт |
| Latency списания (приём запроса ТСП → передача в ОПКЦ) | p95 < 500 мс, p99 < 1 с (без времени НСПК) | Нагрузочный тест, APM |
| Latency регистрации мандата (приём → запрос в ОПКЦ) | p95 < 500 мс | Нагрузочный тест |
| Применение отзыва согласия | Новые списания запрещены ≤ 60 с от получения отзыва; события в ОПКЦ — 0 после `REVOKED` | Тест на отзыв, метрика лага |
| Гонка «отзыв ↔ списание» | 0 зачислений по списанию, чей мандат отозван до зачисления | Chaos-тест сценария гонки |
| Доступность реестра мандатов | ≥ 99,95 % (мес.) | Uptime-мониторинг |
| RPO мандатов и доказательств согласия | 0 (ни одна запись согласия не теряется) | Тест отключения ноды, сверка |
| RTO подписочного контура | ≤ 1 час | Chaos-тест, DR-учения |
| Сверка мандатов с сервисом СБП | ежечасная; расхождений по активным мандатам — 0 (расхождение «у СБП отозван, у нас активен» — немедленный перевод в `REVOKED`) | Reconciliation-отчёт |
| Аудит согласий (доказательство) | 100 % мандатов имеют неизменяемую запись доказательства; лог append-only | Аудит, fitness-правило `append-only-journal` |
| ПДн в логах/метриках | 0 (ПДн плательщика отсутствуют в логах и метках метрик) | fitness-правило `no-pii-in-logs`, сканирование логов |
| Наблюдаемость подписок | 100 % списаний имеют `subscriptionId`/`periodKey`/trace id; отчёт незавершённых (`OPKC_UNKNOWN`) актуален | APM, проверка отчёта |
| Throughput списаний | 50 TPS sustained, пик 200 TPS (первая волна ТСП) | Нагрузочный тест |

## Зависимости (внешние входы для NFR)

- Регламенты НСПК: таймауты, сроки уведомлений, требования к доступности [ТРЕБУЕТ ПРОВЕРКИ — из документации НСПК].
- SLA АБС на зачисление и списание (согласуется с владельцем АБС).
- Требования ЦБ к защите информации при переводах (номер Положения — уточнить у ИБ) [ТРЕБУЕТ ПРОВЕРКИ].
- Сервис подписок СБП: лимиты, сроки подтверждения согласия, требования к уведомлению [ТРЕБУЕТ ПРОВЕРКИ — из документации НСПК].

## Критерии приёмки

- Каждый NFR имеет числовую цель и метод проверки (нагрузочный/chaos-тест, метрика, сверка или fitness-правило) — «непроверяемых» пунктов нет.
- Негативные цели раздела 7 (0 списаний без мандата, 0 двойных списаний, 0 повторных отправок при неопределённости, 0 зачислений при отозванном мандате) подтверждены тестами на гейте A4.
- Для каждого NFR указана тактика (реплика/очередь/сверка/feature-флаг) и trade-off; конфликты NFR разрешены записанным решением (ADR), а не молча.
- Критерий отката: после выключения подписок новые списания отсутствуют, мандаты читаемы, сверка чистая (см. `changes/sbp-subscriptions/DELTA.md`).

## Риски

- Значения подписочных NFR (доля успешных списаний, лаг отзыва, throughput) — baseline; регламенты НСПК и бизнес-требования могут быть строже, тогда цели пересматриваются с ADR/обоснованием.
- Достижимость «0 списаний без мандата» зависит от корректности внешнего состояния согласия (СБП); расхождения закрываются сверкой, но требуют эксплуатационной дисциплины.
- Рост числа списаний и возвратов увеличивает эксплуатационную нагрузку; цели по лагу DLQ/очередей могут потребовать пересмотра приоритетов.
