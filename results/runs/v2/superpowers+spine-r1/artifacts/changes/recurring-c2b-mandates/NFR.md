# NFR — СБП-подписки (рекуррентные C2B-списания)

- Изменение: `recurring-c2b-mandates` · Дата: 2026-09-28 · Статус: Proposed
- Дополняет `docs/nfr.md`; при archive вливается в раздел «Рекуррентные списания».

Метод: метрика + целевое значение + метод измерения + следствие нарушения. Значения — baseline; часть (предупреждение плательщика, лимиты, сроки) зависит от регламента ОПКЦ и помечена `[ТРЕБУЕТ ПРОВЕРКИ]`.

## 1. Своевременность списания (ядро ценности подписки)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доля списаний, инициированных в плановом окне (от `nextChargeAt` в пределах ±60 мин) | ≥ 99,9 % | Метрика планировщика, сверка с расписанием |
| Лаг планировщика: задержка от `nextChargeAt` до создания `Charge` | p95 ≤ 60 с, p99 ≤ 5 мин | Метрика планировщика, APM |
| Доля мандатов с корректным `nextChargeAt` после смены периода/отзыва | 100 % | Тест + сверка |
| Следствие нарушения | Списание «не в свой день» → жалобы плательщиков, отток подписок | Отчёт инцидентов |

## 2. Целостность и идемпотентность (критично для денег)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Двойных списаний за один `(mandateId, billingPeriod)` | **0** | Property-тест «две инициации → одно списание»; прод-мониторинг |
| Списаний без действующего (`ACTIVE`) мандата | **0** | Property-тест `consent-before-auto-action`; аудит |
| Повторных зачислений в АБС по одному списанию | **0** | Тест идемпотентности АБС-вызова (переиспользуется из базового NFR) |
| Доля списаний в состоянии `UNKNOWN` дольше | ≤ 0,1 % и разрешение сверкой ≤ 15 мин | Сверка, отчёт незавершённых операций |

## 3. Производительность и пиковые дни

| Метрика | Цель | Метод проверки |
|---|---|---|
| Throughput планировщика | ≥ 50 списаний/с sustained, ≥ 200/с в пике | Нагрузочный тест на «пиковый день» |
| Пиковый профиль (начало месяца: кинотеатры, ЖКХ, связь) | ×5 к среднему дню, window 4 ч | Нагрузочный тест по профилю |
| Backlog due-списаний в пик | возраст самого старого необработанного ≤ 15 мин | Метрика backlog (AgeOfFirstAttempt) |
| Регистрация/отзыв мандата (API ТСП) | p95 < 500 мс (без НСПК) | Нагрузочный тест |
| Следствие нарушения | Просрочка списаний, жалобы, ручной разбор штормов | Отчёт эксплуатации |

## 4. Согласие, предупреждение и лимиты

| Метрика | Цель | Метод проверки |
|---|---|---|
| Списаний без предупреждения плательщика (если требуется регламентом) | 0 | Сверка событий ОПКЦ `[ТРЕБУЕТ ПРОВЕРКИ]` |
| Отзыв согласия: задержка от события до `REVOKED` | p95 ≤ 5 с | Метрика обработки событий |
| Списаний, созданных после отзыва согласия | **0** | Тест гонки «отзыв ‖ инициация»; аудит |
| Выход списания за `amountLimit` мандата | **0** | Тест + проверка перед инициацией |
| Следствие нарушения | Несанкционированное списание — регуляторный риск | ИБ/комплаенс |

## 5. Доступность и восстановление

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доступность API мандатов | ≥ 99,95 % | SLO-мониторинг |
| RPO по мандатам/расписанию/списаниям | 0 | Тест отключения ноды, сверка |
| RTO обработки списаний после сбоя планировщика | ≤ 1 ч (в контуре общего RTO) | Chaos-тест: остановка планировщика → пересчёт due |
| Потеря списания при перезапуске планировщика | 0 (пересчёт из БД) | Тест «рестарт не теряет и не дублирует» |

## 6. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace id на списание и мандат | 100 % операций | APM |
| Метрики планировщика (due, created, lag, backlog, lease state) | доступны всегда | Мониторинг |
| Алерт на лаг/backlog выше порога | ≤ 5 мин | Мониторинг |
| Алерт на аномалию доли отказов списаний | ≤ 5 мин | Мониторинг |

## 7. Безопасность и ПДн

| Метрика | Цель | Метод проверки |
|---|---|---|
| ПДн плательщика в шлюзе | минимизированы: обезличенная ссылка ОПКЦ, без хранения лишних данных | ИБ-ревью, схема данных |
| Аудируемость согласия и каждого списания | 100 % финансовых переходов и действий с мандатом | Аудит, SIEM |
| Ручные операции с мандатами | 4-eyes | RBAC-проверка |

## 8. Внешние зависимости NFR

- Регламент ОПКЦ по подпискам: предупреждение плательщика, лимиты, сроки, доступность — `[ТРЕБУЕТ ПРОВЕРКИ]` (документация НСПК).
- SLA АБС в пиковые дни массовых списаний — согласуется с владельцем АБС.
- Требования ЦБ по защите информации при переводах (номер Положения — уточнить у ИБ) — `[ТРЕБУЕТ ПРОВЕРКИ]`.

## 9. Противоречия и trade-off

- **«Не потерять списание» vs «не списать неожиданно много»**: при длительном отказе планировщика «догон» может выдать много списаний сразу. Решение: ограниченное окно догона + политика отсечения устаревших периодов + предупреждение (владелец — бизнес, на A3).
- **Своевременность vs нагрузка на НСПК/АБС в пик**: сглаживание (лимиты, bulkhead) против «в свой день». Решение: приоритеты и лимиты, утверждаются на A2.
