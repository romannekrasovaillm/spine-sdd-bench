# Состязательное ревью изменения «Подписки СБП»

- Проведено: 2026-09-28, независимый контур (отдельный агент, свежий контекст; навык `adversarial-review`).
- Область чтения: `ARCHITECTURE-SPINE.md`, `docs/solutioning-subscriptions.md`, `docs/spec/subscriptions.md`, `docs/spec/state-machine.md`, `docs/adr/ADR-008-*.md`, `docs/nfr.md`, `openapi/tsp-api.yaml`, `docs/contracts/tsp-api.md`, `docs/contracts/opkc-adapter.md` (+ базовая подложка).
- Установка: «я не проектировал эту систему; моя работа — найти, что сломается».

## VERDICT: NOT-READY (первичный, до исправлений)

Находки (с проверяемым свидетельством):

1. **[blocker]** Рекуррентное списание не проходит переиспользуемый автомат: путь до `PAID` требует `qrId` (`docs/spec/subscriptions.md` §4 «R3 … `QR_ISSUED → PAID`»; `docs/spec/state-machine.md` §2 «T2 … `qrId` непустой»), а `createSubscriptionDebit` возвращает `ACCEPTED` без `qrId` (`docs/contracts/opkc-adapter.md` §3) → списание застревает в `CREATED`, зачисление недостижимо.
2. **[blocker]** Ограничения согласия (лимит, период, срок) не проверяются при инициации; `M7 ACTIVE→EXPIRED` без механизма; кардинальность «мандат→подписки» не ограничена (`docs/spec/subscriptions.md` §2, §4 R1, §5; `openapi/tsp-api.yaml` `MandateRequest`/`SubscriptionRequest`) → подписка выше `maxAmount`/на истёкшем мандате, обход лимита несколькими подписками.
3. **[blocker]** Противоречие ключа идемпотентности: `(subscriptionId, billingPeriod)` (AD-010) против `(subscriptionId, billingPeriod, attempt)` (`docs/spec/subscriptions.md` §4 R4); при таймауте (`opkc-adapter` §6 «неизвестный исход») возможен двойной списательный путь.
4. **[major]** Предуведомление плательщика назначено шлюзу без канала/компонента/владельца (R5); плательщик — клиент другого банка (`docs/solutioning.md` §2) → «обещание показателя без механизма», метрика NFR невыполнима.
5. **[major]** Приоритет отзыва над «списанием в полёте» недоказуем: момент отзыва не определён vs NFR «p95 ≤ 60 с»; runbook не в артефактах изменения; «не более одного на согласие» неисполнимо при нескольких подписках на мандат.
6. **[major]** План отката противоречив: rolling-откат релиза ядра убирает подписочный контур, обязанный обслуживать отзывы (AD-008 Reversibility vs §6.2).
7. **[major]** Ёмкость планировщика (100 000/час) меньше заявленного пика (200 TPS = 720 000/час) (`docs/nfr.md` §7).
8. **[major]** Нет проверки принадлежности мандата вызывающему ТСП (`docs/spec/subscriptions.md` §3 S2; `openapi` `SubscriptionRequest` `tspId`+`mandateId` из тела) → межтенантная привязка.
9. **[major]** Поведение при недоступности транспорта/пропущенном периоде не задано для планового списания (`opkc-adapter` §9.3; `subscriptions` §4 R1).
10. **[major]** Формат `billingPeriod` (компонент ключа) не определён (`openapi` без `pattern`; `period` бывает не только `MONTHLY`) → ключ перестаёт быть детерминированным на неделях/границах месяца.
11. **[minor]** Контракт обещает `status: PENDING_PAYER` синхронно, хотя по автомату сначала `CREATED` (M1) (`docs/contracts/tsp-api.md` §3.6).
12. **[minor]** Два события на один исход списания; `payment.rejected` требует `qrId`, которого у списания нет (`opkc-adapter` §3–4).
13. **[minor]** Машиночитаемый контракт не покрывает ошибки/аутентификацию/часть методов; доказательство аддитивности невоспроизводимо (нет снимка v0.1 в `openapi/`).
14. **[minor]** Маршрут ПДн плательщика (хранение/срок/удаление при `REVOKED`) не определён.
