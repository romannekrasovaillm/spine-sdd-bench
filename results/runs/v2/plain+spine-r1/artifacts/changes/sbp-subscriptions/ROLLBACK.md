# План отката — Подписки СБП

Источник: `docs/solutioning-subscriptions.md` §6.2, ADR-008 (Reversibility), `changes/sbp-subscriptions/DELTA.md`.

- **Обратимость:** `costly`. До боевой эксплуатации — `reversible` (фича за флагом). После появления действующих согласий откат = «stop-new» + обслуживание существующих.
- **Триггеры отката (сигналы):** массовые двойные списания; списания по отозванным мандатам; деградация планировщика (пропуск расписаний); нарушение уведомлений; расхождения сверки по согласиям.
- **Порядок:**
  1. `stop-new` — запрет новых согласий/подписок.
  2. Остановка планировщика по новым периодам (существующие «в полёте» доводятся).
  3. Отключение подписочной фичи фича-флагом. Откат релиза ядра — **только** для компонентов вне подписочного контура; сам контур остаётся на предыдущей совместимой версии (blue-green), иначе исчезает компонент, обязанный обслуживать отзывы.
  4. Компенсации/возвраты по затронутым операциям (сага ADR-005).
  5. Эскалация вендору транспорта при его отказе.
  6. Сверка и отчёт.
- **Что НЕ откатывается:** данные согласий/подписок и обязательства перед плательщиками; отзывы обязаны обрабатываться и после отката.
- **Владелец решения:** архитектор платёжного контура + владелец продукта + дежурная смена платежей (4-eyes для ручных компенсаций). **RTO ≤ 1 ч.**
- **Репетиция отката (rollback rehearsal) — обязательна к A4** (`REHEARSAL.json`/`docs/WALKING-SKELETON.md`), на момент propose не выполнена.
