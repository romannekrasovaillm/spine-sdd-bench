# Критерии приёмки — Подписки СБП (EARS)

Источник: `docs/solutioning-subscriptions.md` §6.1, `changes/sbp-subscriptions/DELTA.md`, `docs/spec/subscriptions.md`. Проверяются на гейтах A4/A5.

- [ ] Когда планировщик запущен повторно на тот же `billingPeriod` (или происходит транзиентный ретрай), the шлюз shall вернуть существующий `paymentId` и не создать второе **зачисленное** списание (AD-010).
- [ ] If статус согласия ≠ `ACTIVE`, или `amount > maxAmount`, или `scheduledAt ≥ validUntil`, then инициация списания shall быть недостижима и зафиксирована алертом (AD-009).
- [ ] If вызывающий ТСП не владеет `mandateId`, then создание подписки shall быть отклонено — `MANDATE_NOT_OWNED` (AD-009).
- [ ] If на мандат уже есть активная подписка, then создание второй shall быть отклонено — `SUBSCRIPTION_EXISTS` (AD-009/AD-013).
- [ ] If на мандат есть активная подписка, then возобновление (`SUSPENDED → ACTIVE`) другой подписки по этому мандату shall быть отклонено (закрытие обхода кардинальности через S4→S1→S5, AD-009).
- [ ] When приходит нотификация об отклонении рекуррентного списания, the платёж shall перейти в `FAILED` (`T4b`), а повтор — только как `attempt+1` по политике ретраев (AD-010; `docs/spec/state-machine.md`).
- [ ] When платёж создан по подписке, the его путь до `PAID` shall идти без QR (`CREATED → PAID`, `T4a`); ветвь `QR_ISSUED` для подписки недостижима (AD-012).
- [ ] When получен подтверждённый отзыв согласия (`REVOKING`/`REVOKED`), the подписочный контур shall не инициировать новые списания; «в полёте» — не более одного на согласие и урегулирование по runbook (AD-011).
- [ ] Where платёж создан по подписке, the зачисление shall происходить только из `PAID` через общий шлюз зачисления (AD-005/AD-012).
- [ ] When ТСП отменяет подписку, the согласие плательщика shall остаться в текущем статусе (AD-013).
- [ ] When приходит повторная нотификация НСПК с тем же `eventId`, the состояние shall не измениться (AD-003).
- [ ] When наступает `billingPeriod`, the шлюз shall обеспечить инициацию предварительного уведомления плательщика через ОПКЦ в срок `[ТРЕБУЕТ ПРОВЕРКИ]` (R5).
- [ ] If вендорский транспорт недоступен, then списания shall не теряться (очередь/DLQ, отчёт незавершённых операций, сверка добирает результат).
- [ ] When ТСП вызывает любой метод v0.1 после релиза v0.2, the поведение shall не измениться (аддитивность; `contract-diff` + regression-тест).
- [ ] Критерий успешного отката: существующие согласия/подписки обслуживаются (отзывы обрабатываются, «в полёте» завершаются), расхождений сверки — 0.
