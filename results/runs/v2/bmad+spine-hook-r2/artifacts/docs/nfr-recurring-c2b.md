# NFR — Рекуррентные C2B-списания по подписке СБП

- Status: Draft (для ревью на гейте A1 изменения `sbp-recurring-c2b`)
- Owner: solution-architect (платёжный контур)
- Дополняет: `docs/nfr.md`. Наследуются все действующие цели (доступность 99,95 %, RPO=0, RTO ≤ 1 ч, двойных зачислений 0); ниже — только **новые** измеримые цели. Значения помечены как baseline; протоколозависимые — `[ТРЕБУЕТ ПРОВЕРКИ]` до получения документации НСПК.

## 1. Планировщик и плановые списания

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Лаг инициации планового списания от `scheduledAt` | p95 ≤ 5 мин, p99 ≤ 15 мин | Метрика планировщика, APM | Списание приходит позже ожидаемого; жалобы ТСП |
| Точность планировщика | 100 % должных списаний создано в пределах окна `catch_up_horizon`; простой дольше окна — инцидент с ручным разбором | Сверка плана и факта | Недобор выручки ТСП (в пределах окна — ноль) |
| Дубли на `(mandateId, periodKey)` | 0 | Тест двойного прогона/нод | Двойное списание — инцидент |
| Догоняющий прогон (catch-up) после отказа | все пропущенные за ≤ 1 ч | Chaos-тест остановки планировщика | Потеря списаний за период |
| Live-проверка статуса мандата перед инициацией | p95 < 1 с (включая ОПКЦ) `[ТРЕБУЕТ ПРОВЕРКИ]` | Метрика планировщика | Задержка списаний |
| Throughput плановых списаний | sustained ≤ 100 TPS, burst ≤ 300 TPS — при условии, что **суммарная** нагрузка (разовые + плановые) не превышает бюджет `docs/nfr.md` (200/500 TPS); доля плановых выводится из модели объёма мандатов | Нагрузочный тест с профилем «разовые + плановые» | Выход за бюджет шлюза; деградация разового приёма |

## 2. Мандаты (согласия)

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Latency создания заявки на мандат (API ТСП) | p95 < 500 мс, p99 < 1 с (без НСПК) | Нагрузочный тест | Замедление онбординга подписки |
| Latency запроса статуса мандата | p95 < 300 мс | Нагрузочный тест | — |
| Активация мандата (подтверждение → `ACTIVE`) | p95 ≤ 60 с `[ТРЕБУЕТ ПРОВЕРКИ]` | Метрика процесса | Задержка старта подписок |
| Блокировка новых списаний после отзыва | ≤ 60 с (p99); новых списаний после отзыва — **0**; статус мандата проверяется перед каждой инициацией (live-проверка, целевой режим) | Тест отзыва (в т.ч. при потере события) + контроль списаний | Несанкционированное списание |
| Сверка статусов мандатов с ОПКЦ | ежедневно; расхождений `ACTIVE` — 0 | Reconciliation-отчёт | «Отозван у плательщика, активен у нас» |
| Отработка расхождения мандата | 100 % по runbook за ≤ 4 ч | KPI дежурной смены | Накопление неверных мандатов |

## 3. Надёжность и безопасность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Несанкционированные списания (без действующего мандата/сверх лимита) | 0 | Тесты guard + аудит |
| RPO для мандатов и списаний | 0 (нет потери согласия и списания) | Тест отключения ноды, сверка |
| Аудит жизненного цикла мандата и списаний | 100 % переходов и оснований | Аудит, SIEM |
| ПДн в мандате | 0 сырых реквизитов плательщика (только токены) | ИБ-ревью, тест-скан |
| Доступ операторов к ручным операциям по мандатам | 4-eyes | RBAC-проверка |

## 4. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Метрики планировщика (lag, due/created/failed, dedup-hits, catch-up) | доступны всегда | Дашборд/мониторинг |
| Алерт на лаг планировщика | > 15 мин → алерт за ≤ 5 мин | Мониторинг |
| Алерт на расхождение мандатов | любое расхождение → алерт | Сверка + мониторинг |
| Trace id на мандат и плановое списание | 100 % | APM |

## Зависимости (внешние входы)

- Регламенты НСПК по рекуррентному C2B (тайминги подтверждения/отзыва, лимиты сумм и периодов) `[ТРЕБУЕТ ПРОВЕРКИ]`.
- SLA АБС на зачисление/списание для рекуррентных документов (согласуется с владельцем АБС).
- Требования ЦБ к уведомлению плательщика о предстоящем списании и к хранению согласий `[ТРЕБУЕТ ПРОВЕРКИ]`.
- **Модель объёма и распределения мандатов по датам** (число активных мандатов, распределение `scheduledAt`) — без неё лаг, throughput и catch-up не проверяемы (владелец: продукт/аналитика ТСП).
- **Компонент и канал уведомления плательщика** о предстоящем списании (владелец: продукт + ИБ) `[ТРЕБУЕТ ПРОВЕРКИ]`.
