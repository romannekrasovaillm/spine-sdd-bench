# NFR — Платёжный шлюз СБП (C2B-приём)

Целевые значения — **измеримые критерии приёмки** на гейтах A4/A5. Значения помечены как baseline; финальные согласуются с бизнесом и НСПК (регламенты оператора могут быть строже).

## Проблема

Платёжный шлюз СБП обрабатывает финансово значимые операции, поэтому «быстро» и «надёжно» без чисел здесь неприемлемы: без измеримых бюджетов латентности, доступности, RPO/RTO и идемпотентности нельзя ни доказать корректность регулятору, ни принять релиз на A4. Дополнительно каждый новый функционал (подписки СБП, раздел 7) вводит собственные бюджеты, и их отсутствие — блокер приёмки.

## 1. Доступность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доступность шлюза (месяц) | ≥ 99,95 % (плановая); целевая 99,99 % в часы пик | Uptime-мониторинг, синтетика на критичный путь |
| Недоступность регистрации QR (месяц) | ≤ 22 мин суммарно (для 99,95 %) | SLO-отчёт |
| Плановая недоступность | 0 при деплоях (rolling, без downtime) | CI/CD pipeline |

## 2. Производительность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Latency API ТСП «регистрация QR» | p95 < 500 мс, p99 < 1 с (без учёта времени НСПК) | Нагрузочный тест, APM |
| Latency «запрос статуса» | p95 < 300 мс | Нагрузочный тест |
| Доставка нотификации ТСП от события НСПК | p95 < 5 с | Метрика лага очереди |
| Зачисление в АБС от подтверждения НСПК | p95 < 60 с (SLA с АБС) | Метрика процесса |
| Throughput sustained | 200 TPS | Нагрузочный тест |
| Throughput пик (burst) | 500 TPS, допустимый burst 1000 TPS на 1 мин | Нагрузочный тест |
| Масштабируемость | ×2 без изменения архитектуры (горизонтальное масштабирование) | Load-test на 400 TPS |

## 3. Надёжность и восстановление

| Метрика | Цель | Метод проверки |
|---|---|---|
| RPO | 0 (нет потери зарегистрированных операций, статусов, событий outbox) | Тест отключения ноды, сверка |
| RTO (восстановление обработки) | ≤ 1 час | Chaos-тест, DR-учения |
| Потеря нотификации НСПК | 0 (компенсируется сверкой и опросом статусов) | Сверка с НСПК |
| Двойное зачисление при повторах | 0 (идемпотентность) | Тест на повторную доставку |

## 4. Сверка и расхождения

| Метрика | Цель | Метод проверки |
|---|---|---|
| Сверка с НСПК | ежечасная; расхождений по завершённым операциям — 0 | Reconciliation-отчёт |
| Сверка с АБС | суточная; расхождений — 0 | Reconciliation-отчёт |
| Отработка расхождений | 100 % по runbook за ≤ 4 часа | KPI дежурной смены |

## 5. Безопасность и соответствие

| Метрика | Цель | Метод проверки |
|---|---|---|
| Каналы к ОПКЦ | 100 % на сертифицированных СКЗИ (ГОСТ, mTLS) | ИБ-аудит, конфигурация |
| Финансовые переходы в аудит-логе | 100 %, лог неизменяем | Аудит, SIEM |
| ПДн | хранение минимизировано, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Доступ операторов к ручным операциям | 4-eyes (два согласования) | RBAC-проверка |
| Интеграция с AML/антифрод | передача операций по порогам — 100 % | Тест-кейсы |

## 6. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace id на операцию | 100 % операций | APM |
| Алерт на DLQ | DLQ > 0 → алерт за ≤ 5 мин | Мониторинг |
| Лаг очереди нотификаций | ≤ 60 с в норме | Мониторинг |
| Отчёт незавершённых операций | доступен всегда, актуален | Проверка |

## 7. Подписки СБП — рекуррентные списания (ADR-008, Proposed)

Бюджеты для нового функционала (согласие + планировщик списаний). Действуют после A3; на мок-адаптере проверяются в walking skeleton.

| Метрика | Цель | Метод проверки |
|---|---|---|
| Инициация списания от срока (`billingPeriod`) | p95 ≤ 5 мин; ≥ 99,9 % в окне ±15 мин | метрика планировщика, нагрузочный тест |
| Дубликаты списаний на период | **0** | тест повторного тика/ручного триггера |
| Списание без `ACTIVE`-согласия → вызов ОПКЦ | **0** | fitness + тест `CONSENT_NOT_ACTIVE` |
| Прекращение новых списаний после отзыва (ядро) | ≤ 60 с | тест отзыва |
| Доведение отзыва до транспорта/НСПК | ≤ 5 мин (цель; SLA НСПК — внешний вход) | сверка/метрика |
| Latency операций согласия (`POST`/`GET /consents`) | p95 < 500 мс | APM |
| Пропускная способность планировщика | ≥ 50 000 списаний/час (burst), рост ×2 без перепроектирования | нагрузочный тест |
| Сверка «согласие ↔ списания ↔ АБС» | суточная; расхождений — 0 | reconciliation-отчёт |
| Аудит изменения согласия | 100 %, лог неизменяем | аудит/SIEM |
| Доступность подписочного пути | ≥ 99,95 % | SLO-отчёт |
| RPO по состоянию согласия | 0 | тест отключения ноды |
| RTO восстановления обработки списаний | ≤ 1 ч | DR-учения |
| Двойное зачисление по списанию при повторах | 0 (идемпотентность `consentId + billingPeriod`) | тест на повторную доставку |

## Критерии приёмки

Измеримые критерии приёмки (проверяются командами/телеметрией на A4/A5):

- [ ] Доступность шлюза ≥ 99,95 % (раздел 1) — SLO-отчёт.
- [ ] Регистрация QR p95 < 500 мс, sustained 200 TPS / пик 500 TPS (раздел 2) — нагрузочный тест.
- [ ] RPO = 0, RTO ≤ 1 ч, двойных зачислений — 0 (раздел 3) — chaos/DR-учения.
- [ ] Сверка с НСПК ежечасная и с АБС суточная, расхождений — 0 (раздел 4).
- [ ] 100 % каналов к ОПКЦ на сертифицированных СКЗИ, финансовые переходы в аудите (раздел 5).
- [ ] Подписки: дубликаты списаний — 0; списание без `ACTIVE`-согласия — 0; отзыв ≤ 60 с (раздел 7).
- [ ] Любой NFR-бюджет без числа и метода проверки — блокер приёмки (навык `nfr-design`).

## Риски

| Риск | Влияние | Митигация |
|---|---|---|
| НСПК меняет сроки/требования к отзыву согласия | NFR подписок недостижимы | значения помечены baseline; пересмотр после документации НСПК |
| АБС не держит массовые списания в один срок | SLA зачисления нарушен | приоритеты очередей, окно размазывания списаний, согласование SLA с АБС |
| Планировщик: пропуск/дубль при сбое | пропущенное или двойное списание | идемпотентность `consentId + billingPeriod`, сверка, DLQ |
| Рост ПДн из-за согласий | нарушение 152-ФЗ, рост поверхности атаки | минимизация, шифрование, аудит (AD-007) |
| Расхождение метрик NFR и реальности (нет метода) | ложная приёмка | каждый бюджет — с методом проверки, гейт A4 |

## Зависимости (внешние входы для NFR)

- Регламенты НСПК: таймауты, сроки уведомлений, требования к доступности [ТРЕБУЕТ ПРОВЕРКИ — из документации НСПК].
- SLA АБС на зачисление и списание (согласуется с владельцем АБС).
- Требования ЦБ к защите информации при переводах (номер Положения — уточнить у ИБ) [ТРЕБУЕТ ПРОВЕРКИ].
- Для подписок: протокол мандата НСПК, сроки отзыва и лимиты сумм/срока согласия [ТРЕБУЕТ ПРОВЕРКИ].
