## Проблема

ТСП (онлайн-кинотеатры, ЖКХ, связь) просят рекуррентные C2B-списания по согласию плательщика: сегодня каждый платёж требует динамического QR и действия клиента в приложении банка, поэтому подписочные модели (ежемесячная плата) невозможны. Нужен домен **согласия (мандата)** и исполнитель списаний по расписанию, которые переиспользуют принятые инварианты шлюза (AD-001…AD-008) и не ломают контракт `openapi/tsp-api.yaml` для существующих потребителей.

## ADDED

- **Требование CONSENT-1 (регистрация согласия).** ТСП регистрирует согласие плательщика под рекуррентные списания. Критерий (EARS): When ТСП вызывает `POST /v1/consents` с валидным `Idempotency-Key`, the СБП-шлюз shall создать согласие в состоянии `PENDING_PAYER` и вернуть `consentId` не позднее p95 500 мс.
- **Требование CONSENT-2 (активация).** Критерий (EARS): When плательщик подтверждает согласие в приложении своего банка (по каналу НСПК), the СБП-шлюз shall перевести согласие в `ACTIVE` атомарной транзакцией «статус + outbox + аудит» и уведомить ТСП событием `consent.activated`.
- **Требование CONSENT-3 (отзыв).** Критерий (EARS): When приходит отзыв согласия (плательщик, банк плательщика, ТСП, НСПК), the СБП-шлюз shall перевести согласие в `REVOKED` необратимо и прекратить инициацию новых списаний не позднее ≤ 60 с (ядро) / ≤ 5 мин (транспорт, SLA НСПК).
- **Требование DEBIT-1 (списание по расписанию).** Критерий (EARS): When наступает срок списания по `ACTIVE`-согласию, the планировщик шлюза shall инициировать ровно одно списание на период, идемпотентное по ключу `consentId + billingPeriod`.
- **Требование DEBIT-2 (ручной триггер ТСП).** Критерий (EARS): Where включён режим списания по запросу ТСП, When ТСП вызывает `POST /v1/consents/{consentId}/debits` с `Idempotency-Key`, the СБП-шлюз shall создать то же списание, что и планировщик, без второго финансового действия.
- **Требование DEBIT-3 (списание как платёж).** Критерий (EARS): When списание инициировано, the СБП-шлюз shall создать платёж в существующей статусной машине (`CREATED → QR_ISSUED → PAID → CREDITED → COMPLETED`), где `PAID` — подтверждение НСПК по списанию.
- **Требование GUARD-1 (запрет списания без согласия).** Критерий (EARS): If согласие не в состоянии `ACTIVE` (или лимит исчерпан, или срок истёк), then the СБП-шлюз shall отклонить инициацию списания кодом `CONSENT_NOT_ACTIVE` и не обращаться к ОПКЦ.
- **Требование GUARD-2 (зачисление только из PAID).** Критерий (EARS): When НСПК подтверждает списание, the СБП-шлюз shall зачислить АБС только из состояния `PAID` (AD-005) — состояние согласия не является основанием зачисления.
- **Требование AUDIT-1 (аудит согласия).** Критерий (EARS): When изменяется состояние согласия или лимит, the СБП-шлюз shall записать неизменяемое аудит-событие (кто, когда, основание) в том же контуре (AD-007).
- **Артефакты:** `docs/adr/ADR-008-...`; раздел «Подписки СБП» в `docs/nfr.md`; консентная статусная машина и переходы DEBIT в `docs/spec/state-machine.md`; раздел «Согласия и списания» в `docs/contracts/tsp-api.md`; пути/схемы в `openapi/tsp-api.yaml` (v0.2.0, аддитивно); подписочные операции в `docs/contracts/opkc-adapter.md` и `docs/rfp/vendor-rfp.md`.

## MODIFIED

- **AD-002 (единый источник истины).** Было: источник истины — только статусная машина платежа. Стало: согласие — **второй** источник истины со своей машиной в той же БД шлюза и той же атомарной дисциплиной перехода (`статус + outbox + аудит`). Причина: рекуррентное списание невозможно без долгоживущего основания. Rule не меняется.
- **AD-003 (идемпотентность).** Было: ключи `Idempotency-Key` / `eventId` / `paymentId`. Стало: добавляются ключи `consentId`, `consentId + billingPeriod` (планировщик); `refundId` без изменений. Причина: двойное списание — финансовый инцидент, тот же класс, что двойное зачисление.
- **AD-005 (зачисление только из PAID).** Было: зачисление из `PAID` платежа. Стало: тот же Rule, явно подтверждён для списаний: `ACTIVE`-согласие — основание **инициации**, не основание зачисления. Причина: исключить «списание из воздуха» по аналогии с «платежом из воздуха».
- **AD-004 (единственный адаптер ОПКЦ).** Было: набор методов платежа/возврата. Стало: тот же адаптер получает подписочные операции (создание мандата, списание, статус/отзыв мандата) — Rule «протокол НСПК знает только адаптер» не меняется, расширяется только набор.
- **`openapi/tsp-api.yaml`.** Было: v0.1.0, только платежи/возвраты. Стало: v0.2.0 — **аддитивно** добавлены `/v1/consents*`, `/v1/consents/{consentId}/debits`, схемы `Consent`/`DebitRequest`, поле `consentId` в `Payment` (опц.). Существующие пути, поля и enum не удаляются и не сужаются.
- **`docs/nfr.md`.** Было: NFR приёма платежей. Стало: добавлены измеримые NFR подписок (инициация по расписанию, дубликаты, отзыв, reconciliation) — см. ADR-008 §NFR.
- **`docs/solutioning.md`.** Было: «автоплатежи» в roadmap вне scope. Стало: автоплатежи/подписки выведены в scope отдельным изменением (этот пакет).
- **`README.md`.** Было: статус без упоминания подписок. Стало: ссылка на пакет изменения и его статус Proposed.

## План отката

- **До A3 / до реализации:** откат = архив дельты без влития; `ARCHITECTURE-SPINE.md` и ADR-008 возвращаются к базовому коммиту; кода нет — откат бесплатный и полный.
- **До боевой эксплуатации:** фиче-флаг `sbp.subscriptions.enabled` (по умолчанию `false`); `false` = согласия регистрируются только в тестовом контуре, планировщик остановлен, боевой приём не затронут.
- **После включения:** мгновенный stop-new — остановка планировщика + отклонение `POST /v1/consents`, при этом **уже открытые согласия и списания дорабатываются** (никаких «висящих денег»); откат релиза — rolling; новые таблицы аддитивны, обратной миграции данных не требуется; согласия остаются читаемыми.
- **Аварийный сценарий:** дубликаты/расхождения → DLQ + сверка по runbook; решение об откате принимает владелец — см. `changes/sbp-subscriptions/handoff/ROLLBACK.yaml` (триггеры и владелец).
- **Сигналы отката (триггеры):** двойное списание > 0; отзыв не исполнен в срок; инцидент целостности согласий; несоответствие требованиям НСПК по подпискам; предписание регулятора.
