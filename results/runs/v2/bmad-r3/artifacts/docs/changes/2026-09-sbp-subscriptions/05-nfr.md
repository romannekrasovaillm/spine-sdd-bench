# 05. Измеримые NFR нового функционала

Канонический источник — [`docs/nfr.md`](../../nfr.md) §7. Здесь — те же цели с обоснованием и способом проверки на гейтах A4/A5. Значения — **baseline**; финальные согласуются с бизнесом и регламентами НСПК.

## 1. Идемпотентность и целостность (главное)

| Метрика | Цель | Обоснование | Метод проверки |
|---|---|---|---|
| Более одного зачисленного списания на период | **0** | Один объект списания `(mandateId, periodKey)`, дуннинг — попытки внутри него, AD-011 | Тест гонки двух экземпляров инициатора; тест «рестарт в середине периода»; тест повторных попыток дуннинга; повторная нотификация с тем же `eventId` |
| Списание при `variable` без заданной суммы | **0** (fail-closed, списание не инициируется) | ADR-009 | Тест «нет `POST …/charges` → нет списания» |
| Списание по не-`ACTIVE` мандату | **0** | AD-009 | Негативный тест: списание после `REVOKED`/`SUSPENDED` → отказано, финансового движения нет |
| Списание выше лимита `variable` | **0** | ADR-009 | Граничные тест-кейсы: `amount = maxAmount`, `= maxAmount+1` |
| Двойное зачисление при повторах АБС | **0** | AD-005/ADR-005 (наследуется) | Тест повторного подтверждения АБС по `paymentId` |

## 2. Инициатор: своевременность и восстановление

| Метрика | Цель | Обоснование | Метод проверки |
|---|---|---|---|
| Лаг инициации от `scheduledAt` | p95 < 60 с, p99 < 5 мин (в норме) | Предсказуемость списаний для ТСП и плательщика | Мониторинг инициатора, синтетика |
| Catch-up после простоя | пропущенных активных периодов 0; **не более 1** списания на просроченный период | AD-011; защита от «пачки» списаний после сбоя | Chaos-тест: остановка инициатора на несколько периодов → проверка числа списаний |
| Пропускная способность | ≥ 50 инициаций/с sustained, пик 200/с | Запас под рост базы подписок | Нагрузочный тест |
| Масштабируемость | ×2 без изменения архитектуры, без дублей | AD-011 (ключ вместо лидер-лока) | Load-test 100 инициаций/с на 2+ экземплярах |

## 3. Мандат: оформление, отзыв, уведомление

| Метрика | Цель | Обоснование | Метод проверки |
|---|---|---|---|
| Регистрация мандата (`POST /v1/mandates`) | p95 < 500 мс (без учёта НСПК) | Согласуется с NFR API ТСП | Нагрузочный тест |
| Активация мандата после согласия | p95 < 30 с от события НСПК `[ТРЕБУЕТ ПРОВЕРКИ]` | Согласие должно вступать в силу быстро | Метрика процесса |
| Блокировка новых списаний при отзыве | p95 < 60 с от получения события; **100 %** отзывов обрабатываются приоритетно | Защита плательщика, AD-009/AD-012 | Негативный тест «отзыв → попытка инициации» |
| Уведомление плательщика о списании | 100 % списаний в регламентный срок `[ТРЕБУЕТ ПРОВЕРКИ]` | 161-ФЗ/НПС, AD-012 | Отчёт/аудит |

## 4. Сверка, аудит, доступность

| Метрика | Цель | Обоснование | Метод проверки |
|---|---|---|---|
| Сверка мандатов с НСПК | ежечасная; расхождений **0** (в т.ч. «у нас `ACTIVE`, у НСПК отозван») | AD-002/ADR-004 | Reconciliation-отчёт |
| Сверка списаний с АБС | суточная; расхождений 0 | ADR-005 | Reconciliation-отчёт |
| Хранение доказательств согласия | 100 % записей неизменяемы; retention по НПС/152-ФЗ `[ТРЕБУЕТ ПРОВЕРКИ]` | AD-012, 152-ФЗ | ИБ-аудит |
| Доступность функции подписок | ≥ 99,95 % (месяц) | Согласовано с SLO шлюза | SLO-отчёт |
| Наблюдаемость инициатора | lag, число catch-up, дуннинг-ретраи, DLQ, доля отказов | ADR-010 | Мониторинг/алерты |

## 5. Наследуемые сквозные цели (не меняются)

Доступность шлюза ≥ 99,95 %; RPO = 0; RTO ≤ 1 ч; зачисление в АБС от подтверждения НСПК p95 < 60 с; сверка с НСПК ежечасная; двойных зачислений 0 (см. `docs/nfr.md` §1–4). Регулярные списания не вводят отдельных исключений — подписки обязаны укладываться в эти же цели.

## 6. Внешние входы, влияющие на NFR

- Регламенты НСПК по мандатам и уведомлениям: тайминги активации, сроки уведомления о списании, требования к доступности `[ТРЕБУЕТ ПРОВЕРКИ]`.
- Правила отзыва согласия (161-ФЗ/Положение ЦБ): срок и порядок, влияющие на цель «блокировка при отзыве».
- SLA АБС (наследуется, не пересматривается).
