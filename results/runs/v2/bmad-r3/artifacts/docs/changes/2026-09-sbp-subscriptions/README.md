# Изменение 2026-09 — Подписки СБП (рекуррентные C2B-списания)

Пакет архитектурного изменения **поверх принятого решения** «Платёжный шлюз СБП (C2B-приём)». Готовится к вынесению на архитектурное решение (гейт **A3**) и последующей передаче исполнителям.

- **Изменение:** ТСП (онлайн-кинотеатры, ЖКХ, связь) получают возможность рекуррентных C2B-списаний по согласию плательщика (подписки СБП) — без QR и действия клиента на каждое списание. Наличие mandate-механизма в протоколе ОПКЦ — внешнее допущение `[ТРЕБУЕТ ПРОВЕРКИ]`.
- **Выбранная модель:** мандат плательщика + **инициатор регулярных списаний в ядре шлюза** (банк владеет расписанием); тип мандата — `fixed` и `variable`.
- **Статус:** `Draft` · **ожидает человеческого решения A3** · код не реализовывался (по условию задачи).
- **Маршрут:** **Critical** (оценка изменения 11/15 — см. [`01-significance-and-route.md`](01-significance-and-route.md)).

## Однострочный итог для решения

Ядро не перепроектируется: регулярное списание — **обычный платёж** в уже принятой статусной машине, зачисление по-прежнему только из подтверждённого НСПК `PAID`. Новое — **мандат плательщика** (согласие) как отдельный источник истины и **инициатор**, обеспечивающий «ровно одно списание на период». Риск — регуляторный (согласие, уведомление, отзыв) и внешний (протокол мандатов НСПК, расширение RFP вендора).
