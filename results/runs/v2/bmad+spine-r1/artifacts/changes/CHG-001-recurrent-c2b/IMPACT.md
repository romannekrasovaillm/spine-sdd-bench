# CHG-001 — Влияние на принятую архитектуру

- Дата: 2026-09-28
- База: `ARCHITECTURE-SPINE.md` (AD-001..AD-008), ADR-001..007, `docs/`, `openapi/tsp-api.yaml` v0.1

## 1. Инварианты: что затронуто

| Инвариант | Статус | Как затрагивается |
|---|---|---|
| AD-001 Изоляция платёжного контура | Расширяется (Binds) | Новые элементы (сервис подписок, планировщик, реестр мандатов) — внутри платёжного контура; внешние вызовы по-прежнему только через адаптеры. Не нарушен. |
| AD-002 Единый источник истины (автомат) | Не нарушен, подтверждён | Денежный автомат не дублируется: каждое списание — платёж существующего автомата. Добавляется отдельный автомат мандата (не денежный). |
| AD-003 Идемпотентность | Расширяется (Binds) | Новые ключи: `(subscriptionId, billingPeriod)` для списаний; идемпотентность отзыва/отмены. |
| AD-004 Единственный адаптер ОПКЦ | Расширяется (Binds) | Рекуррентный протокол НСПК добавляется только в адаптер; ядро остаётся транспортно-независимым. |
| AD-005 Зачисление только из `PAID` | Подтверждён, критичен | Каждое рекуррентное списание зачисляется только из `PAID`; исключений не вводится. |
| AD-006 Trust-зоны и сегментация | Сохраняется | Новый сервис размещается в платёжном контуре; новых trust-зон нет. Реестр мандатов — в защищённом контуре. |
| AD-007 НПС/КИИ/ПДн | Расширяется | Мандат — персонально значимые данные; аудит автоматических списаний и уведомлений; сроки хранения согласия. |
| AD-008 Гибрид, транспортная независимость | Подтверждён | Рекуррентный протокол — в вендорском адаптере; контракт ядра расширяется внутри. |
| AD-009 Мандат — основание списания | Новый (Proposed) | Вводится. |
| AD-010 Списание — идемпотентная платёжная операция | Новый (Proposed) | Вводится. |
| AD-011 Отзыв немедленно запрещает списания | Новый (Proposed) | Вводится. |
| AD-012 Расписание/исполнение — прослеживаемый источник истины | Новый (Proposed) | Вводится. |

**Вывод:** ни один принятый инвариант не отменяется и не переопределяется. Изменение — аддитивное расширение (новые Binds и новые AD-009..AD-012).

## 2. Компоненты: что добавляется

- **Сервис подписок** — управление подписками/мандатами по API ТСП.
- **Реестр мандатов** (новое хранилище) — жизненный цикл согласия, RPO=0.
- **Планировщик списаний** — инициирование периодических списаний и фиксация периодов.
- Расширение **адаптера ОПКЦ** — рекуррентные операции/события (вендор).
- Расширение **API ТСП** — аддитивно, `/v1` v0.2.

Не меняется: статусная машина денег, транзакционный outbox, нотификатор ТСП, интеграция с АБС (переиспользуется), сверка.

## 3. Владельцы, с которыми согласовывать

| Тема | Владелец |
|---|---|
| Модель мандата, расписание, отзыв | solution-architect (платёжный контур) |
| Интеграция зачисления/списания, идемпотентность АБС | владелец АБС |
| ПДн, КИИ, хранение согласия, режим доступа | ИБ / КИИ |

| Рекуррентные операции в RFP/контракте вендора | проектный офис / закупки |

## 4. Scope-изменение и эскалация

- **Scope**: «автоплатежи» ранее значились вне scope (`docs/solutioning.md`, §1) и в Deferred — переводятся в scope этим изменением.
- **Эскалация на родительский spine**: вводится новый домен «согласия/подписки». Родительский spine initiative «Подключение банка к СБП (эквайринг C2B)» должен подтвердить, что новый домен не вводит конфликтующих ограничений. До подтверждения — локальное изменение остаётся `Proposed` (см. `OPEN-QUESTIONS.md`).
- Родительские ограничения не переопределяются; конфликт (если обнаружится) — эскалация наверх, не локальное решение.

## 5. Риски влияния

| Риск | Влияние | Митигация |
|---|---|---|
| Гонка «отзыв ↔ списание в полёте» | Недетерминированные списания | AD-011 + явная политика исхода (A3) |
| Дубли планировщика | Двойные списания | AD-010 (ключ периода) + лидерство планировщика |
| Пакетные пики периода | Деградация шлюза | NFR пакетных пиков, нагрузочные тесты |
| ПДн в реестре мандатов | Регуляторный риск | Минимизация, шифрование, ИБ-ревью (AD-007) |
| Внешний вход протокола НСПК | Блокировка реализации | Мок-адаптер, `[ТРЕБУЕТ ПРОВЕРКИ]`, старт ядра независимо (AD-008) |
