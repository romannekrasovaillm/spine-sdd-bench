# CHG-001 — Что остаётся на решение человека-архитектора (A3) и почему

- Дата: 2026-09-28
- Принцип: агент готовит пакет и машиночитаемый черновик решения; человек принимает развилки, необратимые по смыслу, продуктовые, регуляторные или коммерческие.

## Развилки A3

### Q1. Тип подписки в первой волне: фиксированная сумма или переменная?
- Варианты: (a) только фиксированная сумма; (b) фиксированная + переменная с лимитом (`maxAmount`).
- Почему человек: влияет на схему мандата и на требования НСПК; переменные суммы расширяют риск и регулирование.
- Рекомендация агента: (a) в первой волне — фиксированная; переменная — отдельным изменением.

### Q2. Политика неоплаченных периодов и догона пропущенных списаний.
- Варианты: (a) N повторных попыток в течение M часов, затем `SKIPPED` без догона; (b) догон в пределах действующего мандата; (c) ручной разбор.
- Почему человек: бизнес-решение с юридическими последствиями (догон без явного основания рискован).
- Рекомендация агента: (a) — повторные попытки без «тихого» догона; `SKIPPED` фиксируется явно (AD-012).

### Q3. Уведомление о предстоящем списании: срок и канал.
- Почему человек: задаётся регламентом НСПК и политикой банка `[ТРЕБУЕТ ПРОВЕРКИ]`.
- Рекомендация агента: реализовать по регламенту; NFR-SLA на своевременность уведомлений включить в A4.

### Q4. Источник истины по мандату: локальный реестр + зеркало банка плательщика, или локальный как единственный для ядра?
- Почему человек: решение о персонально значимых данных (152-ФЗ), режиме хранения и сроке жизни согласия; ИБ-развилка.
- Рекомендация агента: локальный реестр — источник истины для расписания/идемпотентности (AD-001), события банка плательщика — вход; минимизировать хранимые ПДн.

### Q5. Исход списания «в полёте» при отзыве мандата.
- Варианты: (a) доводить до терминального статуса по протоколу ОПКЦ; (b) компенсировать (возврат) при отзыве.
- Почему человек: финансово-правовое решение; требует политики и runbook.
- Рекомендация агента: (a) — детерминированный исход по протоколу, компенсация только по факту успешного списания; правило фиксируется в AD-011.

### Q6. Эскалация на родительский spine (новый домен «согласия/подписки»).
- Почему человек: feature-spine не переопределяет родительские ограничения; нужен явный ack родительского контура.
- Рекомендация агента: подтвердить отсутствие конфликта; при конфликте — эскалация, а не локальное решение.

### Q7. Рекуррентный протокол в контракте вендора.
- Варианты: (a) расширение текущего RFP/адаптера; (b) отдельный SOW/этап.
- Почему человек: коммерческое решение и сроки; влияет на критический путь.
- Рекомендация агента: (a) — расширение текущего адаптера с обязательным требованием идемпотентности по `reference`.

### Q8. Контрактная стратегия.
- Развилка: расширение `/v1` (выбрано, breaking = 0) против нового `/v2`.
- Почему человек: подтверждение совместимости и deprecation-политики с потребителями.
- Рекомендация агента: `/v1` аддитивно (доказано `contract_diff`).

## Что НЕ требует человека (решено агентом в рамках принятого)

- Выбор переиспользования статусной машины денег вместо второго автомата (следует из AD-002/AD-005).
- Аддитивный характер контракта и версия 0.2 (проверено `contract_diff`).
- Форма жизненного цикла мандата (предложена; финальная семантика — по протоколу НСПК).

## Обязательные внешние входы до apply

1. Документация НСПК по подпискам (протокол, статусы, события, уведомления) `[ТРЕБУЕТ ПРОВЕРКИ]`.
2. Подтверждение ИБ/КИИ по режиму хранения мандатов.
3. Согласование с владельцем АБС идемпотентности списаний по `refundId`/`paymentId`.
4. Ack родительского spine по новому домену.
