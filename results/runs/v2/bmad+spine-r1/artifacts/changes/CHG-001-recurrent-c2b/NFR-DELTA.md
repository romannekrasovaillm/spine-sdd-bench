# CHG-001 — Измеримые NFR нового функционала

- Дата: 2026-09-28
- Назначение: бюджеты для подписок/мандатов; дополняют `docs/nfr.md` (после archive). Значения — baseline; уточняются с бизнесом, АБС и по регламентам НСПК.
- Правило: метрика + цель + метод проверки + следствие нарушения.

## 1. Мандат и подписка

| NFR | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Регистрация подписки (API ТСП) | p95 < 700 мс, p99 < 1.5 с (без времени ОПКЦ) | нагрузочный тест, APM | медленный онбординг подписчиков |
| Запрос карточки подписки | p95 < 300 мс | нагрузочный тест | деградация ЛК ТСП |
| Активация после согласия плательщика (от события ОПКЦ) | p95 < 5 с | метрика лага обработки событий | подписка неактивна, списание пропущено |
| Хранение мандата: RPO | 0 (согласие не теряется) | тест отказа ноды, сверка | потеря основания списания, регуляторный риск |
| Доступность расширенного контура (месяц) | ≥ 99,95 % | uptime-мониторинг, синтетика | подписки и QR-приём недоступны |

## 2. Рекуррентные списания

| NFR | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Точность расписания | ≥ 99.9 % списаний инициируются в окне ± 15 мин от планового времени периода | отчёт «плановое ↔ фактическое время» | жалобы плательщиков, нарушения регламента |
| Инициация списания (API/ядро) | p95 < 600 мс | нагрузочный тест | задержка пакета периода |
| Зачисление в АБС от подтверждения ОПКЦ | p95 < 60 с (SLA с АБС, прежний) | метрика процесса | задержка расчётов с ТСП |
| Двойные списания за один период | 0 (идемпотентность `(subscriptionId, billingPeriod)`) | тест повторных триггеров/дублей планировщика | финансовый инцидент, возвраты |
| Пакетный пик (начало периода) | sustained 300 TPS, burst 800 TPS на 5 мин | нагрузочный тест пакетного профиля | деградация всего шлюза в пик |
| Масштабируемость | ×2 по нагрузке без изменения архитектуры | load-test ×2 | блокировка роста подписчиков |
| Сверка списаний с ОПКЦ/АБС | период × charge без расхождений (0 расхождений по завершённым) | reconciliation-отчёт | незамеченные/двойные списания |

## 3. Отзыв и уведомления (граница безопасности)

| NFR | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Блокировка после отзыва мандата | 0 новых списаний после фиксации `revokedAt` | негативный тест «отзыв → новое списание невозможно» | незаконное списание, регуляторный риск |
| Детерминизм исхода in-flight списания при отзыве | 100 % операций имеют один из двух задокументированных исходов | тест гонки «revoke ↔ initiateCharge» | неопределённое финансовое состояние |
| Уведомление о предстоящем списании | 100 % плановых списаний уведомлены в срок по регламенту `[ТРЕБУЕТ ПРОВЕРКИ]`; своевременность ≥ 99.9 % | отчёт по уведомлениям | нарушение прав плательщика |
| Приостановка/отзыв — доступность API | p95 < 500 мс | нагрузочный тест | плательщик не может отозвать согласие |

## 4. Наблюдаемость

| NFR | Цель | Метод проверки |
|---|---|---|
| Trace id на операцию подписки/списания | 100 % | APM |
| Метрики подписок | active/suspended/revoked, charges по статусам, доля FAILED, глубина DLQ | дашборд |
| Алерты | DLQ > 0 → ≤ 5 мин; провал точности расписания → ≤ 15 мин; расхождение сверки → ≤ 1 ч | мониторинг |

## 5. Безопасность и соответствие

| NFR | Цель | Метод проверки |
|---|---|---|
| ПДн в реестре мандатов | минимизация, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Аудит автоматических списаний | 100 % переходов мандата и списаний в неизменяемом аудит-логе | аудит, SIEM |
| Доступ к реестру мандатов | только сервисный, привилегированный доступ 4-eyes для ручных операций | RBAC-проверка |

## Зависимости (внешние входы)

- Регламент НСПК по подпискам: сроки уведомления, лимиты, таймауты, состав событий `[ТРЕБУЕТ ПРОВЕРКИ]`.
- Политика неоплаченных периодов (число попыток, интервалы, догон) — решение бизнеса (`OPEN-QUESTIONS.md`).
- SLA АБС на зачисление/списание — прежнее.
