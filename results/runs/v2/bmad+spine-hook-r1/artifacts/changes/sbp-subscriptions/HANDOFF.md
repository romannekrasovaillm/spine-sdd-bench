# Handoff — Подписки СБП (рекуррентные C2B-списания по согласию)

Пакет передачи исполнителям (кодовому харнессу) для изменения `sbp-subscriptions`. Компилирует
суть поверх принятого решения (ARCHITECTURE-SPINE.md, ADR-001..007) и ADR-008. Дополняет
`.arch-handoff/` (пакет walking skeleton базового C2B-потока); не заменяет его.

## Задача (epic-context)

Реализовать **контур подписок** в СБП-шлюзе: согласие плательщика (мандат) как сущность со своим
жизненным циклом и инициатор, который по расписанию создаёт платежи по действующему мандату и
переиспользует уже принятый платёжный контур. Реальный протокол НСПК по подпискам не реализуется
(внешний вход `[ТРЕБУЕТ ПРОВЕРКИ]`) — адаптер мокается.

Стыки:
- **ТСП → шлюз**: новые методы `POST /v1/mandates`, `GET /v1/mandates/{mandateId}`, `POST /v1/mandates/{mandateId}/revoke`; в `Payment` — опциональные `originationType`, `mandateId`; вебхуки `mandate.activated|revoked|expired`, `debit.failed` (`openapi/tsp-api.yaml`, v0.2.0).
- **инициатор → платёжная статусная машина**: платёж по мандату — тот же автомат; переходы `CREATED → PAID | FAILED` без `QR_ISSUED` (T13–T15, `docs/spec/state-machine.md`).
- **шлюз → адаптер ОПКЦ** (мок): `createMandate`, `getMandateStatus`, `revokeMandate`, `createDebitByMandate`; события `mandate.*`, `debit.*` (`docs/contracts/opkc-adapter.md` §10).
- **шлюз → АБС**: без изменений контракта — идемпотентное зачисление по `paymentId` (ADR-005).
- **жизненный цикл мандата**: `docs/spec/mandate-state-machine.md` — состояния, переходы M1–M10, лимиты, идемпотентность.

## Обязательные инварианты (передаются дословно; менять запрещено)

- **AD-005**: «Вызов АБС на зачисление возможен только из состояния `PAID` (подтверждённый НСПК статус).»
- **AD-002**: «Изменение финансового статуса платежа и запись исходящего события (outbox) выполняются в одной локальной транзакции.»
- **AD-003**: «Повторная доставка любого сообщения не изменяет уже завершённое состояние.»
- **AD-004**: «Протокол НСПК знает только адаптер ОПКЦ; внутренний контракт шлюза — единственный интерфейс для остальных компонентов.» (это AD-004/AD-008 — протокол не покидает адаптер)
- **AD-008**: «Ядро шлюза проектируется контрактно-независимым от транспорта (внутренний контракт адаптера ОПКЦ — единственная зависимость).»
- **AD-009** (новый): «Рекуррентное C2B-списание инициируется только против мандата в состоянии `ACTIVE`, в пределах его лимитов (на списание, на период, по числу списаний) и по его расписанию… отзыв терминален — после него новые списания невозможны.»
- **AD-010** (новый): «Рекуррентные списания инициирует только планировщик платёжного контура шлюза; каждое списание идемпотентно по ключу `(mandateId, periodKey)`… пропущенный запуск фиксируется в отчёте незавершённых операций и не теряется. Взаимодействие с ОПКЦ — только через адаптер ОПКЦ.»

**Запрещено менять:** `Payment.status` (перечисление), правило зачисления только из `PAID`, контракт
адаптера §1–§9, существующие методы API ТСП, стратегию ADR-007/AD-008. Конфликт с инвариантом обязан
остановить работу и эскалировать, а не «разрешиться на месте».

## Ограничения (CONSTRAINTS.yaml)

Действуют `.arch-handoff/CONSTRAINTS.yaml` (включая 4 новых правила подписок) и fitness-гейт
`arch-be gate --route auto`. Правила проверяют: наличие ADR-008 и спецификации мандата, инвариант
AD-009 в спайне, измеримость NFR подписок.

## Критерии приёмки (выполнимы на моках)

- Создание мандата идемпотентно по `Idempotency-Key`; `GET` возвращает состояние мандата.
- Списание по `REVOKED`/`EXPIRED`/`FAILED`/лимит-исчерпанному мандату → отказано, платёж не создан (AD-009).
- Повторный запуск инициатора за тот же `(mandateId, periodKey)` → одно списание (AD-010).
- Зачисление только из `PAID`; повторное подтверждение АБС не создаёт вторую проводку (AD-005, AD-003).
- Повторная нотификация (тот же `eventId`) не меняет состояние; событие по завершённому переходу — алерт.
- Отзыв согласия: новые списания прекращены в целевом окне (≤ 5 мин); факт отзыва в аудит-логе.
- Вебхуки: at-least-once, дедупликация по `X-SBP-Event-Id`, после исчерпания ретраев — DLQ.
- Совместимость: потребитель API 0.1 работает без изменений; `openapi_lint` — PASS.

## План отката

- До боя: не включать фичу. После: флаг `stop-new` (новые мандаты/списания запрещены, открытые платежи доводятся), архивация мандатов, rolling-откат, сверка. RTO ≤ 1 ч. Сигналы отката и владелец — `proposal.md` §6.2.

## Контракт результата (headless JSON)

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа):

```json
{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}
```

`conflicts_with_prior_decisions` — сигнал эскалации к архитектору (ADR-008/спайн), а не молчаливое
отклонение. При `blocked` перечислить недостающие входы (в т.ч. документация НСПК по подпискам).

## Контур контроля после прогона

`arch-be control check <repo>` (fitness) → `arch-be gate --route auto` → рубрика приёмки
(`.arch-handoff/RUBRIC.yaml`, `handoff_quality`). Инциденты/отклонения — в новые сенсоры и правила.
