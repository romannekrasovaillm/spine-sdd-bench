# NFR (дополнение) — Подписки СБП: рекуррентные C2B-списания по согласию

- Status: Draft (baseline; финал — на гейте A1 дельты «подписки СБП»)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, ADR-009, `docs/nfr.md` (базовый набор), AD-005, AD-009 (spine)

Дополняет, **не заменяет** `docs/nfr.md`: базовые SLO (доступность ≥ 99,95 %, RPO=0, RTO ≤ 1 ч, sustained 200 TPS / пик 500 TPS) продолжают действовать. Ниже — измеримые цели **только нового функционала**, все — кандидаты в критерии приёмки A4/A5. Регламенты НСПК могут быть строже — значения помечены `[ТРЕБУЕТ ПРОВЕРКИ]` и уточняются по документации.

## 1. Латентность (без учёта времени ОПКЦ)

| Метрика | Цель | Метод проверки |
|---|---|---|
| `POST /v1/mandates` (создание согласия) | p95 < 1 с, p99 < 2 с | Нагрузочный тест, APM |
| `POST /v1/mandates/{id}/debits` (инициация списания) | p95 < 500 мс, p99 < 1 с | Нагрузочный тест, APM |
| `GET /v1/mandates/{id}` | p95 < 300 мс | Нагрузочный тест |
| Активация согласия от события НСПК | p95 < 60 с | Метрика обработки событий |
| Событие вебхука по согласию до ТСП | p95 < 5 с | Лаг очереди нотификаций |

## 2. Пропускная способность и пики подписок

| Метрика | Цель | Метод проверки |
|---|---|---|
| Sustained (с подписками) | 200 TPS без деградации базовых SLO | Нагрузочный тест |
| **Синхронный пик биллинга** (массовое списание 1-го числа) | 500 TPS, burst 1000 TPS ≤ 1 мин — без потери операций | Нагрузочный тест по профилю «1-е число» |
| Изоляция по ТСП | всплеск одного ТСП не влияет на латентность остальных (rate limit по ТСП) | Chaos-тест «шумный сосед» |
| Отклонение сверхлимитных списаний | 100 % отказов ≤ 50 мс, без вызова ОПКЦ | Тест guard-проверок |

## 3. Корректность подписок (главные критерии)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Двойное списание за один (`mandateId`, `billingPeriod`) | **0** | Property-тест на фейке: повтор → один эффект |
| Списание после отзыва согласия | **0** | Тест «отзыв → ноль новых списаний» |
| Списание вне лимитов согласия | **0** | Тест guard-проверок (сумма, период) |
| Пропуск предуведомления | **0** (отказ при нарушении lead time) | Тест `PRE_NOTIFICATION_REQUIRED` |
| Потеря согласия при сбое (регистрация/статус) | **0** (RPO=0) | Тест отключения ноды, сверка |
| Зачисление по рекуррентному списанию не из `PAID` | **0** | Fitness-тест недостижимости (AD-005) |

## 4. Отзыв согласия (безопасность денег)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Задержка запрета новых списаний после события отзыва | ≤ 60 с от получения события | Тест, метрика |
| Обработка списания «в полёте» при отзыве | 100 % через дозапрос статуса, без слепого повтора | Тест сценария UNKNOWN |
| Отзывы в неизменяемом аудит-логе | 100 % | Аудит, SIEM |

## 5. Безопасность и соответствие (152-ФЗ / 161-ФЗ / КИИ)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Артефакт подтверждения согласия сохранён и неизменяем | 100 % активных согласий | Аудит, тест |
| ПДн плательщика в согласии | минимизированы, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Согласия и их переходы в аудит-логе | 100 %, лог неизменяем | Аудит, SIEM |
| Каналы к ОПКЦ (операции согласий) | 100 % на сертифицированных СКЗИ | ИБ-аудит |

## 6. Совместимость контрактов (машинная проверка)

| Метрика | Цель | Метод проверки |
|---|---|---|
| Ломающие изменения `openapi/tsp-api.yaml` v0.1→v0.2 | **0** (`CD-001..CD-010`) | `contract_diff` (old→new), `openapi_lint` PASS |
| Регресс разового приёма (без `mandateId`) | Базовая латентность/статусы без изменений | Регрессионный набор базовых сценариев |

## 7. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Метрики согласий (создано/активировано/отозвано/отклонено) | доступны, алерты на аномалии | Мониторинг |
| Алерт на «списание после отзыва» | 0 случаев, но алерт обязателен | Мониторинг |
| Отчёт незавершённых согласий/списаний | доступен всегда | Проверка |

## Зависимости (внешние входы)

- Lead time предуведомления, сроки подтверждения/истечения согласия, лимиты — по документации НСПК `[ТРЕБУЕТ ПРОВЕРКИ]`.
- Поддержка операций согласий вендорским адаптером ОПКЦ — обязательное требование RFP (constraint AD-008).
- Правовое основание и состав хранимых артефактов согласия — ИБ/юрист (152-ФЗ).
