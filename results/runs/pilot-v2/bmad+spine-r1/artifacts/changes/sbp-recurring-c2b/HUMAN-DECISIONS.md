# Что остаётся на решение человека-архитектора (A3)

Изменение — маршрут **Critical**, поэтому человеческое архитектурное решение обязательно (навык `significance-routing`: A3 — единственная обязательная человеческая точка). Ниже — развилки, которые агент сознательно **не** закрывает, и почему.

| # | Развилка | Варианты | Почему решает человек |
|---|---|---|---|
| H-1 | **Форма решения** (ADR-008) | A. Расширить ядро шлюза (рекомендация агента) · B. Отдельный сервис подписок · C. Вендорское решение · D. Прокси без хранения согласия | Управленческий выбор: стоимость владения, состав команд, vendor lock-in, аудируемость для ЦБ. Затрагивает несколько команд и бюджет |
| H-2 | **Политика при отзыве согласия** | (а) подтверждённые списания доводятся до конца; (б) откатываются/возвращаются; (в) гибрид по статусу | Правовое основание и отношения с плательщиком; цена ошибки — жалобы/регулятор. Не техническое решение |
| H-3 | **Форма и срок хранения доказательства согласия** | Что считается доказательством (квитанция НСПК `[ТРЕБУЕТ ПРОВЕРКИ]`), срок хранения, где хранится | Регуляторика (152-ФЗ/161-ФЗ) и правовая позиция; решает ИБ + юридическая служба, архитектор утверждает модель |
| H-4 | **Возвраты/диспуты по рекуррентным списаниям** | Остаться на базовых возвратах (диспуты — deferred) · развернуть диспуты сразу | Расширение scope; в исходном spine диспуты вынесены в Deferred — их возврат меняет объём и сроки |
| H-5 | **Допустимость функционала при отсутствии поддержки вендором** | Ждать вендора с поддержкой подписок · сменить вендора · собственная реализация транспорта подписок | Внешняя блокирующая зависимость; влияет на roadmap и контракт с вендором |
| H-6 | **Целевые числа NFR** | Утвердить/ужесточить цели (латентности, TPS дня биллинга, SLA блокировки при отзыве ≤ 5 с/60 с) | Баланс стоимости и SLA; часть значений диктуется регламентами НСПК `[ТРЕБУЕТ ПРОВЕРКИ]` |
| H-7 | **Политика отката для уже выданных согласий** | Stop-new с сохранением чтения/отзыва · миграция в другую модель · полный вывод функционала | Управленческое и правовое решение; воздействует на клиентов ТСП |
| H-8 | **Ратификация инвариантов AD-009/AD-010** | Принять как Proposed→Adopted · скорректировать формулировки | Инварианты обязательны для параллельных исполнителей; их формулировка — предмет архитектурного решения |
| H-9 | **Границы первой волны** | Только подписки для трёх сегментов (кино/ЖКХ/связь) · шире | Продуктовый scope; влияет на объём онбординга ТСП и лимиты |
