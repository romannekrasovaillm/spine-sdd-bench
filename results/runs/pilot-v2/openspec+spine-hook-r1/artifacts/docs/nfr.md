# NFR — Платёжный шлюз СБП (C2B-приём)

Целевые значения — **измеримые критерии приёмки** на гейтах A4/A5. Значения помечены как baseline; финальные согласуются с бизнесом и НСПК (регламенты оператора могут быть строже).

## 1. Доступность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Доступность шлюза (месяц) | ≥ 99,95 % (плановая); целевая 99,99 % в часы пик | Uptime-мониторинг, синтетика на критичный путь |
| Недоступность регистрации QR (месяц) | ≤ 22 мин суммарно (для 99,95 %) | SLO-отчёт |
| Плановая недоступность | 0 при деплоях (rolling, без downtime) | CI/CD pipeline |

## 2. Производительность

| Метрика | Цель | Метод проверки |
|---|---|---|
| Latency API ТСП «регистрация QR» | p95 < 500 мс, p99 < 1 с (без учёта времени НСПК) | Нагрузочный тест, APM |
| Latency «запрос статуса» | p95 < 300 мс | Нагрузочный тест |
| Доставка нотификации ТСП от события НСПК | p95 < 5 с | Метрика лага очереди |
| Зачисление в АБС от подтверждения НСПК | p95 < 60 с (SLA с АБС) | Метрика процесса |
| Throughput sustained | 200 TPS | Нагрузочный тест |
| Throughput пик (burst) | 500 TPS, допустимый burst 1000 TPS на 1 мин | Нагрузочный тест |
| Масштабируемость | ×2 без изменения архитектуры (горизонтальное масштабирование) | Load-test на 400 TPS |

## 3. Надёжность и восстановление

| Метрика | Цель | Метод проверки |
|---|---|---|
| RPO | 0 (нет потери зарегистрированных операций, статусов, событий outbox) | Тест отключения ноды, сверка |
| RTO (восстановление обработки) | ≤ 1 час | Chaos-тест, DR-учения |
| Потеря нотификации НСПК | 0 (компенсируется сверкой и опросом статусов) | Сверка с НСПК |
| Двойное зачисление при повторах | 0 (идемпотентность) | Тест на повторную доставку |

## 4. Сверка и расхождения

| Метрика | Цель | Метод проверки |
|---|---|---|
| Сверка с НСПК | ежечасная; расхождений по завершённым операциям — 0 | Reconciliation-отчёт |
| Сверка с АБС | суточная; расхождений — 0 | Reconciliation-отчёт |
| Отработка расхождений | 100 % по runbook за ≤ 4 часа | KPI дежурной смены |

## 5. Безопасность и соответствие

| Метрика | Цель | Метод проверки |
|---|---|---|
| Каналы к ОПКЦ | 100 % на сертифицированных СКЗИ (ГОСТ, mTLS) | ИБ-аудит, конфигурация |
| Финансовые переходы в аудит-логе | 100 %, лог неизменяем | Аудит, SIEM |
| ПДн | хранение минимизировано, шифрование в покое, маскирование в логах | ИБ-ревью, тесты |
| Доступ операторов к ручным операциям | 4-eyes (два согласования) | RBAC-проверка |
| Интеграция с AML/антифрод | передача операций по порогам — 100 % | Тест-кейсы |

## 6. Наблюдаемость

| Метрика | Цель | Метод проверки |
|---|---|---|
| Trace id на операцию | 100 % операций | APM |
| Алерт на DLQ | DLQ > 0 → алерт за ≤ 5 мин | Мониторинг |
| Лаг очереди нотификаций | ≤ 60 с в норме | Мониторинг |
| Отчёт незавершённых операций | доступен всегда, актуален | Проверка |

## 7. NFR — подписки СБП (рекуррентные C2B-списания)

Добавлено изменением `add-sbp-subscriptions` (ADR-008). Целевые значения — измеримые критерии приёмки на A4/A5; часть уточняется по регламентам НСПК и продуктовой политике.

### 7.1 Производительность и пропускная способность

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Latency создания мандата (`POST /v1/mandates`) | p95 < 500 мс (без учёта времени НСПК) | нагрузочный тест, APM | ТСП не проходит онбординг клиента в реальном времени |
| Latency инициации списания (`POST …/charges`) | p95 < 500 мс | нагрузочный тест, APM | биллинг-джоб ТСП растягивается, растут ретраи |
| Зачисление списания от подтверждения НСПК | p95 < 60 с (SLA АБС) | метрика процесса | задержка расчётов с ТСП, жалобы |
| Throughput окна биллинга | 100 TPS sustained, 300 TPS пик, burst 600 TPS на 1 мин (окно 00:00–02:00 МСК) | нагрузочный тест на окне биллинга | массовые отказы списаний в окне списаний |
| Масштабируемость | ×2 без изменения архитектуры | нагрузочный тест | перепроектирование в разгар подписочного сезона |

Допущение: числа окна биллинга выведены из предположения о числе ТСП и плательщиков первой волны — **подтвердить у бизнеса** (см. «Что остаётся на решение человека-архитектора», п. 8).

### 7.2 Надёжность, восстановление, идемпотентность

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Доступность реестра мандатов и списаний | как у шлюза: ≥ 99,95 % | SLO-отчёт | недоступность подписок у всех ТСП одновременно |
| RPO / RTO | RPO = 0; RTO ≤ 1 ч | chaos-тест, DR-учения | потеря оформленных согласий и списаний |
| Двойные списания за период подписки | **0** | property-тест на фейке ОПКЦ/АБС («две идентичные заявки → одно финансовое действие») | двойное списание со счёта плательщика — регуляторный инцидент |
| Распространение отзыва мандата | новые списания блокируются ≤ 60 с после подтверждения отзыва | тест + сверка | списание по отозванному согласию |
| Списание при неподтверждённом состоянии мандата | 0 (fail-closed) | негативный тест | списание без подтверждённого согласия |

### 7.3 Сверка и расхождения

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Сверка мандатов с ОПКЦ | ежечасная; расхождений по активным мандатам — 0 | reconciliation-отчёт | списания по мандатам с неизвестным состоянием |
| Сверка списаний с АБС | суточная; расхождений — 0 | reconciliation-отчёт | незачисленные списания |
| Отработка расхождения мандата | 100 % по runbook за ≤ 4 часа | KPI дежурной смены | накопление расхождений, эскалация |

### 7.4 Уведомления, безопасность, ПДн, наблюдаемость

| Метрика | Цель | Метод проверки | Следствие нарушения |
|---|---|---|---|
| Уведомление плательщика о списании | 100 % списаний `[ТРЕБУЕТ ПРОВЕРКИ — регламент НСПК]` | тест, отчёт покрытия | скрытые списания: регуляторный и репутационный риск |
| Контроль лимитов мандата при списании | 100 % списаний | тест на граничные значения | списание сверх согласия плательщика |
| Финансовые переходы мандата и списания в аудит-логе | 100 %, лог неизменяем | аудит, SIEM | неаудируемые финансовые переходы |
| ПДн согласия | минимизация, шифрование в покое, маскирование в логах; срок хранения `[ТРЕБУЕТ ПРОВЕРКИ]` | ИБ-ревью, тест на отсутствие ПДн в логах | нарушение 152-ФЗ |
| Наблюдаемость подписок | trace id 100 %; алерт на лаг активации/отзыва > 5 мин и DLQ > 0 за ≤ 5 мин | мониторинг | инциденты обнаруживает плательщик, а не банк |

### 7.5 Зависимости изменения

- Регламент сервиса подписок НСПК: тайминги активации/отзыва, обязательность и форма уведомления плательщика, лимиты, правило первого списания `[ТРЕБУЕТ ПРОВЕРКИ — документация НСПК]`.
- SLA АБС на списание по мандату (используется существующая операция; согласуется с владельцем АБС).
- Числа пиковой нагрузки окна биллинга — бизнес.

## Зависимости (внешние входы для NFR)

- Регламенты НСПК: таймауты, сроки уведомлений, требования к доступности [ТРЕБУЕТ ПРОВЕРКИ — из документации НСПК].
- SLA АБС на зачисление и списание (согласуется с владельцем АБС).
- Требования ЦБ к защите информации при переводах (номер Положения — уточнить у ИБ) [ТРЕБУЕТ ПРОВЕРКИ].
