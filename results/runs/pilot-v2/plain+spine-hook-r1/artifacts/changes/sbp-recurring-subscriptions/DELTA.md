## Проблема

ТСП (онлайн-кинотеатры, ЖКХ, связь) просят подписки СБП — повторяющиеся C2B-списания по согласию
плательщика без QR и без действия клиента на каждый период. Принятое решение спроектировано под
разовый платёж (клиент сканирует QR). Нужно добавить безакцептное рекуррентное списание, доказуемое
согласие и управляемый отзыв — не разорвав инварианты AD-001..AD-008 (зачисление только из `PAID`,
атомарные переходы, идемпотентность, изоляция протокола НСПК).

## ADDED

- **Требование SUB-1 (согласие как сущность).** When ТСП оформляет согласие, the сервис согласий
  shall создать согласие со статусной машиной `INITIATED→PENDING_PAYER→ACTIVE` и зафиксировать его
  параметры и аудит-запись (AD-002, AD-010).
- **Требование SUB-2 (списание только по активному согласию).** When ТСП инициирует списание,
  the шлюз shall выполнить его только при согласии в состоянии `ACTIVE` и в пределах параметров
  согласия (получатель, лимит на списание, суммарный лимит, период), иначе shall отклонить запрос
  без создания платежа (AD-009).
- **Требование SUB-3 (зачисление только из `PAID`).** While согласие в состоянии `ACTIVE`,
  the шлюз shall зачислять средства по списанию только из подтверждённого НСПК состояния `PAID`
  (AD-005, усиление).
- **Требование SUB-4 (отзыв блокирует новые списания).** When плательщик/банк отзывает согласие,
  the сервис согласий shall перевести согласие в `REVOKED` и заблокировать новые списания в пределах
  NFR §7 (`docs/nfr.md`).
- **Требование SUB-5 (идемпотентность).** When повторно приходит запрос или событие
  (`Idempotency-Key`/`eventId`), the шлюз shall не создавать второе списание и не изменять состояние
  (AD-003).
- **Требование SUB-6 (доказуемость и ПДн).** When изменяется состояние согласия, the сервис согласий
  shall записать неизменяемую аудит-запись; ПДн плательщика shall храниться минимизированно
  (референс согласия, не полные реквизиты) (AD-010, ADR-006).
- **Требование SUB-7 (аддитивный контракт).** Where контракт `openapi/tsp-api.yaml`, the изменение
  v0.1.0 → v0.2.0 shall не содержать ломающих изменений (проверка `contract_diff` = 0 breaking).
- Спайн: **AD-009**, **AD-010** (новые инварианты).
- Спека: `docs/spec/subscriptions.md` (статусная машина согласия).
- Контракт: пути `/v1/subscriptions*` в `openapi/tsp-api.yaml` и §6 `docs/contracts/tsp-api.md`.
- Внутренний контракт адаптера: `registerConsent`/`getConsentStatus`/`revokeConsent` и события
  `consent.activated`/`consent.rejected`/`consent.revoked` (`docs/contracts/opkc-adapter.md`).
- NFR: `docs/nfr.md` §7.

## MODIFIED

- **Spine `AD-002` (область применения)**: расширяется вторым агрегатом — согласием; его переходы
  также атомарны («статус + outbox + аудит»). Было: только платёж; стало: платёж + согласие.
- **Spine `AD-003` (ключи идемпотентности)**: добавляются `Idempotency-Key` создания согласия и
  списания, `eventId` consent-событий, `reference` отзыва.
- **Spine `AD-005` (усиление)**: явно зафиксировано, что `ACTIVE`-согласие не подменяет `PAID`;
  зачисление по списанию — только из `PAID`.
- **Spine `Deferred`**: «автоплатежи» переведены в scope (модель согласия); планировщик списаний на
  стороне шлюза и «списание по QR в рамках согласия» добавлены в Deferred с условием возврата.
- **`docs/solutioning.md` §1 (roadmap)**: «автоплатежи» исключены из вне-scope (реализуются этим
  изменением); прочие вне-scope пункты (C2C, выплаты, диспуты) без изменений.
- **`docs/contracts/tsp-api.md`**: v0.1 → v0.2 (аддитивно) — новые методы/события/коды ошибок.
- **`docs/spec/state-machine.md`**: добавлен §7 (связь со списанием по согласию) и обязательные
  секции сенсора (проблема/приёмка/риски) без изменения существующих переходов T1–T12.
- **`docs/nfr.md`**: добавлен §7 (бюджеты подписок); цели §1–§6 не изменены.

## REMOVED

- Нет удаляемых требований/методов. Контракт ТСП расширяется аддитивно; удалений и замен —
  нет, план миграции потребителей не требуется (доказательство: `contract_diff` = 0 breaking).

## План отката

- **До боевой эксплуатации:** откат = не включать. Фиче-флаг `subscriptions_enabled` по умолчанию
  **выключен**; изменения контракта аддитивны; миграций данных нет.
- **После включения:** `stop-new-charges` (флаг запрещает инициирование новых списаний, не трогая
  начатые операции и отзыв согласий) → откат релиза rolling → согласия остаются читаемыми и
  отзываемыми, шлюз — источник истины до сверки с НСПК.
- **Сигналы отката:** двойное списание; списание без действующего согласия; неблокировка отзыва;
  расхождение сверки по согласиям.
- **Владелец решения об откате:** solution-architect платёжного контура + дежурная смена.
  Критерий успешного отката: новые списания прекращены, разовые платежи и отзыв согласий работают,
  расхождений сверки — 0. Репетиция — гейт A4 (`arch-be control gate A4 --rehearse`).

## Критерии приёмки

- [ ] When ТСП инициирует списание по согласию не в `ACTIVE`, шлюз отклоняет запрос и не создаёт платёж.
- [ ] When сумма списания выходит за лимиты согласия, шлюз отклоняет с `SUBSCRIPTION_LIMIT_EXCEEDED`.
- [ ] When приходит повторное событие согласия с тем же `eventId`, состояние не меняется.
- [ ] When плательщик отзывает согласие, новые списания блокируются в пределах NFR §7.
- [ ] While согласие активно, зачисление по списанию возможно только из `PAID` (AD-005, тест).
- [ ] When изменяется состояние согласия, записана неизменяемая аудит-запись (AD-010, тест).
- [ ] Where `openapi/tsp-api.yaml` v0.1.0→v0.2.0, `contract_diff` = 0 breaking, `openapi_lint` PASS.
- [ ] Репетиция отката на A4 — PASS.
