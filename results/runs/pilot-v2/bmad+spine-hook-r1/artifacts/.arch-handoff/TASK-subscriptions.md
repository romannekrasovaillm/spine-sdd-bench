# Задача для кодового харнесса — Рекуррентные C2B-списания (подписки СБП)

Дополнение к базовому handoff-пакету (`.arch-handoff/TASK.md`, walking skeleton C2B). Эпик: реализовать рекуррентные списания по согласию плательщика поверх принятого решения. Код — после ратификации A3 (`docs/DECISION.md`).

## Цель эпика (epic-context, дистиллят)

Дать ТСП (кинотеатры, ЖКХ, связь) рекуррентные C2B-списания: плательщик один раз даёт согласие, далее ТСП списывает по расписанию. Согласие — отдельный ресурс; истина о его статусе — у ОПКЦ; каждое списание — **обычный платёж** существующей статусной машины; зачисление — **только из `PAID`**.

Стыки: ТСП → API v0.2 (consent/subscription/charge); шлюз → ОПКЦ через вендорский адаптер (методы согласий, предуведомление) — протокол `[ТРЕБУЕТ ПРОВЕРКИ]`, мок; шлюз → АБС (идемпотентное зачисление по `paymentId`); планировщик → модуль согласий; сверка согласий с ОПКЦ.

## Инварианты (дословно, обязательны)

- **AD-009:** «Материализация рекуррентного списания (`Charge` → `Payment`) возможна только при `Consent.status = ACTIVE`, сумме и периодичности в пределах согласия и выдержанном окне предуведомления (немедленное списание запрещено); зачисление — только из `PAID` (AD-005); уникальность списания в слоте расписания — по `(subscriptionId, scheduledAt)`, идемпотентность — по `chargeId` (расширяет область AD-003, не переписывая блок); протокольная часть согласий — в контракте адаптера ОПКЦ (AD-004).»
- **AD-010:** «Статус согласия принимается из событий/ответов ОПКЦ; при расхождении истиной считается ОПКЦ, локальная копия приводится к ней; сверка согласий — ежечасная, расхождений — 0.»
- **AD-005 (сохраняется):** зачисление в АБС — только из `PAID`.
- **AD-002/AD-003:** атомарные переходы «статус + outbox + аудит»; идемпотентность повторных доставок (расширена ключом `chargeId`).
- **AD-004:** протокол НСПК знает только адаптер ОПКЦ.
- **AD-006/AD-007:** trust-зоны не меняются; ПДн плательщика минимизируются; все переходы согласия — в неизменяемом аудите.

**Запрещено менять:** AD-001, AD-005, AD-006, AD-008; существующий путь `/v1/payments*` и `Payment.status`; trust-зоны. Конфликт с spine обязан **остановить** работу и вернуть `blocked`/`conflicts_with_prior_decisions`.

## Критерии приёмки

Полный список — `docs/ACCEPTANCE.md` (AC1–AC16, включая AC8b — дедупликацию слота, и AC16 — ownership/403), включая негативные: списание без `ACTIVE`-согласия невозможно; превышение лимита → `charge.skipped` без проводки; повтор планировщика/повтор в том же слоте не создаёт дубль; отзыв согласия останавливает ожидающие списания; расхождение копии с ОПКЦ останавливает списание; чужой ресурс → `403`. NFR — `docs/nfr.md` §7 (пик 2000 списаний/мин без потерь и дублей).

Walking skeleton — `docs/WALKING-SKELETON.md` (сначала доказать сквозной путь + негативы, потом массовая генерация). План отката — `docs/ROLLBACK.md` / `.arch-handoff/ROLLBACK.yaml` (фиче-флаг `recurrence.enabled`, заморозка новых согласий, летящие платежи не отменяются).

## Контракт результата

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа):

```json
{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}
```

- `status`: `complete` — выполнено полностью; `partial` — частично; `blocked` — заблокировано.
- `assumptions`: допущения при реализации.
- `open_questions`: вопросы к архитектору.
- `conflicts_with_prior_decisions`: расхождения с ADR/spine (в т.ч. с AD-009/AD-010) — обязаны остановить и эскалировать.

Источники: `docs/solutioning-subscriptions.md`, `docs/adr/ADR-008-...md`, `changes/sbp-recurrent-c2b/DELTA.md`, `ARCHITECTURE-SPINE.md` (AD-001..AD-010), `.arch-handoff/CONSTRAINTS.yaml`, `openapi/tsp-api.yaml`.
