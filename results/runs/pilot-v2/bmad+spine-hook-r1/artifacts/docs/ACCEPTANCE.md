# Критерии приёмки — Рекуррентные C2B-списания (подписки СБП)

- Дата: 2026-09-28 · Гейты: A4 (conformance), A5 (drift)
- Формат: EARS + проверяемое действие. Источник: `changes/sbp-recurrent-c2b/DELTA.md` R1–R9.

## Позитивные критерии

- [ ] **AC1.** When ТСП вызывает `POST /v1/consents` с `Idempotency-Key`, the шлюз shall вернуть `201` с `consentId` и `status=PENDING_PAYER`; повтор с тем же ключом и телом возвращает тот же `consentId` без нового ресурса (тест идемпотентности).
- [ ] **AC2.** When приходит событие `consent.activated`, the шлюз shall перевести согласие в `ACTIVE` ≤ 30 с (p95) и отправить вебхук `consent.activated` (тест задержки).
- [ ] **AC3.** When наступает `scheduledAt` и согласие `ACTIVE` и сумма в пределах, the шлюз shall инициировать списание; платёж проходит `CREATED→…→PAID→CREDITED→COMPLETED`, вебхук `charge.completed` (сквозной тест).
- [ ] **AC4.** When платёж доходит до `PAID`, the шлюз shall зачислить в АБС только из `PAID` (AD-005) — порядок переходов проверяется по аудит-логу (тест переходов).
- [ ] **AC5.** When согласие `REVOKED`/`EXPIRED`, the шлюз shall остановить ожидающие списания ≤ 60 с (p95) и не отменять проведённые (негативный тест + тест гонки).

## Негативные критерии (обязательны)

- [ ] **AC6.** When согласия нет / оно `PENDING_PAYER`/`REVOKED`/`EXPIRED`, the шлюз shall НЕ создавать `Payment` (fitness-тест AD-009; ожидается `charge.skipped` или `422 CONSENT_NOT_ACTIVE`).
- [ ] **AC7.** When сумма превышает `maxAmountPerCharge`/`maxAmountPerPeriod`, the шлюз shall не выполнять списание, зафиксировать `charge.skipped`, поднять алерт; движения денег нет (`422 CONSENT_LIMIT_EXCEEDED` при явном запросе).
- [ ] **AC8.** When планировщик запускается повторно по тому же `chargeId`, the шлюз shall не создавать второе списание и вторую проводку (тест идемпотентности).
- [ ] **AC8b.** When приходит повторная инициация в тот же слот `(subscriptionId, scheduledAt)` с новым `Idempotency-Key`, the шлюз shall вернуть существующий `Charge` и не создать второго `Payment` (тест дедупликации слота).
- [ ] **AC9.** When окно предуведомления не выдержано, the шлюз shall не выполнять списание (тест окна; немедленное списание запрещено).
- [ ] **AC10.** When локально `ACTIVE`, а в ОПКЦ `REVOKED`, the шлюз shall привести копию к `REVOKED` и не инициировать списание (тест сверки, AD-010).
- [ ] **AC11.** When ОПКЦ недоступен, the шлюз shall не инициировать новые списания, не теряя открытые платежи; при пропущенном плановом окне — catch-up по резервной политике (§4.5) либо `charge.skipped` за grace-окном; после восстановления сверка добирает состояние (chaos-тест).
- [ ] **AC16.** When ТСП обращается к чужому `consent`/`subscription`/`charge`, the шлюз shall ответить `403 FORBIDDEN` и не раскрыть данные (тест авторизации/ownership).

## Нефункциональные критерии

- [ ] **AC12.** Нагрузочный тест: sustained 500 списаний/мин, пик 2000/мин в плановое окно — без потери заявок и без дублей; метрики из `docs/nfr.md` §7 в целях.
- [ ] **AC13.** Доступность контура согласий ≥ 99,95 %; RPO=0 для согласий/расписаний (тест отключения ноды).
- [ ] **AC14.** Сверка согласий с ОПКЦ ежечасная, расхождений 0; аудит 100 % переходов согласия.

## Критерий отката

- [ ] **AC15.** When включён `recurrence.enabled=false`, the шлюз shall не инициировать новые списания и не принимать новые согласия (`503 FEATURE_DISABLED`), при этом существующие платежи завершаются штатно; после отката сверка показывает 0 расхождений. Репетиция отката на гейте A4 — PASS **на уровне целостности артефактов отката** (в архитектурной фазе кода нет); рантайм-репетиция фиче-флага — критерий эпика реализации.
