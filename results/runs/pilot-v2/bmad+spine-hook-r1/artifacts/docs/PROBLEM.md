# Проблема и значимость — Рекуррентные C2B-списания (подписки СБП)

- Маршрут: **Critical** (Architecture Significance Score 11/15, forcing-триггер `security_boundary_change`)
- Дата: 2026-09-28 · Owner: solution-architect (платёжный контур)
- Дельта: `changes/sbp-recurrent-c2b/DELTA.md` · Решение: `docs/adr/ADR-008-...md`

## Проблема

ТСП (онлайн-кинотеатры, ЖКХ, связь) не могут обслуживаться в СБП-приёме банка по подписочной модели: каждый C2B-платёж сегодня требует QR и активного действия клиента, поэтому регулярные списания (ежемесячная подписка, оплата ЖКХ, связь) невозможны. Бизнес просит рекуррентные списания по согласию плательщика — «подписки СБП».

Изменение принципиально меняет **модель авторизации**: инициатором списания становится ТСП по хранимому мандату, а не плательщик в момент операции. Это не «ещё один метод API», а новая граница полномочий на движение денег плательщика — отсюда высокий маршрут.

## Оценка значимости (11/15)

Сработавшие триггеры: `security_boundary_change` (forcing), `criticality_or_exception` (forcing), `api_contract_change`, `data_contract_change`, `consistency_model_change`, `cross_domain_integration`, `domain_ownership_change`, `new_component`, `significant_nfr`, `rto_rpo_targets`, `financial_impact`.

Не сработали: `new_vendor` (тот же вендор транспорта), `new_datastore` (согласия/расписания — таблицы в существующей БД шлюза, RPO=0 наследуется), `trust_zone_change` (новую зону сознательно не вводим), `irreversible_migration` (изменение additive, без миграции данных).

Маршрут остаётся Critical: сработал forcing-триггер `security_boundary_change` (порог ≥5 триггеров также пройден).

Полное обоснование — `docs/solutioning-subscriptions.md` §2.

## Почему нужен полный Solutioning, а не дельта

Маршрут Critical по политике репозитория (`significance-routing`) требует: spine (новые инварианты), ADR с альтернативами и обратимостью, измеримые NFR, обязательную человеческую точку A3, walking skeleton до массовой генерации и evidence-гейты. Дельта (`changes/sbp-recurrent-c2b/DELTA.md`) используется как носитель изменения истины, но её одной недостаточно.

## Затронутые инварианты (кратко)

- **Сохраняются без изменений:** AD-001 (изоляция), AD-005 (зачисление только из `PAID`), AD-006 (trust-зоны), AD-008 (гибрид).
- **Расширяются:** AD-003 (идемпотентность — ключ `chargeId`), AD-004 (адаптер ОПКЦ — методы согласий), AD-002 (вторая, нефинансовая машина состояний согласия), AD-007 (новый объект ПДн/аудита).
- **Добавляются:** AD-009 (списание только по действующему согласию в пределах), AD-010 (истина о согласии — у ОПКЦ).

## Критерий успеха

Рекуррентные списания обслуживаются без обхода AD-005: каждое списание — обычный аудируемый платёж, зачисляемый только из `PAID`; списание без действующего согласия невозможно; отзыв согласия останавливает будущее и не переписывает прошлое.
