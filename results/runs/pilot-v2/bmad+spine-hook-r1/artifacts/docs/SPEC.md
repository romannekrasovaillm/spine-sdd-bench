# Спецификация изменения — Рекуррентные C2B-списания (подписки СБП)

- Status: Предложение (на A3) · Маршрут: Critical · Дата: 2026-09-28
- Дельта: `changes/sbp-recurrent-c2b/DELTA.md` · Дизайн: `docs/solutioning-subscriptions.md` · ADR: `docs/adr/ADR-008-...md`

## 1. Цель и границы

Дать ТСП возможность рекуррентных C2B-списаний по согласию плательщика. **В scope:** согласие (мандат), подписка, расписание, рекуррентное списание, предуведомление, отзыв согласия, сверка согласий, контракт ТСП v0.2, NFR, fitness-правила. **Вне scope:** изменение одноразового пути QR/ссылки, возвратов-саги, trust-зон, АБС-интеграции, родительского spine.

## 2. Изменение истины (спека-дельта)

Дельта `changes/sbp-recurrent-c2b/DELTA.md` фиксирует ADDED R1–R9, MODIFIED (AD-003/AD-004 — область расширяется через AD-009/AD-010, сами блоки не переписываются; контракт v0.2; NFR §7) и REMOVED (нет). Живая истина обновляется вливанием дельты (`arch-be delta archive`) после ратификации A3 и реализации.

## 3. Модель (что добавляется)

`Consent` (согласие, истина у ОПКЦ) → `Subscription` (тариф/расписание ТСП) → `Charge` (списание) → `Payment` (существующая статусная машина). Ключевой принцип: `Charge` — обёртка авторизации, `Payment` — движение денег; материализация `Charge→Payment` только по AD-009, зачисление только из `PAID` (AD-005).

## 4. Инварианты (связывающие, для исполнителей)

- **AD-009 (Proposed):** «Материализация рекуррентного списания (`Charge` → `Payment`) возможна только при `Consent.status = ACTIVE`, сумме и периодичности в пределах согласия и выдержанном окне предуведомления (немедленное списание запрещено); зачисление — только из `PAID` (AD-005); уникальность списания в слоте расписания — по `(subscriptionId, scheduledAt)`, идемпотентность — по `chargeId` (расширяет область AD-003, не переписывая блок); протокольная часть согласий — в контракте адаптера ОПКЦ (AD-004).»
- **AD-010 (Proposed):** «Статус согласия принимается из событий/ответов ОПКЦ; при расхождении истиной считается ОПКЦ, локальная копия приводится к ней; сверка согласий — ежечасная, расхождений — 0.»
- Сохраняются: AD-001, AD-002, AD-003 (расширенный), AD-004 (расширенный), AD-005, AD-006, AD-007, AD-008.

## 5. Контракт

API ТСП v0.1 → **v0.2 только добавлением**: `POST/GET /v1/consents`, `POST /v1/consents/{id}/revoke`, `POST/GET/PATCH/DELETE /v1/subscriptions`, `POST/GET /v1/subscriptions/{id}/charges`; новые схемы `Consent`/`Subscription`/`Charge`/`Problem`; новые вебхуки `consent.*`, `charge.*`. Файлы: `openapi/tsp-api.yaml`, `docs/contracts/tsp-api.md`. Проверено: `openapi_lint` PASS, `contract_diff v0.1→v0.2` breaking = 0.

## 6. NFR

Раздел 7 `docs/nfr.md`: регистрация согласия p95 < 500 мс; `ACTIVE` p95 ≤ 30 с; точность запуска ±60 с (p99); предуведомление 100 %; массовое окно 2000 списаний/мин; остановка при отзыве p95 ≤ 60 с; двойное списание 0; списание без согласия 0; сверка согласий ежечасная, расхождений 0.
