# План отката — Рекуррентные C2B-списания (подписки СБП)

- Дата: 2026-09-28 · Owner решения об откате: дежурный архитектор платёжного контура + продукт
- Связано: `docs/adr/ADR-008-...md` (Reversibility: costly), `changes/sbp-recurrent-c2b/DELTA.md`

## Принцип

Рекуррентный контур **изолирован фиче-флагом** `recurrence.enabled` и надстроен над неизменённым одноразовым путём платежа. Откат выключает **инициацию** новых списаний и приём согласий, но **не отменяет** уже запущенные платежи: они завершаются существующим путём. Данные согласий не мигрируются обратно (они новые).

## Сигналы отката (триггеры)

1. Рост `charge.failed`/`charge.skipped` аномально против baseline (ложные отказы по согласию).
2. Лаг очереди списаний/планировщика выше SLO; потеря заявок в плановом окне.
3. **Расхождение сверки согласий** с ОПКЦ (AD-010), **не отработанное по runbook за ≤ 4 часа**, либо всплеск жалоб плательщиков на несогласованные списания.
4. Регуляторное предписание/замечание по модели авторизации.

## Шаги отката

1. **Stop-new** — `recurrence.enabled=false`: планировщик не инициирует новые `Charge`; уже материализованные `Payment` не трогаются.
2. **Freeze** — `POST /v1/consents` и `POST /v1/subscriptions` → `503 FEATURE_DISABLED`; существующие подписки помечаются `PAUSED`.
3. **Drain** — дождаться завершения летящих платежей (обычный путь `PAID→CREDITED→COMPLETED`); не отменять их.
4. **Reconcile** — сверка согласий и списаний с ОПКЦ; отчёт незавершённых операций; подтверждение 0 расхождений.
5. **Rollback релиза** — откат кода/конфигурации (rolling, без downtime), флаг остаётся off.
6. **Verify** — 0 новых списаний, 0 дублей, существующий одноразовый путь не затронут.

## Что НЕ откатывается и почему

- Уже проведённые рекуррентные платежи (деньги в контуре) — корректируются только возвратом-сагой (ADR-005), не откатом релиза.
- Ратифицированные инварианты AD-009/AD-010 — отменяются через `Superseded`/статус, а не удалением (дисциплина ADR/spine).

## Обратимость и репетиция

- Оценка ADR-008: **costly** (функционально откат дешёвый и без миграции; пересмотр модели авторизации после боевой эксплуатации дорог).
- В **архитектурной фазе** (кода нет) `arch-be control gate A4 . --rehearse` проверяет **целостность артефактов отката** на baseline (`.arch-handoff/ROLLBACK.yaml` → `REHEARSAL.json`): репетируется возврат к baseline, а не рантайм-переключение флага. Это осознанный срез, а не подмена: рантайм-репетиция шагов 1–6 (флаг `recurrence.enabled`, `503`, drain, reconcile) — **критерий эпика реализации** (A4 после walking skeleton), и ROLLBACK.yaml эпика обязан включать эти шаги как исполняемые.
- Плановая ревизия модели — через 12 месяцев боевой эксплуатации (срок пересмотра в ADR-008).
