# Оценка значимости и маршрута — «СБП-подписки» (рекуррентные C2B-списания)

- Дата: 2026-09-28
- Метод: significance-routing (15 триггеров риска → маршруты Fast/Standard/Critical, контрольные точки A0–A5).
- Базовое решение: маршрут **Critical** (11/15) — `README.md`, `docs/solutioning.md`.
- Итог по изменению: маршрут **Critical**, полное Solutioning обязательно.

## 1. Карта триггеров (что вносит именно это изменение)

| # | Триггер | Сработал | Обоснование |
|---|---|---|---|
| 1 | new_component | **ДА** | Рекуррентный оркестратор/планировщик и реестр мандатов — новый логический компонент в платёжном контуре (не новый deployable-контур). |
| 2 | new_datastore | НЕТ | Новые сущности (мандат, подписка, списание) — в существующей БД шлюза (единый источник истины). |
| 3 | new_vendor | НЕТ | Тот же вендор транспорта ОПКЦ; контракт `opkc-adapter.md` расширяется, POC/RFP дополняются. |
| 4 | domain_ownership_change | НЕТ | Владелец прежний — solution-архитектор платёжного контура. |
| 5 | cross_domain_integration | **ДА** | Новый паттерн интеграции: инициируемое эквайером списание и синхронизация мандата с банком плательщика через НСПК; вовлекается АБС (списание по подписке). |
| 6 | api_contract_change | **ДА** | Новые пути/схемы мерчант-API (`/v1/mandates`, `/v1/subscriptions`) и контракта адаптера ОПКЦ. |
| 7 | data_contract_change | **ДА** | Новые сущности и данные: согласие плательщика, идентификаторы, лимиты, история списаний. |
| 8 | security_boundary_change | **ДА** | Новый класс чувствительных данных (согласие + ПДн плательщика) и новая семантика авторизации финансового действия без участия плательщика. |
| 9 | trust_zone_change | НЕТ | Trust-зоны (AD-006) те же; расширяются классы данных и объекты аудита. |
| 10 | consistency_model_change | **ДА** | Мандатная модель + идемпотентность «ровно одно списание за период» — расширение модели консистентности. |
| 11 | significant_nfr | **ДА** | Новые измеримые NFR (латентность оформления/инициации, лаг отзыва, ноль двойных списаний). |
| 12 | rto_rpo_targets | **ДА** | RPO=0/RTO≤1 ч расширяются на мандаты и периодические списания (финансово значимые). |
| 13 | irreversible_migration | НЕТ | Изменения аддитивны; откат — фиче-флаг без миграции данных назад. |
| 14 | financial_impact | **ДА** | Прямое финансовое действие по согласию плательщика; ошибка = двойное списание/незаконное списание. |
| 15 | criticality_or_exception | **ДА** | Платёжный контур / КИИ / НПС. |

**Сработало 10 из 15**, включая `security_boundary_change`, `financial_impact`, `criticality_or_exception`. По правилу маршрутизации любой из этих трёх (и порог ≥5) даёт **Critical**.

## 2. Почему нужен полный Solutioning, а не дельта

- `delta-spec` прямо исключает Critical Path (платежи, КИИ, смена security boundary): дельты недостаточно.
- Дороже всего ошибка **модели согласия и идемпотентности списания**: неверная модель = незаконные/двойные списания, регуляторный и репутационный ущерб; откат после боевого запуска — `costly`.
- Новый внешний вход: точный протокол мандатов/списаний СБП получается от НСПК по договору; до этого все протокольные детали — `[ТРЕБУЕТ ПРОВЕРКИ]`. Это проектный риск, который нельзя закрыть «на ходу».
- Затрагиваются инварианты AD-002/AD-003/AD-005 и стратегия AD-008 [ADOPTED] — решения должны быть зафиксированы ADR до реализации (adr-authoring).

## 3. Обязательные контрольные точки

| Гейт | Что требуется по этому изменению |
|---|---|
| A0 (architecture fit) | Укладывается ли мандат в существующий паттерн «ядро + адаптеры»? Да — расширение, не новый контур (ADR-001 сохраняется). |
| A1 (impact) | Blast radius: ядро шлюза (статусная машина), контракт ТСП, контракт ОПКЦ, АБС (списание), сверка, отчётность, ИБ/ПДн. Затронутые владельцы — в `IMPACT.md`. |
| A2 (solutioning trigger) | Порог задан заранее: «финансовое действие без участия плательщика» — триггер Critical по умолчанию. |
| A3 (human decision) | **Обязательна**: ратификация ADR-008 и Proposed-блоков AD-009…AD-011; развилки бизнеса/юристов/ИБ — `HUMAN-DECISIONS.md`. |
| A4 (conformance) | Fitness-инварианты (мандат только `ACTIVE`, списание только из подтверждённого статуса), нагрузочные NFR, тесты идемпотентности и отзыва, ИБ-аудит ПДн. |
| A5 (drift) | Сверка мандатов/списаний с НСПК и АБС в проде; SLO-отчёт; проверка дрейфа модели согласия. |

## 4. Approval theater (детектор)

Решение выносится на человека один раз и предметно (A3): документ содержит ≥2 альтернативы, отрицательные последствия и обратимость. Повторные «согласования» по факту являются консультациями владельцев (ИБ, юристы, АБС), а не архитектурным решением, — их результаты включены в `HUMAN-DECISIONS.md`.
