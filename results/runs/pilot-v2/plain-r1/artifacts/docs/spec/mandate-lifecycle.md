# Жизненный цикл мандата и подписки — спецификация

- Status: Draft (для ревью на гейте A1/A3; ADR-008 Proposed)
- Owner: solution-architect (платёжный контур)
- Связано: ADR-008, ADR-002, ADR-005, AD-002, AD-003, AD-005, AD-009…AD-011

Мандат (согласие плательщика на периодические списания) — объект **ядра шлюза**, единый источник истины (AD-002). Каждый переход — атомарная транзакция «смена статуса + outbox + аудит». Повторные триггеры идемпотентны (AD-003).

## 1. Состояния мандата

| Состояние | Смысл | Виден ТСП |
|---|---|---|
| `DRAFT` | Мандат создан в шлюзе, регистрация в ОПКЦ в процессе | да |
| `PENDING_PAYER` | Ссылка/QR на подписание выдана, плательщик ещё не подтвердил | да |
| `ACTIVE` | Согласие подтверждено НСПК, списания разрешены | да |
| `SUSPENDED` | Приостановлен ТСП/ядром (без отзыва), списания запрещены | да |
| `REVOKED` | Отозван плательщиком или ТСП; списания запрещены необратимо | да |
| `EXPIRED` | Истёк срок действия мандата | да |

Дополнительно подписка имеет состояния `PENDING_ACTIVATION → ACTIVE → PAUSED → CANCELLED`; списание (charge) переиспользует состояния платежа (`CREATED … COMPLETED`, терминальные).

## 2. Таблица переходов мандата

| № | From | To | Триггер | Guard | Действие |
|---|---|---|---|---|---|
| M1 | — | `DRAFT` | `POST /v1/mandates` (Idempotency-Key) | ТСП активен, реквизиты полны | запись мандата + outbox «регистрация в ОПКЦ» |
| M2 | `DRAFT` | `PENDING_PAYER` | ответ адаптера: получена ссылка/QR | ссылка непуста | сохранить ссылку, outbox-нотификация ТСП |
| M3 | `DRAFT` | `REVOKED` | ошибка регистрации (не транзиентная) | — | `errorCode`, вебхук `mandate.failed` |
| M4 | `PENDING_PAYER` | `ACTIVE` | подтверждение подписания НСПК (`mandate.activated`) | **scope согласия совпадает** с заявленным | outbox, вебхук `mandate.activated` |
| M5 | `PENDING_PAYER` | `EXPIRED` | истёк срок подписания | подпись не получена | вебхук `mandate.expired` |
| M6 | `ACTIVE` | `SUSPENDED` | запрос ТСП `POST /v1/mandates/{id}/suspend` | плательщик не отзывал | outbox |
| M7 | `SUSPENDED` | `ACTIVE` | запрос ТСП `POST /v1/mandates/{id}/resume` | мандат не отозван/не истёк | outbox |
| M8 | `ACTIVE`/`SUSPENDED` | `REVOKED` | отзыв плательщика (`mandate.revoked`) или ТСП `POST /v1/mandates/{id}/revoke` | — | **немедленный запрет новых списаний**, outbox, вебхук `mandate.revoked`; открытые списания — по саге |
| M9 | `ACTIVE` | `EXPIRED` | наступил срок действия мандата | — | запрет новых списаний, outbox |

## 3. Переходы подписки

| From | To | Триггер | Guard |
|---|---|---|---|
| — | `PENDING_ACTIVATION` | `POST /v1/subscriptions` | мандат существует |
| `PENDING_ACTIVATION` | `ACTIVE` | мандат стал `ACTIVE` | лимиты/период валидны |
| `ACTIVE` | `PAUSED` | `PATCH` (pause) | — |
| `PAUSED` | `ACTIVE` | `PATCH` (resume) | мандат `ACTIVE` |
| `ACTIVE`/`PAUSED` | `CANCELLED` | `DELETE`/`,revoke` | — |

Подписка не может быть `ACTIVE`, если мандат не `ACTIVE`. Отзыв мандата автоматически переводит связанные подписки в `PAUSED` (без новых списаний) с последующей отменой ТСП.

## 4. Периодическое списание (charge)

| № | From | To | Триггер | Guard | Действие |
|---|---|---|---|---|---|
| C1 | — | `CREATED` | наступил период / ручной вызов `POST /v1/subscriptions/{id}/charges` | мандат `ACTIVE`, подписка `ACTIVE` | платёж + outbox «списание в ОПКЦ», ключ `(mandateId, subscriptionId, billingPeriod)` |
| C2 | `CREATED` | `PAID` | подтверждение списания НСПК | сумма и получатель совпадают с мандатом | outbox «зачисление в АБС» |
| C3 | `CREATED` | `FAILED` | отказ НСПК / превышен лимит мандата | — | `errorCode` (`MANDATE_LIMIT_EXCEEDED`, …), вебхук `charge.failed` |
| C4 | `PAID` | `CREDITED` | подтверждение АБС (`absDocId`) | вызов идемпотентен по `chargeId` | outbox |
| C5 | `CREDITED` | `COMPLETED` | доставка/постановка вебхука ТСП | — | outbox, вебхук `payment.completed` |

Далее платёж подчиняется обычной статусной машине (`docs/spec/state-machine.md`), включая возвраты (сага, ADR-005).

## 5. Запрещённые переходы (инварианты)

- **Списание невозможно, если мандат не `ACTIVE`** (AD-009). Проверяется fitness-тестом.
- **Зачисление в АБС по списанию невозможно из состояния, кроме `PAID`** (AD-005 не ослабляется на рекуррентном пути).
- **Не более одного успешного списания на `(mandateId, subscriptionId, billingPeriod)`** (AD-010); повтор не создаёт второй платёж/проводку.
- **После `REVOKED`/`EXPIRED` мандата новые списания недостижимы** (AD-011).
- Сумма списания не превышает лимит мандата и согласованный scope; расхождение — отказ + алерт (не зачисление).
- `PAID` не откатывается; корректировки — только возвратом (сага).

## 6. Идемпотентность

| Триггер | Ключ | Поведение при повторе |
|---|---|---|
| `POST /v1/mandates` | `Idempotency-Key` | тот же `mandateId`, состояние не меняется |
| `POST /v1/subscriptions` | `Idempotency-Key` | та же `subscriptionId` |
| Событие НСПК `mandate.activated`/`mandate.revoked` | `eventId` | обработанный `eventId` игнорируется; новый `eventId` по завершённому переходу — алерт, состояние не меняется |
| Периодическое списание | `(mandateId, subscriptionId, billingPeriod)` | повтор не создаёт второе списание |
| Подтверждение АБС | `chargeId` | повтор не создаёт вторую проводку |

## 7. Сверка и восстановление

- Открытые мандаты (`PENDING_PAYER`, `ACTIVE`, `SUSPENDED`) и открытые списания (`CREATED`, `PAID`) — кандидаты сверки с НСПК; списания — также с АБС (суточная сверка).
- «У НСПК мандат отозван, у нас `ACTIVE`» → срочный стоп списаний → M8.
- «У НСПК списание `PAID`, у нас нет» → дозапрос статуса → C2.
- Платёж по подписке в `PAID` при недоступной АБС — остаётся `PAID`, виден в отчёте незавершённых операций, зачисляется ровно один раз после восстановления.

## 8. Согласованность с API ТСП

Наружу выставляются состояния мандата/подписки/списания из `openapi/tsp-api.yaml`; технические подсостояния не выставляются. Расширение аддитивно: значения `Payment.status` не меняются.

## Проблема

Рекуррентное списание выполняется без участия плательщика в каждом периоде. Без формального жизненного цикла мандата и строгой идемпотентности возможны незаконные списания (по неактивному/отозванному согласию) и двойные списания за один период.

## Критерии приёмки

- [ ] Списание при мандате не `ACTIVE` отклоняется (`MANDATE_NOT_ACTIVE`), финансового следа нет (AD-009).
- [ ] Отзыв мандата запрещает новые списания ≤ 60 с (p99); отзыв — в неизменяемом аудит-логе (AD-011).
- [ ] Повторная инициатива за тот же период не создаёт второе списание (AD-010).
- [ ] Переходы мандата атомарны — «статус + outbox + аудит» в одной транзакции (AD-002).

## Риски

- Рассинхрон состояния мандата с НСПК → сверка (§7), срочный стоп списаний.
- Поздняя/повторная нотификация → дедуп по `eventId` (AD-003).
- Расширение ПДн в контуре (согласие плательщика) → минимизация и шифрование (AD-006/AD-007).
